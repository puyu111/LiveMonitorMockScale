# mock_scale · 本地确定性 inpainting 能否替代擦除接口？

> 本工程是 **LiveMonitorMockScale** 的出片子工程：两条换名出片线（`mock/` `expand/`）
> 与 2026-10-28 起的**正文替换线**（同样住在 `mock/`）共用 `core/` 里**唯一一份**管线与运行配置。
> 2026-10-27 由原 `test2` 项目合并而来，旧路径对照见
> [`docs/工程结构.md`](docs/工程结构.md#迁移对照2026-10-27-从-test2-并进来)。

## 一句话结论

**能：擦除与排版这两步是干净的，8 张零瑕疵、650 张批量里 1488 次零违规。** 但**定位**那一步
才是真正的瓶颈（批量实测 12.9% 失败），而且失败集中在两类版式上 —— 见「边界」与
[`docs/技术说明.md`](docs/技术说明.md) §6。

**分阶段说清楚**（650 张批量实测；按 2026-09-30 的规格，**88 张先跳过** —— 60 张昵称是
纯 ASCII、28 张原图含表情，跳过不是失败，**也不计入任何数量**，见「跳过」）：

| 阶段 | 结果 |
|---|---|
| 跳过 | **88 / 650**（`SKIP_PURE_EN` 60 + `SKIP_EMOJI` 28）—— 不出片、不计入任何数量 |
| 处理 | **562 张**（= 扫到的 650 − 跳过 88）；其中 11 张检测不到框 ⇒ **可定位分母 551** |
| 擦除 + 排版 | **496/496 张、×3 探针 = 1488/1488 次全部合规**；`擦不干净` 与 `蒙版外被改动` 一次都没出现 |
| 定位 | **496/551 = 90.0%** —— 失败 10.0%，三个家族（框内没有高饱和段 49.1% / 有饱和段但凑不成名字+冒号 40.0% / 没有冒号段 10.9%） |
| 检测 | 找不到框 11/562 = 2.0%；找到多框 50/551 = 9.1%（其中 34 张仍定位成功） |

⚠️ **「不越框 ✓ 1488/1488」量的是框右界，不是四条边。** 内建判据 `Outcome.box_ok` 只比
`result[:, box_right:]` 与原图（即**右界之外**零改动）。**上下**由另一条机制守：定位按
「行带」把改动夹在名字那一行的上下界内（见下），第二行一个字都不碰。

✅ **2026-09-30 修掉的三条**（前两条曾让上面的数字比读起来窄）：

1. **上下越框（bug-166）**：字高过去取墨迹蒙版的**极值行**，被描边内侧的抗锯齿残渣
   （右框内缘 1 列杂点 + 底框内缘 50 列）钉到整个内缩框高 **84px**（昵称本体只有 ~33px）
   ⇒ 字号 **88px**（框高才 96）⇒ 新名字在绿框**上沿外 2px** 改了 54 个像素，而批量照报
   `box_ok`。⇒ 现在字高取**墨量最大的那条行带**（`inkmask.row_bands`，缝 ≤3px 聚成带），
   该带仍高过「一行字」上限（45px）时再用**本色墨迹**那条带兜底。全量 24 张的字高被修正，
   `>45px` 的从 10 张降到 **1 张**。
2. **检测框跨两行评论（bug-168）**：`一麻袋开心(沧海一舟)-6/1.jpg` 这类框高 96 里装的是
   **两行**文字，而判据判的是「几何自不自洽」、不问「框里有几行」⇒ 四道判据全绿却把两行
   一起擦掉。⇒ 现在定位先按行带判「框里有没有第二行」，有就把**擦除蒙版的行**与**尾巴块的
   行范围**都夹进名字所在的那一条带。全量命中 **10 张**，独立脚本复量：距行带 >3px 的改动
   **0 像素**（那 3px 是既有的蒙版膨胀环）。**检测端（框为什么圈大了）仍未修。**
3. **等级徽章被当成名字（新修）**：抖音有一版等级徽章是**空心图标 + 数字**，填充率
   **0.48** 正落在汉字的 0.37~0.49 里 ⇒ 「实心药丸」那条判据**分不开**，徽章被当成名字的
   第一个段。后果不是「多擦一点」而是三连：槽位把徽章圈进去（`宝宝不乖-3/1.jpg` 槽位
   **194px**，真名字只有 112px）、字高取到徽章的 **32px**（真名字 28px）、取色从**蓝紫色**
   的徽章上取 ⇒ 出图「**名字又大又白**」。⇒ 加了第二条判据 **笔画粗细**（`cv2.distanceTransform`
   峰值：徽章 **16.0** vs 文字一律 **3.0~3.2**，差 5 倍，阈值取 6），且只对「上下连成一条带」
   的段生效（框跨两行时徽章会和两行文字连成一整段，不加这道闸会误删整段 ⇒ 实测回归 3 张）。
   全量 **36 张**受益（被丢的段笔画峰值全是 16.0），**定位 464 → 480**。⚠️ 后续两轮又抬到 **496**：480→495 是「徽章兜底（宽度区间+笔画粗细）」+「`row_keep` 按字带夹紧」，495→496 是「字带锚在**冒号所在行**」。

## 这个实验要回答什么

原有的 API 管线（标注框 → 擦除 → 写字）卡在**擦除**这一步：调 DashScope 的
`wanx2.1-imageedit` 擦用户名，14 次真调里**擦干净只有 3 张**，而且 **4 张擦完墨迹比原来还多**
—— 模型在蒙版区里**凭空造字**（bug-144）。根因已排除提示词 / 合成 / 对齐，判定为模型端随机性。

本实验换一个方向问：**这一批图的背景是近乎纯色的暗色 UI 底，属于 inpainting 的最简情形。
那还需要模型吗？传统确定性算法够不够？**

## 结论：三道指标 + 肉眼，全部通过

| 指标 | 结果 | 说明 |
|---|---|---|
| **墨迹清除率** | 8/8 张 **100%**（10830 px → **0**） | 槽位内一个非背景像素都不剩 |
| **蒙版外改动** | **0 像素**（8 张合计） | 局部性是**构造保证**，不是事后断言 |
| **造字** | **0 次** | 填充值只来自邻域已有像素，物理上不可能造字 |
| **尾巴整块平移** | 8/8 **逐像素相同**（合计 0 px 差） | 「冒号 + 正文」是**同一批像素搬家**，不是重画 |
| **名字↔冒号** | 8/8 = **5 px**（= 原图） | 结果图上**重新量**的，不是按构造推的 |
| **冒号↔正文（含正文内各段间距）** | 8/8 **与原图逐段相等** | 段宽、段间距**全部**对齐，不是只看第一段 |
| **改名后总长不变** | 8 张 **\|名字宽 − 槽位宽\| ≤ 2px**（合计 8px；4.jpg 精确 0） | 名字比槽位窄时**随机补字补满**，尾巴几乎不动（2026-09-29 规格） |
| **绿框 / 框外** | 8/8 **逐像素零改动** | 含描边抗锯齿边、框右界之外的一切 |
| **耗时** | **0.70 s/张**，单核 CPU | 对照：API 每次调用要排队 + 计费 |
| **成本** | **0 元** | 对照：API 按框计费，且失败也要钱 |

上表每一行都是**在结果图上重新量**的，不是从代码推的 —— 7 项判据的独立校验脚本见本文件最后。

## 实现的规格：整条装配一起平移，越框才截断

> 原话（四句，逐句补全了模型）：
> 1. 「识别『：』。冒号前是要修改的，『：』和后面的是不修改的。」
> 2. 「最后拼接：少了的用无字的部分填充，多了的截取。」
> 3. 「**『：』距离名字的距离不变**，底色和其他不能变。」
> 4. 「**正文也是相对距离不变**，整体是否超过框，是则截断。」

第 3、4 句合起来把模型补完整了：`[名字][间距][：][间距][正文]` 是**一整块刚体**，
名字一变宽窄，后面**全部跟着挪**，所有间距原样保持。

**后续补充（2026-09-29，两条新规格）**：

5. 「**拼接的时候，不管正文还是用户名都不要表情**」⇒ 新写的文本里不许有 emoji
   （原图里的 emoji 一个字都不动）。
6. 「**总体长度不够，生成更长的用户名，保持总体长度不变**」⇒ 新名字比原槽位**窄**时，
   不再「尾巴左移 + 右边填背景色」，而是**随机补字补满槽位**。
   这一条**推翻了第 2 句在「短」这一支上的旧做法**：旧做法是「尾巴左移
   `新名字宽 − 槽位宽`、右端空出来的那截填背景色」，于是**总长跟着变短**。
   旧行为仍可复现（`--no-fill`，或把 `config.FILL_SLOT_ENABLED` 关掉）。

```
原图:   [ 爱国者 ]←5→[：]←19→[正文··········]          框右界 ┤
结果:   [ SuperUser ]←5→[：]←19→[正文··········]              ┤   ← 整条尾巴右移 56px
结果:   [ 张三88 ]←5→[：]←19→[正文··········]                 ┤   ← 名字被补满到槽位宽，尾巴几乎不动
```

* **名字** 左对齐写进原名字的位置（`EraseRegion.slot`）。写之前先**剔掉 emoji**
  （`draw_text.strip_emoji`，见下）。
* **总长不够就补满**（`draw_text.fill_to_slot`）：名字墨迹比 `slot_width` 窄时，
  从「常用中文字池 / ASCII 字母数字池」随机补字，补到最接近 `slot_width` 的宽度。
  于是 `shift_px ≈ 0`、尾巴几乎不动，8 张实测 `|名字宽 − 槽位宽| ≤ 2px`（合计 8px）。
* **尾巴**（冒号 **+ 正文 + 其间所有空隙**）整块平移 `新名字宽 - 槽位宽`。
  `join_gap`（名字↔冒号）从**原图量**（8 张全是 5px），冒号↔正文的距离是**搬出来的**。
* **长了** ⇒ 尾巴右移；**装配整体越框**时按 `--fit` 处理，默认 `clip`：字号不动、从右往左砍字。
* **截断预算是「框」而不是「原名字的宽度」**：`EraseRegion.max_name_width =
  槽位宽 + 尾巴还能右移多少`。8 张实测余量差别很大：

  | 图 | 名字↔正文之间的余量 | `SuperUser`（140px） |
  |---|---|---|
  | 2 / 5 / 7 / 8.jpg | 92 / 89 / 78 / 91 px | **放得下，不截断** |
  | 3 / 9.jpg | 10 / 7 px | 截成 `SuperU` / `Super` |
  | 4 / 6.jpg | **0 px**（正文已经顶到绿框） | 截成 `Super` |

⚠️ **平移，不是重画。** 取原图尾巴墨迹 bbox 外扩 2px 的**一整块**，原位填背景色，
再整体贴到目标位置 —— 同一批像素搬家，字形宽度天然一致（实测新冒号 4px = 原冒号 4px）。
用 Pillow 重画会宽 1~2px，多出的像素漏到右边（bug-150）。

⚠️ **间距必须量出来，不能假设成「名字右缘 + 1」。** 那样会把「紧贴」当成原间距，
实测 2px 而不是 5px（bug-151）。

⚠️ **必须先搬尾巴、后写名字。** 搬尾巴要把旧位置填成背景色，那条竖带在新名字变宽时
**正好压在新名字身上** —— 顺序反了就是拿背景色啃掉名字的右半边。曾经想靠「把矩形左边界
切到名字右缘之后」来保名字，结果**把冒号从补丁里切掉了**，冒号整体错位 51px（bug-153）。

⚠️ **搬家矩形要夹在内缩框里。** 外扩的 `pad` 圈会伸出内缩框、盖到绿色描边的抗锯齿边上，
这一步又涂又贴，等于把描边的边线搬走一截（4/5/6/7.jpg 各有 124~549 px，bug-154）。

⚠️ **固定像素的内缩不够，还要按颜色削。** 描边往框内糊多少逐图不同 —— 5.jpg 糊到
框右缘 -7px，落在 `BOX_INSET=6` 之内，那一列被算成正文墨迹跟着搬走了（bug-155）。
现在 `inset_box` 之后再跑一趟 `shave_frame`：逐边检查最外一行/列是否「绿占优」且占比 ≥90%。

⚠️ **补字要「不近视」。** 字宽是离散的（中文≈整字宽、ASCII≈半宽），逐步随机补很
容易**近视**：在没有余量、不许越过槽位的图上，先补一个汉字（差 5px）比补一个 ASCII
（差 16px）看着更近，于是抓了汉字、之后就再也补不进更窄的组合。`fill_to_slot` 每步
除了随机抽字，还**穷举一个小字母表 `i8W张` 的 1~2 字组合**（`config.FILL_SLOT_ALPHABET`），
保证「两个 ASCII 落在槽位里」这类组合不会被错过。并列最优的候选里**随机取一个** ——
精度靠「谁最接近」定、随机性靠并列抽签定。8 张实测总长偏差 **≤ 2px**。

⚠️ **emoji 直接剔除，但要留痕。** `new_name` 里的 emoji 在 `plan_name` 里被
`strip_emoji` 剔掉（规格：新文本不含表情），剔了哪几个进日志与 `Outcome.stripped_chars`
—— **不静默改用户给的名字**。原图里的 emoji 不受影响（那是语料）。

⚠️ **随机补字必须可复现。** 种子默认由「图名 + 新名字」经 `md5` 派生
（不用内建 `hash` —— 它受 `PYTHONHASHSEED` 影响，跨进程不稳定）。同一张图永远给同一
结果，本实验看家的确定性不丢；`--seed N` 可整体换一套抽法。

## 与 API 路线的逐条对照

| | API 路线 | 本实验（本地） |
|---|---|---|
| 擦干净 | **3 / 14** | **8 / 8** |
| 造字 | **4 / 14 张凭空写字** | **0** |
| 确定性 | 随机（同用户同几何，一张干净一张造字） | 确定（同输入同输出） |
| 冒号 | 丢（9+1 次调用都没保住，bug-146） | 保住（**根本没擦、没画，原文不动**） |
| 尺寸下限 | **≥512px 硬约束**，295×47 的框必须外扩再缩回 | **无**，原分辨率直接擦 |
| 重采样损失 | 有（缩放往返） | 无 |
| 成本 / 耗时 | 按框计费 + 排队 | 0 元 + 0.68s |
| 依赖 | dashscope + rapidocr + opencv 全家桶 | numpy + opencv-headless + Pillow |

## 管线（四步，全本地）

1. **定位**（`core/inkmask.py`）—— 框内墨迹按**列**投影成段，用**核心色饱和度**把
   用户名（70~80）/ 冒号（31~42）/ 正文白（4~6）分开；徽章用「实心药丸」判据先摘掉。
   内缩框之后再按颜色削掉残留的描边（`shave_frame`）。**徽章**两条判据：填充率（实心药丸）
   **或**笔画粗细（`distanceTransform` 峰值 ≥6 ⇒ 图形；只认「上下一条带」的段）。
   量出**尾巴**（冒号及其右侧一切）的包围盒。
   **上下这一维同样要量准**（2026-09-30）：把命中的行按「缝 ≤3px」聚成**行带**，
   **字带**取墨量最大的那条（不是墨迹的极值行 —— 描边抗锯齿残渣会把字高顶到整个框高）；
   若全框有**两条以上**「一行文字」高的行带，判为**框跨两行**，本次出片**只动名字那一行**。
2. **擦除**（`core/inpaint_local.py`）—— 先**洗源**（把蒙版半径内的非背景像素在工作副本里刷成背景色），
   再 inpaint，最后**只把蒙版内那部分贴回原图**。蒙版**只覆盖用户名槽位，不含冒号**。
3. **排布**（`draw_text.plan_name`）—— 先**剔掉 emoji**（`strip_emoji`），再按原字高
   二分搜索字号，定下要写的字、宽度，名字比槽位窄时**随机补字补满槽位**
   （`fill_to_slot`，总长不变），以及**尾巴该平移多少**。此时一个字都还没画。
4. **搬尾巴**（`draw_text.shift_tail`）—— 把**原图**的尾巴像素整块平移，原位填背景色。
   矩形夹在内缩框内，位移夹在框与图像边界内。
5. **写字**（`draw_text.render_name`）—— 最后才把新名字左对齐写在原名字的位置上。
   **冒号一个字都不画**，它是被搬过来的原文像素。
6. **度量** —— 擦除前后各数一次槽位内非背景像素 + 蒙版外改动；
   再在**结果图上重新量**「名字↔冒号」，以及「框右界之外有没有被改动」（越框判据）。

> 以上是**换名**那条流水。**换正文**是另一条：上游几何（`geom.json`，或从交付树
> `manifest.json` + 各段 `comments.jsonl` 自动重建）→ `body_text.measure_body`
> 在 `text_box` 行带内量行 / 宽 / em / 颜色 → `replace_body.plan_body` 按**像素宽**从
> `bodies.jsonl` 挑一句（行数相等 / 不越界 / 第一行顶满 / 右缘对齐）→ 逐行铺平擦除 →
> 断行写回 → `batch_body.verify` 用同一把尺子在成品上过**八道闸**。
> 原理见 [`docs/mock正文.html`](docs/mock正文.html)，用法见 [`mock/README.md`](mock/README.md)。

## 三个踩过的坑（都在代码注释里）

1. **不能按位置切分「用户名 vs 正文」。** 最初用「最右段是正文」，8 张里错 6 张 ——
   正文里字与字的空隙会把它切成**多段**（7.jpg 的正文是三段 `[198-253]/[255-280]/[310-421]`），
   取「最后一段」会把正文前半截**当成名字一起擦掉**。改用颜色判据后 8/8 正确。
2. **`ink_after` 必须量在「擦完、写字之前」。** 最初量在最终图上，把**新写的名字**也算成残余墨迹，
   得出 3.jpg「1326 → 1497 越擦越多」的假象 —— 看着像 bug-144 在本路线复现，其实纯粹是量错了对象。
3. **`cv2.inpaint` 的取样半径会伸进描边。** 绿边只有 5px 厚，而 3.jpg 的字形下缘几乎贴着它 ⇒
   Telea **把绿色抹进了填充区**。修法是「洗源」：只洗工作副本，Telea 于是只从干净背景取样。
4. **「冒号位置对了」不等于「冒号像素对了」。** Pillow 画的「：」墨迹宽 **6px**、原图只有
   **4px** —— 坐标能对齐到 0px，多出的 2px 照样漏到冒号**右边**。正解是**整块平移原图像素**，
   不是重画。（bug-150）
5. **间距要从原图量，不能假设成「名字右缘 + 1」。** 那样把「紧贴」当成了原间距，
   实测 2px 而不是 5px。量出来的 `join_gap` 才是可复现的。（bug-151）
6. **一句有歧义的需求，「自洽的推理」不等于「正确的理解」。** 中间有一版把「短了要填充」
   推成「原名字那块是固定槽位 ⇒ 冒号不能动」，链条完整无懈可击，渲染出 `Super ：`
   —— 名字和冒号之间裂开一大截空白。用户看图指正后才知道填充指的是**冒号右边**那截。
   同一句话两处空白都说得通。**以后再遇到这种强度的反推，先给个最小样例确认。**（bug-152）
7. **「保护新写的东西」的思路会把老东西切掉。** 搬尾巴要填掉它旧位置那条竖带，而那条带子
   在新名字变宽时正好压住名字 —— 于是很自然地想「把矩形左边界切到名字右缘之后」。
   这一刀保住了名字，却**把冒号从补丁源里切走了**（冒号在名字左缘的右边），
   冒号没被搬走、原位被涂成背景，整条尾巴错位 51px。**正解是换顺序，不是收边界。**（bug-153）
8. **`pad` 是「别切掉抗锯齿」，但它自己会越界。** 外扩那一圈会伸出内缩框、盖到绿色描边的
   抗锯齿边上，而这一步既涂又贴 —— 描边的边线就被搬走一截（4/5/6/7.jpg 各有 124~549 px）。
   横向、纵向都中招。**凡是「先涂背景再贴像素」的操作，矩形四边都得夹在可动区域里。**（bug-154）
9. **固定像素的内缩挡不住逐图变化的抗锯齿。** `BOX_INSET=6` 是全局常量，但描边往框内糊
   多少每张图不同（5.jpg 糊到 -7px）。那一列于是被当成正文墨迹，跟着尾巴一起被搬走。
   改成按**颜色**逐边削（`shave_frame`），比调大 inset 安全 —— 调大是全局的，
   会连字形上下缘一起切掉（3.jpg 的字下缘本就贴着框）。（bug-155）

## 边界（**别把这个结论推得太远**）

1. **依赖「用户名是框内唯一的彩色文字」。** 本语料 8 张的昵称一律青色（饱和度 70~80），
   与白色正文（4~6）分得很开。⚠️ 换到**视频号**那类「昵称不饱和、正文更白」的语料，
   这条判据直接不成立 —— 实测定位成功率只有 **26.7%**。
   **批量实测（650 张，跳过 88 张后余 562 张进管线、其中 551 张可定位）把这一条钉死了**：
   定位失败的 71 张里 **38.0% 是「框内压根没有高饱和段」**（昵称淡灰蓝、或检出的框根本不是
   评论行），**54.9% 是「有饱和段但拼不出名字 + 冒号」**——昵称里带 emoji 时，emoji 是实心
   团块，会被「填充率判徽章」的规则剔掉，剩下的文字段拼不出结构。
   详见 [`docs/技术说明.md`](docs/技术说明.md) §6。
2. **依赖「背景近乎纯色」。** 本语料背景 std ≈ 5、mode 色 `(37,37,49)`。背景若有渐变、纹理、
   或压在图片/视频上，`flat` 会露出补丁，Telea 会糊 —— 那时 API 路线（或专门的 inpainting 模型）
   才有意义。
3. **样本量 = 8 张、1 个用户。** 8 张全是「爱国者」同一个人的同一版式。
   这是**同一版式的 8 次重复**，不等于 8 个独立样本。
   **已按这条做了批量**（650 张 / 112 个用户，`core/batch_run.py`）：擦除与排版
   **1488/1488 零违规**，但定位只有 **90.0%** —— 也就是说 8 张给出的「全清」只覆盖了
   这个语料里约六分之五的图。见 [`docs/技术说明.md`](docs/技术说明.md) §6。
4. **框是查表给的，不是自动检测的**（指单张模式）。8 张单跑时框来自 `config.BOX_TABLE`，
   好让 inpainting 的结论不被检测误差污染；批量模式接 `core/box_detect.py`（移植件），
   于是检测的错会进入统计 —— 报告里按「检测 / 定位 / 擦除 / 排版」分开数。
5. **能写多宽取决于「框里还剩多少」——而这在 8 张图里差了 90px。** 名字能占用
   槽位 + 尾巴能让出的余量；余量 = 正文右缘到绿框的距离：

   | 图 | 余量 | 预算 | `SuperUser`（140px，字号 28） |
   |---|---|---|---|
   | 2 / 5 / 7 / 8.jpg | 92 / 89 / 78 / 91 px | 176 / 173 / 162 / 175 px | **完整放下，不截断** |
   | 3 / 9.jpg | 10 / 7 px | 94 / 91 px | 截成 `SuperU` / `Super` |
   | 4 / 6.jpg | **0 px** | 84 px | 截成 `Super` |

   三个 `--fit` 的代价（同一张 2.jpg）：

   | `--fit` | 结果 | 字号 | 代价 |
   |---|---|---|---|
   | **`clip`**（默认） | `SuperUser` | **28**（=原字高） | 名字被砍（余量不够的图上真的丢字） |
   | `width` | `SuperUser` | **16** | 字高只有原来的 **57%**，且**不许动尾巴** |
   | `height` | `SuperUser` | 28 | 溢出，压住冒号；尾巴被夹在框内，`名字↔冒号` 掉到 **0px** |

   这不是实现的毛病，是「名字写长 + 版面不变」本身的无解：`super`/`用户001` 这类
   长度相当的名字完全没问题，`SuperUser` 这种就必须在三者里选一个代价。

6. **`--fit height` 会违反规格，而且是**被检出来的**。** 它不裁名字，于是尾巴被夹在框内、
   名字压住冒号 —— 结果表里 `冒号距名字` 那一栏会亮 ✗，`gap_ok` 全红。
   这个模式的用途就是「看清不裁会怎样」，不是拿来出片的。

## 独立校验脚本（7 项判据，全部在结果图上重量）

README 里的每个「✓」都出自下面这套检查，逐图跑、逐项数。它**不相信构造**：
尾巴是不是真的整块搬过来的，靠「原图那块矩形 == 结果图平移后的同一块矩形」逐像素比；
间距是不是真的没变，靠在结果图上重新切列段、和原图的段宽/段间距列表比。

> 📁 2026-10-27 合并后，`config` / `inkmask` / `replace_username` 这些模块住在 **`core/`** 里
> （唯一一份），所以这段要在 **`core/` 里跑**（或把 `core/` 放进 `sys.path`）：
> `cd core && ../python3 check.py`，其中 `data/` 仍按工程根算。

```python
import numpy as np, config, inkmask, replace_username
from pathlib import Path
from PIL import Image

for name in sorted(config.BOX_TABLE):
    img = np.array(Image.open(f"data/{name}").convert("RGB"))
    o = replace_username.process_image(Path(f"data/{name}"), "SuperUser", save_compare=False)
    res = np.array(Image.open(o.output).convert("RGB"))
    r = inkmask.find_erase_region(img, config.BOX_TABLE[name])
    bg = np.array(r.bg_color, dtype=np.uint8); pad = config.TAIL_MOVE_PAD
    sh, bx0, by0, bx1, by1 = o.tail_shift_px, *r.box_rect
    nr = r.slot[0] + o.text_width - 1                      # 新名字墨迹右缘

    # ① 名字↔冒号：结果图上量，必须等于原图
    rows = slice(r.colon_rows[0], r.colon_rows[1] + 1)
    ink = inkmask.compute_ink_mask(res[rows, nr+1:nr+40], bg, config.BG_DIST_THRESH)
    assert int(np.nonzero(ink.any(axis=0))[0].min()) == o.join_gap

    # ② 尾巴（含 pad 圈、夹在框内）整块平移后必须逐像素相同
    sy0, sy1 = max(by0, r.tail_rows[0]-pad), min(by1, r.tail_rows[1]+1+pad)
    sx0 = max(bx0, r.tail_span[0]-pad)
    sx1 = min(img.shape[1], bx1, r.box_right, r.tail_span[1]+1+pad)
    assert not (img[sy0:sy1, sx0:sx1] != res[sy0:sy1, sx0+sh:sx1+sh]).any()

    # ③ 冒号↔正文、正文各段之间的间距：两边的段宽与段间距列表必须相等
    def segs(im, xf, xt):
        m = inkmask.compute_ink_mask(im[sy0:sy1, xf:xt], bg, config.BG_DIST_THRESH)
        return inkmask.column_segments(m.any(axis=0))
    a, b = segs(img, r.colon_span[0], sx1), segs(res, r.colon_span[0]+sh, sx1+sh)
    assert [q-p+1 for p, q in a] == [q-p+1 for p, q in b]
    assert [a[i+1][0]-a[i][1]-1 for i in range(len(a)-1)] == \
           [b[i+1][0]-b[i][1]-1 for i in range(len(b)-1)]

    # ④ 尾巴腾出去的那条空隙必须是纯背景（名字右边那截）
    #    补满槽位后 sh 多为 0~±2，这个区间常常是空的 —— 空区间 assert 自然成立；
    #    它现在守的是「万一没补满、确实留了缝」那种情况。
    v0 = max(sx0, nr+1) if sh > 0 else sx1+sh
    v1 = sx0+sh if sh > 0 else sx1
    v = res[sy0:sy1, v0:v1]
    assert not inkmask.compute_ink_mask(v, bg, config.BG_DIST_THRESH).any()

    # ⑤ 绿描边（原图里明确是绿的像素）一个都不能变
    sl = (slice(by0-10, by1+11), slice(bx0-10, bx1+11))
    i = img[sl].astype(int)
    strong = (i[:, :, 1] - i[:, :, [0, 2]].max(axis=2)) > 60
    assert not (img[sl][strong] != res[sl][strong]).any()

    # ⑥⑦ 框右界之外、内缩框上下之外，必须零改动
    assert not (res[:, bx1:] != img[:, bx1:]).any()
    assert not (res[by0-10:by0] != img[by0-10:by0]).any()
    assert not (res[by1:by1+10] != img[by1:by1+10]).any()
```

⚠️ 写校验脚本时踩过三个坑，都是**判据本身错了**而不是代码错了：
「最右墨迹列」会把绿描边算进去（框外本来就有别的东西）；「腾空区」在名字变宽时
被新名字覆盖（要取名字右边那一截）；「框内边缘」把内缩框的第一行也框进去了
（那一行本来就在可动区域内）。**报 ✗ 之前先确认判据说的是你要验的那件事。**

## 三条可复用的工程约束

把这条本地路线接回任何别的管线时，真正值得带走的不是 `core/inkmask.py`（它只在这个语料上
硬化过），而是下面三条工程约束：

1. **「洗源」**——inpaint 前把蒙版半径内的非背景像素在工作副本里刷成背景色，
   免得把绿描边采样进填充区；
2. **「只贴蒙版内」的合成方式**——`out = img.copy(); out[inside] = filled[inside]`，
   让「蒙版外零改动」成为**构造保证**而不是事后断言；
3. **「平移而非重画」+「先搬后写」的顺序**——凡是要保住一段原始像素的版式操作，
   都别重新渲染它，整块搬；而搬动会涂背景的，必须排在最后绘制之前。
