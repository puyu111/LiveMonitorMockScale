# 扩展张数线（`expand/`）

**给真实语料里每个真实用户按他自己的名字补图，就地交付。** 底图从**别的真实用户**借（正面照），
框内「用户名 + 等级徽章」一起换成该用户自己的，**正文一行不动**，写回用户自己的目录、
目录名改成 `<用户名>-<新张数>`。

需求原文、口径的每一次拍板、逐轮验证记录全在 **[`扩展张数.md`](扩展张数.md)**（就在本文件夹里）——
**改动出片逻辑前先读它**；本文只讲**怎么跑、当前账是多少**。

## 怎么跑（配置优先）

**「出抖音」还是「出视频号」现在由一份 JSON 决定**，不再靠记忆里那串 flag：

| 配置文件 | 平台 |
| --- | --- |
| `expand_produce.config.json` | 抖音（`platform: auto`，按目录名认出来） |
| `expand_produce.视频号.config.json` | 视频号（**`platform: generic`** —— 刻意，**不是** `wechat_channels`，别「顺手修正」） |
| `expand_produce.视频号app.config.json` | 视频号 **App 端**（`platform: **wechat_app**`）—— App 语料的目录名只叫「视频号」，`auto` 判不出 App 与网页版（会判成 `wechat_channels`），所以**必须写死** |
| `expand_produce.快手.config.json` | 快手 **App 端**（`platform: **kuaishou_app**`）—— 交付框是多行融合框，目标行不一定是第一行；本线会**自动从交付树重建 geom**（`comments.jsonl` 的 `colon_box` 定行） |

**命令行任何参数都能逐项覆盖 JSON**（优先级：命令行 > JSON > 脚本里的 `DEFAULTS`）：

```bash
# 默认读 expand_produce.config.json（抖音）
python3 expand/expand_produce.py                            # P1：只读账，只写 expand_plan.json
python3 expand/expand_produce.py --mode sample              # P2：样张 + 上下对照条
python3 expand/expand_produce.py --mode run --out /tmp/exp  # P3：预演树，不动语料
python3 expand/expand_produce.py --mode run --yes           # P4：就地写回（要显式确认）

# 视频号：换一份配置
python3 expand/expand_produce.py --config expand/expand_produce.视频号.config.json

# 视频号 App 端（720x1600）：另一份配置 + 另一条档
python3 expand/expand_produce.py --config expand/expand_produce.视频号app.config.json

# 快手 App 端（590x1280）：另一份配置；交付框是多行融合框，自动重建 geom
python3 expand/expand_produce.py --config expand/expand_produce.快手.config.json
```

📖 **这几份配置本身就是参数手册**：每个键**紧跟一行 `_<键名>` 备注**，写着它干什么、可以填什么
（取值/范围/单位）、不填时用哪个默认、以及踩过的坑 —— 例如 `_roi_vinset` 那条写着
「**默认 0 别改回 5**」、`_out` 那条写着「`null` = 就地写回，须同时 `yes: true`」。
所以想知道某个旋钮能填什么，打开配置看它下面那行，不必翻 `--help`。改参数时**连备注一起改**。
这几份配置的**共有备注键逐字相同**（同一份文本原样拷贝，**别手工对敲**）：**只差** `_note` 与
`_platform` 两处（前者说这条线是谁、后者说这一档为什么这么选）；App 那份**另加** `_结论` / `_还欠`
两条，写它自己的账与待办。⚠️ **这几份配置的键集是同一套 31 个**（含 `pair_badge_absent`、
`livepipe_join`、`level_pair`、`level_pair_soft`、`two_pass`、`resume`、`cache`）—— 加/改键时三份一起改；**值**可以各不同：目前只有 App 那份
把 `pair_badge_absent` 写成 `true`（见口径 ⑨）。
⇒ 改公共备注（`_source` / `_ratio` / `_roi_inset` …）时**三份一起改**。

## 这条线的口径与账（全文见 [`扩展张数.md`](扩展张数.md)）

`core/batch_produce.py`（mock 线）出的是**假名字假图**，回答的是「这条本地路线能不能批量出片」；
`expand/expand_produce.py` 是它的对面 —— 语料里**每个真实用户**都按**自己的名字**出图、就地补进他自己的
目录，一次交付。两条线共用同一套度量与出片函数（`inkmask` / `inpaint_local` / `draw_text` +
`replace_username` 的判据），**口径 9 处不同**，全部落在 `expand/expand_produce.py` 里
（`core/batch_produce.py` 一行不改）。全文见 [`扩展张数.md`](扩展张数.md)。

| # | 口径 | 说明 |
|---|---|---|
| ① | **张数** | `T = max(min_images, ceil(ratio × 现张数))`（脚本默认 `5 / 1.5`；**三份配置现在都写 `1.6`** ⇒ 跑起来那行报告会印真用的值），只补 `T − 现张数`；**产出缺口 ≤5% 不阻断、>5% 交付（`run`）退 3**（`--only` / `--limit` 小批不判这条）；缺口**逐用户**列在 `expand_reconcile.csv`，不从账上抹掉 |
| ② | **底图从别的用户借** | `base.user_dir ≠ target.dir`，且**允许复用**（一张底图最多借 `--base-cap 3` 个用户、同一目标同一底图 ≤ `--per-target-per-base 2`） |
| ③ | **擦除** | 框内 + **徽章左沿外扩约 8px**（药丸左圆头落在框外） |
| ④ | **徽章整颗换** | 换成**目标用户自己**那颗药丸（含框外的左圆头）。自己图上定不到徽章 ⇒ 这个用户 **0 张** —— 宁可不出，也不出一张顶着**别人等级**的图。⚠️ **唯一的例外是 ⑨**（要显式开 `pair_badge_absent`；不开就是本档原样） |
| ⑤ | **纯 ASCII 昵称目录整目录跳过** | 保留 `collect_material` 的 `SKIP_PURE_EN`（只跳"当底图"，它自己的图照用） |
| ⑥ | **就地写回** | 新图叫 `扩展N.jpg`，目录名改成 `<用户名>-<新张数>`（预演树里保留原名） |
| ⑦ | **标注框取自 `manifest.json` 的 `roi`（表式），不做像素检测** | 见下 |
| ⑧ | **出片口径全盘照上游**（2026-10-11 晚改定；**两个例外见下**） | `render_one` = **`replace_username.process_image(...)` + 贴徽章**，与 `core/batch_run.py` 每天在跑的那条路**同一个函数、同一套画法**：字号 = **逐张跟这张底图的 `region.glyph_height`**（`font_size=None`）、墨宽 = **Noto 原样墨宽**（不拉宽）、擦除 = **`inkmask` 原蒙版**（不多擦上下）。此前扩展线自己造的三处偏离（① 语料标定一个平台字号 ② `adv_k` 横向重采样 ③ `ERASE_EXT_PX` 多擦 3 行 + `fringe_ink` 残墨闸）**连同整套标定机制一起删了**，不设开关；三处遗漏的**代价已逐项量出**（字号散成 15~28、墨宽比底图槽位窄 12%/18%、框外上下 3 行共 227/258px 旧名残墨）—— 见 [`扩展张数.md`](扩展张数.md) §22。唯一一处上游改动：`process_image` 多一个 `inset=` 形参（扩展线的框取自 `manifest.roi`，内缩得用 **5** 而不是 `config.BOX_INSET=6`；`inset=None` 与旧行为**逐像素相同**，55/55 张已证） |
| ⑨ | **无丸配无丸**（2026-10-12 用户定案；`pair_badge_absent`，默认 `false`） | 目标**自己图上定不到徽章**时**照出**，但条件反过来 —— **底图也必须是「没有徽章位」那张**，出片**只换名字、徽章位一个像素都不碰**（账里 `badge_note` 写明）。**这不是放宽 ④，是配对**：④ 挡的是「顶着**别人**的丸」，而这条路一个徽章像素都不碰；反过来「底图必须有一颗**同档**的丸」那条闸对**本来就没有丸**的用户既不成立也没素材。**有丸配同档有丸、无丸配无丸** —— 于是同一条 `allocate` 里两条互斥的分支：`want_badge_w`（C1 同档）优先，它为空时看 `pair_badge_absent`（底图**必须无丸**），两者都不满足才回老行为（底图必须有认定徽章）。⚠️ **别拿 `--allow-unlocated-badge` 当这个用**：它只放开 `render` 侧一条已冗余的判定，**改不了底图池**（实测池子不变、12 张全是**假丸**）—— 见 [`扩展张数.md`](扩展张数.md) §28 |

**⑧ 的两个例外**（2026-10-11 深夜，用户：「**等级标的数字的高度和中文不是一样的，英文，中文，
数字计算逻辑是不一样的**」⇒ 选「两处都改」）。量出来的根据：我们字体同一个字号下，**中文墨高
= 1.00em，数字/大写英文 = 0.75em，小写英文 = 0.80em**，而**平台上数字和中文一样高**；平台字形比
也分成两类（抖音中文 1.456 / 含字母 1.104，视频号 1.387 / 1.172）。两处例外都**只管"算多宽/多大"，
不碰画法**（`process_image` 那条路一个字没改）：

| | 例外 | 效果（抖音 / 视频号，逐张在成品图上重量） |
|---|---|---|
| ① | **字号按"要写的那串字自己"对墨高**（`fit_font_size_for(text, gh)`） | 数字名 0.74 → **1.00**、英文名 0.81/0.80 → **1.00**；**纯中文不变**（1.00 → 1.00） |
| ② | **名字对账的尺子换成按类标定的平台宽度 k**（+ 图上**量到过药丸**就直接删前缀数字） | 视频号 **7 户翻正**（旧账会把等级数字写进名字：`✦13 13yuyuyu`、`✦8 8万事顺意`、`✦11 11天空`、`✦6 6李妥妥呀`、`✦7 7余生&默走`、`✦7 7生活百般滋味`），抖音 1 户（`5XW → XW`，本来不出片）；`0x0`（图上没药丸）不动 |

### 框从哪来：表式取 `roi`，不跑 `detect_box`（2026-10-10 用户口径）

用户原话是「**参考换用户名功能的方式**」—— `replace_username.resolve_box` 那条线的注释写得很清楚：
「**故意不做自动检测**。本实验要量的是 inpainting，不能让框检测的误差混进结论」。
`expand/expand_produce.py` 照此办理：框取 `manifest.json` 逐图的 `roi`（表），`detect_box` 只在
`roi` 缺失/越界时兜底，且把来路逐类计数打印（`标注框来源：{'manifest.roi': 885}`）。

2026-10-10 20:08 上游把绿框改成了**留白框**（`export_user_images.py` 新增 `--pad-ratio 0.25`，
每边外扩 ~9px），`roi` 仍是**紧贴那一行字**的值 —— 于是「画的框长什么样」与我们的量测**彻底无关**。
⚠️ 但 **`config.BOX_INSET = 6` 不能照搬**：那个 6 是给「画在图上、含彩色描边」的框用的
（`BOX_TABLE` 就是那种坐标），而 `roi` 不含描边，再内缩 6px 等于**从字里切掉 6px** ——
实测视频号 120 张里名字定位失败率 `6/120 → 88/120`、`adv_k` 标定 1.40 → 1.63。
⇒ 新增 **`ROI_INSET = 5`**（`--roi-inset`，写进计划）。取值是拿**已交付那一版计划**
（`/tmp/plan_backup/`，抖音 481 / 视频号 91 张）**逐张回放**扫出来的：`base_slot` 在每个内缩量下
都逐张相同（列量测不受纵向窗口影响），只有字高分得开 ——

| 内缩量 | 视频号（旧记录字高中位 21） | 抖音（旧记录 20） |
|---|---|---|
| 0 / 2 / 6 | 27 / 26 / 18 | 27 / 25 / 17 |
| **5** | **20**（87 张里 22 张逐张相同） | **19** |
| 4 | 22 | 21 |

全量重跑后也只有 **5** 同时复现两平台的**徽章宽合法族**（视频号 `[64,84]`、抖音 `[71]`）
与「有贴图源的用户数」（视频号 26 → 28）。

### 真命令与常用旋钮（2026-10-10 实测；2026-10-11 分线后路径）

**抖音与视频号各有一份运行配置**（`expand/expand_produce.config.json` /
`expand/expand_produce.视频号.config.json`），所以最省事的跑法是**不带参数**；
下面第一段仍是「指名道姓」的写法，便于看清每个旋钮。

```bash
cd ~/github/LiveMonitorMockScale/mock_scale       # 本仓库

# ⓪ 读配置跑（2026-10-11 起）：抖音用默认那份，视频号加 --config
python3 expand/expand_produce.py
python3 expand/expand_produce.py --config expand/expand_produce.视频号.config.json

# ① 抖音：平台档 auto 就认得出来（路径里带「抖音」⇒ douyin）
python3 expand/expand_produce.py --mode plan \
    --source ~/github/eagle/Embodied/out/livepipe_example3/抖音/all_users_正面_3张以上     # P1 ~12s（885 张 / 8 进程）
# ② 视频号：**必须显式 `--platform generic`** —— auto 会按目录名认成 wechat_channels，
#    那一档在 238 张抽样上只定得到 82 张（34.5%），generic 是 127/238（53.4%），
#    而且 generic 是它的**严格超集**（两边都定到的 82 张槽位逐张相等；见 扩展张数.md §17.4）
python3 expand/expand_produce.py --mode plan --platform generic \
    --source ~/github/eagle/Embodied/out/livepipe_example3/视频号/all_users_正面_3张以上     # P1 ~6s（445 张）

# P2 样张：每个用户一张 + 「上底图 / 下成品」对照条（默认落 /tmp/expand_samples）
python3 expand/expand_produce.py --mode sample --platform generic --samples 4 --out /tmp/exp --source <平台目录>

# P3 预演：出片进预演树，**语料一个字节都不动**（先小批）
python3 expand/expand_produce.py --mode run --platform generic --source <平台目录> --out /tmp/exp
python3 expand/expand_produce.py --mode run --source <平台目录> --only 肘死你 --limit 10 --out /tmp/exp

# P4 就地写回：新图进用户自己的目录、目录名改 <用户名>-<新张数>（要显式 --yes）
python3 expand/expand_produce.py --mode run --platform generic --source <平台目录> --yes
```

产物落哪：`plan` 写语料根的 `expand_plan.json`（**确定性** —— 同语料同参数重跑 md5 相同），
外加两个**评测旁挂**：`expand_measure_timings.jsonl`（逐图 decode/locate/badge 耗时）与
`expand_pairs.jsonl`（逐次配对；C 起 `tier`/`t_level`/`b_level` 有值，第 3 层排除也记一行）；
另有 `expand_measure_timings.jsonl` 逐图带 `scan_px`（D 的 `N_scan_px`）与 `badge_checked`；它们只喂评测、不参与任何判据（见 `docs/评测方案.html`）；
`--livepipe-join` 再落 `livepipe_join.json`（**A 档只读对账**：每张导出图 join 回
`comments.jsonl` / `rows.jsonl`；缺文件降级 `no_source`，不影响出片）；
`--cache` 另写 `expand/measure_cache.json`（**B 档量测缓存**：逐图量测 + 字号拟合扫描，
原子写、代码/字体指纹一变整份作废；含用户目录名/昵称 ⇒ 已 gitignore，**不是交付物**）；
`run` 写 `expand_run_report.json`（逐图，含逐张 `ms` 与 `timings/counters`）+ `expand_reconcile.csv`（逐用户对账），
并把进度 journal `expand_run_progress.jsonl` 写在 `--out` 目录（逐张完成即 flush，崩溃后 `--resume` 靠它）；
`--out` 给到哪就落哪、就地模式落语料根；`sample` 写 `<out>/samples/`（`samples.json` + `cmp_*.png` 上下对照条）。

常用旋钮：`--workers`（默认 8）、**`--roi-inset`**（默认 5，见上）、`--base-cap` / `--per-target-per-base`
（复用上限）、`--only` / `--limit`（小批）、`--sprite-rects <json>`（外部喂徽章矩形，救"自己图上定不到徽章"
的用户）、`--allow-badge-delta` / `--allow-unlocated-badge` / **`--allow-no-sprite`**（放宽口径，
只给样张/排错用；最后一个**不是**「无徽章出片」—— 它跳过贴徽章，底图那个徽章会原样留着、
顶着别人的等级，见本节末）、**`--pair-badge-absent`**（= 口径 ⑨ 无丸配无丸，**不是**放宽 ——
它是「无丸的配无丸的」，底图侧要求**更严**；只有 App 那份配置默认开）、
`--no-rename`（就地写回但不动目录名）、`--seed`（默认 20261010）、
**`--livepipe-join`**（A 档对账表，只读）、**`--resume`**（E 档断点续跑，复用指纹一致且产物在的 job）、
**`--cache`**（B 档量测缓存：把逐图量测与**字号拟合扫描**缓存进 `expand/measure_cache.json`；
默认关，开不开产物逐字节相同；文件含语料路径/用户名 ⇒ 已 gitignore，**不是交付物**）、
