# mock 用户线（`mock/`）

**读一份名单 JSON，拿真图当底子把名字换成假名字，产出成品** —— 用来验「这条管线能不能批量出片」。

出片那一段调的是 `core/replace_username.process_image`，**整条工程共用的一份代码**
（见 [`../docs/工程结构.md`](../docs/工程结构.md)）—— 所以本线每天在验的那套判据，
就是扩展线出片时用的那套。

线的全貌（为什么这样做、管线逐段原理、边界在哪）在 [`../docs/技术说明.md`](../docs/技术说明.md)
与 [`../docs/全流程说明.md`](../docs/全流程说明.md)；本文只讲**本线怎么跑、口径是什么、实测多少**。

## 怎么跑（配置优先）

**「这次怎么跑」写在运行配置里**（`make_spec.config.json` / `measure_bodies.config.json` /
`gen_bodies.config.json` 在本文件夹，`batch_produce.config.json` / `batch_run.config.json` /
`batch_body.config.json` 跟着脚本住在 `core/`），
所以常见的用法是**不带参数**（正文线除外：`--source` / `--out` 必填；
优先级：命令行 > JSON > 脚本里的 `DEFAULTS`，细则见 [`../docs/工程结构.md`](../docs/工程结构.md)）：

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt

python3 mock/make_spec.py            # 生成名单 → mock/names/
python3 core/batch_produce.py        # 按名单出片 → outputs/produce_<时间戳>/
python3 core/batch_run.py            # 拿真语料验收（检测 → 定位 → 擦除 → 排版）

# 正文线：几何默认自动找（<source>/geom.json，或从交付树 manifest 重建），全程只读语料
python3 mock/measure_bodies.py --source <语料根>   # 正文量测 → mock/data/（两份 JSON）
python3 mock/gen_bodies.py           # 按字数阶梯出句子 → mock/data/bodies.jsonl
python3 core/batch_body.py --source <语料根> --out out/body_run   # 换正文 + 八道闸 + report.json

# 命令行任何参数都能**逐项覆盖** JSON
python3 core/batch_produce.py --limit 3 --dry-run   # 只看选材配对，不出片
```

📖 **配置本身就是参数手册**：每个键**紧跟一行 `_<键名>` 备注**，写着它干什么、可以填什么
（取值/范围/单位）、不填时用哪个默认、以及踩过的坑。所以想知道某个参数能填什么 —— 打开配置
看它下面那行，不必翻 `--help` 或翻历史命令。改参数时**连备注一起改**。

### 正文量测：`measure_bodies.py` → `data/`（2026-10-28）

换名字的下一步是换**评论正文**。正文不能像名字那样「按槽位生成」—— 它的宽度由原作者
说了多少字决定，写短了框里留白、写长了顶到绿框。所以第一步是**把语料量成一张需求表**：

```bash
python3 mock/measure_bodies.py --source <语料根>     # 默认读同目录的 measure_bodies.config.json
```

**输入是上游几何，来源按优先级自动找。** ① `--geom` 显式给的文件（给了就必须能读，读不了
直接退出码 2，不悄悄退回自动）；② `<source>/geom.json`；③ 都没有时，按交付树
`manifest.json` 的 `(seg, t, roi)` 去各段导出目录的 `comments.jsonl` **自动重建**。自动重建
也拿不到（语料根没有 manifest、或某段没有 `comments.jsonl`）才退出码 2，不会去猜框。
几何形状是上游 v1：`{"schema_version": 1, "kind": "geom", "items": {相对路径: {text_box, colon_box, …}}}`。
`text_box` / `colon_box` 只定「这一行在哪、正文从哪起」；下面五个数仍在框内**从墨迹重量**，
不直接拿上游的 `text_box.x2` 当右缘。

常用参数（都能写进 `measure_bodies.config.json`，命令行逐项覆盖）：

| 参数 | 作用 |
| --- | --- |
| `--source` | **必填**，语料根（图和几何的同一棵树；livepipe 交付树可直接自动重建） |
| `--geom` | 上游几何 JSON；不给就按上面的优先级自动找 |
| `--out` | 两份 JSON 写到哪；默认本脚本旁边的 `data/` |
| `--platform` | 黑名单生效的平台键，默认 `generic` |
| `--em` | 强制字号；`0` = 每张量墨迹字高（批量阶段会用这一行名字的 em 覆盖） |
| `--limit N` | 只量前 N 张（按相对路径排序） |
| `--blacklist` / `--no-blacklist` | 是否套用 `source_blacklist.json`（默认开；`--no-blacklist` 只对账用） |
| `--per-bucket` / `--model` / `--prompt-version` | 写进 `bodies_need.json` 的下单意向（本脚本不联网） |
| `--dry-run` | 只量、只打印，不写文件 |
| `--quiet` / `--verbose` | 少打日志 / 每张打一行 |

量的是五个数（在 `text_box` 行带内从**墨迹**重量，不直接信上游的边）：

| 数 | 怎么量 | 为什么不用上游 |
| --- | --- | --- |
| 正文左沿 | 冒号**墨迹**右沿 + 2px 起第一列墨迹（冒号从行带里按「窄段 + 离 `colon_box` 中心最近」认） | **590 宽那批的 `colon_box` 整体右偏 17px**（`四___◆3-5/5`：墨迹 135–138，框 152–170），按 `x2` 切会丢掉第一个字 |
| 正文右缘 | 正文自己的最右墨迹列 | `text_box.x2` 比墨迹宽 1~7px，拿它当右缘新字会顶到绿框 |
| 行数 / 每行上下沿 | 框内墨迹的**行带**（`inkmask.row_bands`） | 折行的续行回到**段落左沿**（40px），只看冒号右边会把两行读成一行 |
| 字号 em | 正文墨迹的字高（本字体 `ink_height == size`） | 上游不给字号；量出来 20~27，与同一行名字的字号一致 |
| 颜色 / 底色 | 最亮 25% 墨迹的均值 / **框内分箱众数**（每通道 8 级） | 不能外扩取：绿标注线就在框外 6px（实测外扩会取到 RGB(17,243,22) 荧光绿）。也不能用精确色众数：视频底色是带噪声的，精确众数会被**刚写上去的实心字**抢走（`bg=(241,254,255)` ⇒ 整行判成 NO_INK） |

**跳过（不猜）的规则**——换错比不换贵得多：

| 判据 | 结论 | 语料实测 |
| --- | --- | --- |
| 框下游还有行带，且**行距 > 1.75em** 或 **开头有彩块**（段内平均饱和度 ≥ 45） | 框跨到了**下一条评论** | 4 张：2 张是真评论但框多圈了一行（`苏___-3/3` · `梦___◆8-2/1`），2 张是官方横幅行（`18-2/*`，同时也黑名单） |
| 框在冒号就结束（`text_box.x2` 顶到冒号右沿） | 正文只有表情、表情在框外 | 2 张（590 宽截图） |
| 框上方还有行带 / 认到 3 行以上 / 续行不在段落左沿 | 说不清，跳过 | 0 张 |

73 张的量测结果（`inputs_digest=c638deb474c2f267`）：

```
可换 65（单行 63 · 两行 2）
跳过 8：黑名单 4（官方横幅行；其中 2 张同时「框跨下一条评论」）
        · 框跨下一条评论 2（苏___-3/3 · 梦___◆8-2/1，真评论但框多圈了一行）
        · 纯表情 2（590 宽，框在冒号就结束）
正文宽 px  min 47 · p25 122 · 中位 147 · p75 171 · max 292   em 20~27（中位 24）
字数阶梯   2:4 · 4:1 · 5:15 · 6:18 · 7:17 · 8:2 · 9:5 · 11:1 · 12:1 · 13:1
```

⚠️ 字数是**按宽度 ÷ em 四舍五入**的估计，不是真字数：标点只有半个字宽
（`远___◆19-2/2` 的「大电池长续航，这个价」是 10 个字、量出来 9.4 → 9），
em 差 1px 也会换一个桶。所以它只是**给 NLP 下订单的桶**，最后仍按**像素宽度**挑句子。

两份产物：

| 文件 | 内容 | 能不能进交付包 / git |
| --- | --- | --- |
| `data/body_measure.json` | 逐张：每行上下左右、em、颜色、擦除矩形、行带证据（含 `reason`） | ❌ **`rel` 是语料目录名（= 用户昵称）**，与 `measure_cache.json` 同口径（`.gitignore` 已挡） |
| `data/bodies_need.json` | 聚合：字数阶梯、行数 / 宽度 / em 分布、两行行的字宽对、`per_bucket` / `model` / `prompt_version` | ✅ 纯聚合，不含昵称；可 diff（同输入跑两遍**字节相同**） |

量测**只读**：脚本里没有对语料的写操作，跑完打印 `inputs_digest`（geom + 每张图的字节），
两次跑一致就说明语料没被动过。

### 正文替换：`gen_bodies.py` + `core/batch_body.py` → `out/body_run/`（2026-10-28）

量完之后是**换**。三段，各有一段自己的「为什么」：

```bash
python3 mock/gen_bodies.py                                        # 句子库：bodies.jsonl
python3 core/batch_body.py --source <语料根> --out out/body_run     # 替换 + 过闸
python3 core/batch_body.py --source <语料根> --out /tmp/t --dry-run # 只挑句子、不落盘
```

`gen_bodies.py` 读 `mock/data/bodies_need.json`（量测产物），**只追加**进
`mock/data/bodies.jsonl`；`--remote` 走 OpenAI 兼容接口（`NLP_API_KEY`），没 key 自动降级到本地池。
`core/batch_body.py` 的完整参数（都能写进 `core/batch_body.config.json`）：

| 参数 | 作用 |
| --- | --- |
| `--source` | **必填**，语料根；几何按与量测相同的优先级自动找（`--geom` > `<source>/geom.json` > 交付树 manifest 重建） |
| `--geom` | 上游几何 JSON；不给就自动找 |
| `--bodies` | 句子库；默认 `mock/data/bodies.jsonl` |
| `--out` | **必填**，预演树写到哪；建议 `out/body_run` |
| `--platform` | 黑名单生效的平台键，默认 `generic` |
| `--limit N` | 只跑前 N 张（按相对路径排序） |
| `--max-reuse N` | 同一句最多用几次（默认 3） |
| `--format png` / `--format source` | 预演树格式；`png`（默认）= 无损可复核，`source` = 跟源后缀（JPEG 会把边缘重编码） |
| `--blacklist` / `--no-blacklist` | 是否套用 `source_blacklist.json`（默认开；官方横幅行不换） |
| `--dry-run` | 只挑句子，不写图、不写报告 |
| `--yes` | 允许 `--out` 指进语料目录（= 就地覆写；默认拒绝） |

⚠️ `--out` 指到语料目录里面会被拒（除非 `--yes`）：验证永远写在另一棵树。

**① 句子：按「字数阶梯」下单，按「像素宽」挑。** 阶梯来自 `bodies_need.json`（5 字 15 行、
6 字 18 行、7 字 17 行），但最后挑哪一句只看**墨迹宽度**。字宽按字形走（一个字 20–27px），
所以 `data/pool_positive.jsonl` 的 101 条手写在 `gen_bodies.py` 里再派生 **191 条句末标点变体**
（`真香` → `真香！` / `真香。`）—— 一个标点半宽，正好补上「5 字 = 130px、6 字 = 156px」中间那个
26px 的空洞（语料里 6 行正好落在洞里）。`--remote` 走 OpenAI 兼容接口（`NLP_API_KEY`），
本机没 key ⇒ 走本地池，`bodies.jsonl` 里的 `model` 会写 `local-pool`。

**② 替换的判据四条**（`core/replace_body.plan_body`）：行数相等 · 每行不越界 ·
第一行顶满（≥ 可用宽 − 0.6em）· 右缘对齐（|Δ| ≤ 0.5em，且不越过框右沿 2px）。
两行的那 2 条更严：**续行也要顶到原尾巴的宽度**，不然会写出「9 个字 + 1 个字」的排版。

**③ 八道闸**（`core/batch_body.verify`，**拿同一把尺子**在成品图上重量一遍）：

| 闸 | 判据 |
| --- | --- |
| `REMEASURE` | 成品图能量回原来的几何（量不回来 = 写坏了） |
| `LINE_COUNT` | 行数不变 |
| `RIGHT_EDGE` | 每行右缘 \|Δ\| ≤ max(3px, 0.5em) + 2px（噪声） |
| `BOX_MARGIN` | 新右缘 ≤ 上游框右沿 − 2px |
| `FIRST_LINE_FILL` | 第一行 ≥ 可用宽 − 0.6em |
| `COLON` | **墨迹冒号**那几列一个像素都不许变（不是上游 `colon_box` —— 590 宽那批它偏 17px） |
| `OUTSIDE` | 擦除矩形外一个像素都不许变 |
| `RESIDUAL` | 擦完、写字**之前**，矩形里残余墨迹 = 0 |

⚠️ 预演树默认写 **PNG**（`--format png`）：按源文件后缀存 JPEG 会把边缘重编码一遍，
同一张图内存里右缘 146px、存盘再量 145px —— 报告里的数就没法从盘上复核了。

73 张的实测（`out/body_run/report.json`）：

```
替换 65 / 65 条可换（67 行，含 2 条两行）· 八道闸 0 失败
不换 8：黑名单 4（官方横幅）· 纯表情 2 · 框跨下一条评论 2
右缘 |Δ|  中位 3px · 平均 3.09px · 最大 13px（0.5 字）· 11 行完全为零
残余 0px · 矩形外改动 0px · 冒号 0 改动 · 语料指纹 c638deb474c2f267 不变
句子    65 条正文用了 31 句（库 292 句，同句上限 3 次）
```

**已知短板**（写在这里，别等上线才发现）：65 行里 50 行是 5–7 字，而手写的这个长度只有 10–11 条
（靠句末标点变体才凑到 30–32 条），65 条正文最终只用了 31 句 —— 复用率是全批最容易被
一眼看穿的地方；新字是重新栅格化的，边缘比视频压缩过的原字实一档（行高 64/67 行完全一致、
3 行差 1–2px，与字号无关）。

逐张的对照图、判据表、直方图在 [`../docs/mock正文验收.html`](../docs/mock正文验收.html)。

### 批量跑真语料（自动检测框，三档长度探针，0 成本）

```bash
python3 core/batch_run.py /home/puyu/work/data/抖音奇瑞汽车/all_users_正面_3张以上
python3 core/batch_run.py <语料根> --limit 30          # 先小步试
python3 core/batch_run.py <语料根> --users '爱国者-*'   # 只跑锚点自检那一组
python3 core/batch_run.py <语料根> --limit 20 --dump all   # 裁剪摞图（只看名字那一段）
python3 core/batch_run.py <语料根> --limit 20 --dump full  # 每档一整图 + 一条裁剪条
python3 core/batch_run.py <语料根> --dump failures     # 只存有失败判据的图
```

⚠️ **`--limit N` 取的是任务表的「前 N 条」，不是随机样本**（按用户目录名排序）——
目录名恰好排在前面、又正好是「纯英文昵称」或「定位失败重灾区」的那几个用户，会把小样本的
比率带得极偏。实测：`--limit 20` 的前 4 个目录是 `@余生都是你-4` / `A携酒话清风D疗-5` /
`A淘气⇒-3` / `Czy-12`，其中 `Czy-12` 一个目录（昵称 `Czy`，**纯 ASCII**）就贡献 8 张跳过 ⇒
那 20 张里 8~12 张跳过（取决于当时的跳过规格），而**全量 650 张只有 88 张跳过（13.5%）**。
小样本试跑完先看一眼 `rows.csv` 的目录分布再下结论。同一条 `--limit` 还会**静默截掉锚点自检**
（`爱国者-9` 在排序里排第 72 位，取不到就整组不跑，只在末尾 WARNING 一句）。

`--dump all` 落**一张四行摞图**（**原图 + 短 + 等长 + 超长**，左侧标出探针名和实际写进去的
名字，`✂N` = 截掉 N 个字）：`dump/<用户>/<序号>_probes.png`，**框外的界面被裁掉**，
只看名字那一段，字形细节看得最清。

`--dump full` 落**每档两张 + 一张基准条**（2026-09-29 按反馈重做过，见下）：

| 文件 | 是什么 |
| --- | --- |
| `dump/<用户>/<序号>_full_<档>.png` | **整张截图，尺寸与原图一致**，只有绿框内被换掉 |
| `dump/<用户>/<序号>_<档>.png` | 该档的**裁剪条**（框 + 留白），看 5px 间距这种细节 |
| `dump/<用户>/<序号>_orig.png` | **原图基准条**（同一个裁剪窗），比对用 |

- **替换只发生在绿框内**。`_full_<档>.png` 就是管线自己的结果图，不是「把一块面板贴回去」
  —— 框外逐像素等于原图，`rows.csv` 的 `outside_changed` 逐行量出来的是 0。
  探针**没出图**（定位失败）时**不落整图，但落裁剪条**：原图那一条加红框写上失败标记，
  否则「这一档没跑」和「跑了但失败」在目录里长得一模一样。
- **一档一张**，不再把四档摞成一张贴回原图：那种形态的代价是那个评论区根本不是任何一张
  真实截图的样子，而且面板带着留白，会把上下的邻居评论和左侧等级徽章一起盖住。
- 检测不到框的图没有裁剪窗，`full` 下不落图（看 `rows.csv` 的 `NO_BOX`）。

⚠️ 三档各存一个**裁剪**文件是看不了的 —— 得来回切图，而且三张内容对不齐
（名字越短、尾巴平移越多），所以 `all` 才要摞成一张。默认 `none` 不存图：
650 张 × 3 个探针 ≈ 1950 张 PNG，几个 GB 的纯浪费；`full` 落整张尺寸的 PNG，
约 2.9 MB/张 × 3 档 ≈ 8.7 MB/张原图 ⇒ 650 张全量约 5.7 GB，配 `--limit` 跑。

## 「跳过」：不是失败，**不计入任何数量**（2026-09-30 规格）

规格原话：「**含有表情也跳过，跳过的不记入数量，跳过的要记绝对路径**」。两类图擦出来必然
不合格 —— 昵称整段是 ASCII 时，「保持总长不变」这条规格完全没有意义；原图名字里有 emoji
时新写的是**纯文字**，那一枚 emoji 的位置要么空着、要么被随机补的字盖住。

| 跳过理由 | 判据 | 判在哪一步 | 怎么判出来的 |
| --- | --- | --- | --- |
| `SKIP_PURE_EN` | 昵称串**只有 ASCII** | **读图之前** | 目录名 / `交付清单.txt` 里的昵称（`str.isascii()`） |
| `SKIP_EMOJI` | **原图**用户名段里有 emoji | **定位之后** | 图上像素：名字段的核心色彩度（标定见 §6） |

- **emoji 必须从图里判**，不能看目录名：目录名会把 emoji 转写或直接丢掉
  （`A淘气⇒` 真身是 `🦄淘气💨`；`A携酒话清风D疗` 的 emoji 一个都没留）。判据也**只判
  用户名段** —— 徽章、冒号、正文里的彩色像素不算。
- **不计入任何数量**：不进 `failures`、不进 `failure_counts`、不进 `by_probe` 的分母，
  **也不进报告里那行「处理了几张」** —— `summary.json` 的 `run.images` / `images_processed`
  是**处理数**，`images_scanned` 才是扫到的总数。跳过数只在自己的块里出现，不参与任何比率。
- **跳过的要留绝对路径**：`rows.csv` 的 `path` 列（每一行都有）是 `Path.resolve()` 的
  绝对路径；另落一份 **`skipped.txt`**，一行一个「绝对路径 + 跳过理由」（本批 88 行）。
- 命中就**不擦不画、不落任何图**：没有 `_full_<档>`、没有 `_orig`、也不落失败条
  （`--dump` 任何档都一样）。
- **不算失败**：`rows.csv` 各记一行（`probe="-"`，`skip` / `skip_note` 两列写明理由），
  `summary.json` 单出 `skipped` 块。

判据的实测标定（650 张语料）在 [`../docs/技术说明.md`](../docs/技术说明.md) §6「跳过」。
锚点自检那一组（`爱国者-9`）既不是纯英文也不含 emoji，8 张照旧全绿。

### 名单 JSON 的格式

**顶层**：一个对象（推荐），或者直接一个数组 / 一个「名字 → 张数」映射。

```jsonc
// ① 对象（推荐 —— 顺带写素材目录 / 输出目录 / 平台 / 默认张数）
{"source": "data", "out": "out/", "platform": "douyin", "default_count": 3,
 "users": [{"name": "张三", "count": 3}, "李四"]}

// ② 裸数组 —— 素材与输出走命令行
["张三", "李四"]

// ③ 裸映射 —— 名字 → 张数，素材与输出走命令行
{"张三": 2, "李四": 5}
```

⚠️ JSON 不支持注释（上面 `//` 只为讲解，真文件里不能有）。

**顶层字段**（键名大小写不敏感；`/` 分隔的是等价别名，写哪个都认）：

| 字段 | 别名 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `users` | `names` / `targets` / `list` / `用户` / `名单` / `生产用户` | 数组或对象 | ②③ 形态可省 | — | 用户条目列表（见下）；也可直接写成「名字 → 张数」映射 |
| `default_count` | `each` / `每张` / `默认张数` | 整数 ≥ 1 | 否 | `3` | 条目里没写张数时用它 |
| `source` | `素材` / `语料` / `root` | 字符串 | 否（可用 `--source`） | — | 素材根目录：`<根>/<昵称-张数>/<n>.jpg` 或**平铺**目录都认 |
| `out` | `output` / `输出` | 字符串 | 否 | `outputs/produce_<时间戳>/` | 输出根目录 |
| `platform` | `平台` | 字符串 | 否 | 名单里的优先，其次按素材路径判 | `douyin` / `视频号` / `微博`（别名表见 `core/platforms.py`） |

名单里的 `source` / `out` 是**相对路径**时，按**名单文件所在目录**解析 —— 名单和素材常常一起搬。

**用户条目**：三种写法，可以在同一个 `users` 里混用。

| 写法 | 例子 |
| --- | --- |
| 字符串 | `"张三"` |
| 对象（推荐） | `{"name": "张三", "count": 3}` |
| 单键映射 | `{"张三": 3}` 或 `{"张三": {"count": 3}}` |

| 字段 | 别名 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `name` | `nickname` / `nick_name` / `nickName` / `user_name` / `userName` / `username` / `昵称` / `用户名` / `名字` | 字符串 | **是**（单键映射形态下由键名充当） | — | 要写到图上的用户名 |
| `count` | `n` / `num` / `images` / `张数` / `数量` | 整数 ≥ 1 | 否 | `default_count` | 这个名出几张 |

解析的原则是「**宽容输入、严格报错**」：能认的写法都认，认不出就**报错退出（码 2）**、
消息里带出错的那一项 —— 不静默降级。

| 情况 | 结果 |
| --- | --- |
| 同一个名字出现多次 | **合并张数**（日志里说一声） |
| 名字里含 `/` | 换成 `_`（目录名不能带），日志里说一声 |
| 名字为空 / 张数 ≤ 0 / 张数不是整数 / 张数是布尔值 | **报错退出 2** |
| 条目里认不出名字字段（例如漏了名字的 `{"张数": 2}`） | **报错退出 2**（不会产出一个叫「张数」的用户） |
| 名字去掉 emoji 后为空（例如 `"😀"`） | **报错退出 2**（规格要求新写的文本不含表情） |
| 名字含 emoji 但还剩文字（例如 `🦄淘气💨`） | 照常出片，**图上写的是剔掉 emoji 后的「淘气」**，日志里说清 |
| 文件不是合法 JSON / 读不了 | **报错退出 2** |

**从 Java mock 池直接导出**也能喂进来（`GET /open/mock/users` 返回的是 `{avatar, nickname}`）：
`nickname` 就是 `name` 的别名，`count` 由 `default_count` 兜底，`avatar` 这类**不认识的键被忽略**：

```json
[{"avatar": "https://…/a.png", "nickname": "张三"},
 {"avatar": "https://…/b.png", "nickname": "李四"}]
```

⚠️ 若手上是接口的**原始响应**（外面裹着 `{"code": 0, "data": [...]}` 之类的外壳），
要把里面那个用户数组取出来再存 —— 那种外壳既不是数组、也没有 `users` 包裹键，
会被当成「名字 → 张数」映射去解析，然后因为在它的值上凑不出合法张数而**报错退出 2**
（实测 `{"code": 0, …}` 报「名单项「code」的张数必须 ≥ 1，收到 0」，消息里带出错的那一项）。

**命令行覆盖名单**（名单里写了也能被命令行压掉）：

| 命令行 | 效果 |
| --- | --- |
| `--source` / `--out` | 压过名单的 `source` / `out` |
| `--platform X` | 压过名单的 `platform`；默认 `auto` = 名单里的平台 > 按素材路径判 |
| `--limit N` | 只跑名单里的**前 N 个用户**（不是前 N 张图） |
| `--format` / `--quality` / `--fit` / `--min-font-ratio` / `--seed` / `--workers` | 名单里没有对应字段，只能在命令行给 |

**产出**（`<out>` 默认 `outputs/produce_<时间戳>/`）：

```
<out>/<名字>-<实际张数>/1.jpg 2.jpg …     ← 交付语料那套目录形态，可直接进现有交付/消费流程
<out>/manifest.json                      ← 逐张：名字 / 源图 / 标注框 / 度量值 / md5
<out>/summary.json                       ← 逐人 requested·produced·shortfall + 素材拒绝原因 + 复用统计
```

目录名取**实际**产出的张数（`<名字>-<张数>` 是从右边切第一个 `-` 解析的，写虚了就跟
`batch_run.collect_images` 对不上）；撞名时后缀加在**张数左边**（`张三_2-3`，不是 `张三-3_2`）。
**产不够 ⇒ 退出码 3**（0 = 全产够，2 = 名单或素材读不了），缺口逐人写在 `targets[].shortfall`。

### 名单从哪来：`mock/make_spec.py` 生成（也可以手写）

只给三样 —— **数据路径** · **要几个名字** · **每个名字出几张** —— 名字由脚本生成：

```bash
python3 mock/make_spec.py --source /home/puyu/work/data/抖音奇瑞汽车/all_users_正面_3张以上 \
                             --users 20 --per-user 3
# → names_douyin_20人x3张.json，并打印下一步该跑什么
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--source` | **必填** | 数据路径（素材根目录）。**平台从它里面认** |
| `--users` | **必填** | 生成几个名字 |
| `--per-user` | `3` | 每个名字出几张（写进 JSON 的 `default_count`） |
| `--min-len` / `--max-len` | `2` / `5` | 名字字数区间（支持 2~6） |
| `--out` | `names_<平台>_<N>人x<K>张.json` | JSON 写到哪 |
| `--seed` | `20260930` | 随机种子（同一份名单可复现） |
| `--fit-corpus` | 关 | 先量 48 张素材，只留「放得下」的名字（见下） |
| `--dry-run` | 关 | 只打印平台与名字，不写文件 |

**平台是从路径里认的**，与批量脚本用**同一张别名表**（`platforms.detect_platform_from_path`，
含在复合目录名里也认）：

| 数据路径 | 认出来的平台 |
| --- | --- |
| `…/抖音奇瑞汽车/all_users_正面_3张以上` | `douyin`（命中路径段「抖音奇瑞汽车」） |
| `…/11-…抖音CTCC（8.8）/快手/all_users_正面_3张以上` | `kuaishou_app`（最近的「快手」先命中，不会被活动名里的「抖音」抢走） |
| `…/2-2026-06-17艾瑞泽8征服版上市/微博/all_users_正面_3张以上` | `weibo`（命中「微博」） |
| `mock_scale/data`（认不出） | **不写 `platform` 字段** + 控制台提示怎么手写（`抖音 / 视频号 / 快手 / 微博`） |

**名字是现生成的通用词组合**（前缀 × 名词 × 后缀，如 `猫不哭` / `柚子爱睡觉` /`大兔子不太冷`），
生成后**逐字校验**（只接受 CJK 统一汉字）、**去重**再乱序。⚠️ 词池是通用词，
**刻意不从语料里抄真昵称** —— 语料里那些名字属于真实用户，不该被拿去做合成身份。

**长度默认 2~5 字是量出来的，不是拍的**（`--fit-corpus` 量的就是这件事）：

| 量过的 37 张可用素材 | 结果 |
| --- | --- |
| 槽位按原字号能容下的字数（中位） | **3.1 字**（最小 0.9 / 最大 10.7） |
| 容得下 ≥3 字 / ≥4 字 / ≥5 字 | 22/37 · 13/37 · 6/37 |
| 加上「缩到原字号 60% 以内仍合格」这条判据 | 硬上限 ≈ `3.1 / 0.6` ⇒ **约 5 字** |

⇒ 6 字只是勉强（在 douyin 语料上 10 个里还能剩下 10 个放得下），更长的名字会**所有素材都报
`FONT_SMALL`、一张也出不来**（实测 9 字与 15 字名都是这个结局）。所以 `--max-len` 的硬上限
卡在 6。

`--fit-corpus` 打开后：先量 48 张素材（检测 + 定位，约 1.5s），只保留**至少能被一张素材按原字号
容下**的名字 —— 太长就一直重抽到凑够；实在凑不够就**如实报缺口**（退出码 3）并写下手头这批，
而不是假装凑齐。名字后面括号里的数字就是「量过的 N 张素材里有多少张不用缩字号就写得下」：

```
生成 5 个名字（2~5 字）· 每个 2 张 ⇒ 合计 10 张：
  大兔子(22张)  南南不吵(13张)  阿猫不哭(13张)  小风(33张)  阿鹿(33张)
```

**实测（生成 → 出片，一条龙）**：上面这 5 个名字 × 2 张 ⇒ `batch_produce` 出 **10 张**，
**10 张不同源图**、来自 **10 个不同原始用户**、md5 重复 **0**，字号全部保持原字号 28（没有缩字号）。

退出码：`0` = 名单写好（或 dry-run 通过）· `2` = 参数或路径不对 · `3` = `--fit-corpus` 下没凑够名字。

### 「尽量不重复」＝ 三条能读出数的规则

| 规则 | 报告里的字段 | 实测（抖音语料，5 人 × 3） |
| --- | --- | --- |
| 一张源图只出一个成品 | `reuse.max_source_reuse`（单张源图**最多被用了几次**，1 = 没有复用） | 15 张用了 **15 张不同源图** |
| 同一个人的几张**叉开原始用户** | —（选材打分里的 `DIVERSITY_WEIGHT`） | 15 张来自 **15 个不同原始用户** |
| 成品按 md5 自检 | `reuse.duplicate_files` | **0** |

第 2 条是选材打分的惩罚项：素材按「源**目录**已用过几次」加代价（0.20/次），挑完立刻把它的
目录计数 +1 —— 同一个原始用户目录下的帧是同一台手机、同一个头像、同一段视频，肉眼一看就是
「同一张片子的不同滚动位置」。第 3 条几乎永远不会非零（源图不同 ⇒ 字节不同），它的价值是把
「不重复」从形容词变成**可以在产物上复量的断言**。

### 选材：先量一遍，再按「名字放不放得下」挑

```bash
python3 core/batch_produce.py 名单.json --dry-run    # 只量 + 只配对，打印「谁配哪张」，不出片
```

1. **测量阶段**只做**检测 + 定位**（不擦不画）—— 量出来的是**与名字无关**的几何量
   （槽位宽度 / 字高 / 有没有 emoji），量一次全组合可用；选不中的素材不该为它擦一遍图。
   素材侧的跳过规格照旧生效（`SKIP_PURE_EN` 判目录名、`SKIP_EMOJI` 判像素）。
2. **选材打分** = 名字自然宽度与槽位宽度的偏离（**宽了比窄了更糟**：宽了要缩字号，
   2.0 vs 0.6 两个权重）+ 目录多样性 + 一点种子抖动打散并列最优。
   **长名字先挑**（能容下长名字的素材最少），一个名字的几张挑完立刻更新目录计数。
3. **出片**走 `process_image`，标注框**由测量阶段随任务带过来**（检测是最贵的一步，不重跑）。

### 三处与 `batch_run` 不同的口径（**2026-09-30 用户定的规格 + 本次字号修复**）

| 口径 | `batch_run`（验证） | `batch_produce`（生产） | 为什么 |
| --- | --- | --- | --- |
| 名字放不下 | `fit=clip` 砍字 / `--fit width` 缩字号 | **`fit=clip` 砍字，字号不缩** | 缩字号会让**同一个名字在不同素材上大小不一**（实测同一名字走过 27/28/32 三种字号）—— 那正是要避免的观感 |
| 名字比槽位窄 | 随机补字补满槽位（默认含 ASCII） | **补满，但只补中文**（`fill_ascii_weight=0`） | 不够长就补到原槽位宽 ⇒ 总长不变、右边评论不动；名单是中文名，后面跟一串随机 ASCII 会很跳 |
| 名字被改动过（截断/补字） | 不做区分 | **单独进 `_名字有改动/`** | 图上显示的名字与名单不完全一致，不能跟「名字原样」的混在一起；`targets[].produced` 只数**名字原样**的那些 |
| 产物格式 | png（无损） | 默认 **jpg q95** | 交付语料是真图（jpg）。⚠️ 实测**框外最大像素差 18**；要「框外逐像素不变」用 `--format png`（实测 **0**） |

### 字号：默认钉死「语料的文字高度」（`--font-size auto`）

**问题**：字号是按**名字槽位量出来的字高**定的，而槽位里除了文字还可能有**比文字高的非文字元素**。
实测 `00口谋財0口渡凡尘-4/3.jpg`：名字里 💕 高 **35**、3️⃣ 高 **31**，而同一行的汉字只有 26~28、
同行**正文 27** ⇒ 字高量成 35 ⇒ 新名字比原文字大一圈（用户报的就是这一张）。反向的也有：
量成 8 / 17 ⇒ 名字小得看不清。**这一类图占 3~4%**。

**解法**：文字高度在同一个语料里是**恒定**的 —— 量 99 张视频号 / 118 张抖音，字高**众数都是 28**
（占 56% / 82%）。所以默认 `--font-size auto`：第一批素材量完就取**字高众数**，把字号**钉死**给整批用。

| `--font-size` | 行为 |
| --- | --- |
| `auto`（默认） | 取量过的素材的**字高众数**钉死一个字号（众数躲开被非文字撑大的少数张，又让同一个名字跨素材大小一致） |
| 整数（如 `28`） | 直接钉死这个字号 |
| `off` | 每张素材各量各的（旧行为） |

**实测**（视频号 3 人 × 6 张，18 张）：`auto` ⇒ **18 张全是 28 号**（每个名字一个字号）；
`off` ⇒ 字号散成 **27/28/32**，其中「夜航船」一个名字就用了**两种大小**。报出的这张图：
字号 35 → **28**，与同行的正文（27）和邻居名字（28）齐平。

⚠️ 改动是**加参数、不动默认以外的路径**：不传 `--font-size` 时的渲染结果与改动前**逐字节相同**
（同一张图 `font_size=None` 与 `font_size=<该图自然字号>` 的 PNG md5 一致）。
`core/batch_run.py` 一个字没改 ⇒ 650 张的定位/合规基线不受影响。

### 等级标：连名字一起擦掉（`--erase-badge`，**批量默认开**）

**规格（2026-10-11 用户）**：mock 用户的图上**不留真用户的痕迹** —— 昵称左边那个等级药丸
（抖音 `◆12` / 视频号 `✦14`）**连着名字一起没**，假名字从 **胶囊头 + `CAPSULE_HEAD_NAME_PAD`
（24px，固定值）**起写，冒号与正文跟着左移。

⚠️ **「胶囊头」＝药丸左边那截半透明的圆头**（用户 2026-10-11：「得保留背景的胶囊头还得计算
胶囊头距离用户名的距离变成固定值」）。等级药丸**不是**一个实心矩形：左边是**半透明的胶囊
圆头**（含药丸的柔和投影），右边才是实心药丸体。只擦实心体 ⇒ 圆头留在新名字左边成一块脏底；
把圆头也算进填平区 ⇒ 那块背景被抹掉（用户第一次报的「胶囊头没有了」就是这个，bug-325）。
现在的口径：**圆头保留（一个像素都不填）**，新名字**从圆头右缘起、固定隔 24px** 写下去 ——
量到圆头才有这待遇（`metrics.capsule_head` 非 `null`），量不到就退回老规矩（见下表脚注）。

| 入口 | 默认 | 关掉 |
| --- | --- | --- |
| `core/batch_produce.py`（出片） | **开** | `--no-erase-badge` |
| `core/batch_run.py`（验收外壳） | **开**（**必须与成品线同口径**，否则绿的是没人交付的那条管线） | `--no-erase-badge` |
| `core/replace_username.py`（单张） | 关（显式开关） | 默认就是关 |
| `expand/expand_produce.py`（扩展线） | —— **不传这个参数，行为一个字节不变** | 见下 |

⚠️ **扩展线对等级标的口径相反，是设计**：那条线的标**一律来自目标用户自己**（用户 2026-10-10
「还是用以前的办法，但等级标得一致」），自图里找不到就不出片。两条线**别互相抄**。

三个数必须分开看（混成一个就会出错）：

| 数 | 语义 |
| --- | --- |
| **原槽位** `slot_width` | 原名字自己占的宽度 —— 「补满」仍按它算（名字短就补字到原槽位宽） |
| **装配基准 / 写名字的起点** | **胶囊头 + `CAPSULE_HEAD_NAME_PAD`（24px）**起、写到名字右缘 —— 位移按它算 ⇒ 名字↔冒号间距按构造成立。量不到胶囊头就退回**药丸左沿**起（老规矩，`metrics.capsule_head` 为 `null`） |
| **填平区** `badge_rect` | 要**整块铺平**的那块地（含药丸、含药丸的投影、含探出 ROI 内缩框的那 1~2 行） |

四处坑（都在 2026-10-11 修掉并记入 buglog）：

- **「名字左边还有段」≠「那段是药丸」**（bug-325，用户「胶囊头没有了」）。视频号这条定位
  是**从冒号往左走**、缝超过 `NAME_RUN_GAP_MAX=40` 就停，于是「名字左边还有段」有三种来路，
  只有第一种是药丸：① 走过一段实心宽块（= 药丸）；② **缝太大走不过去**，左边那段其实是
  **框左沿糊进来的 1px 描边残渣**；③ 更左边还有别的段。20:51 那批 1466 张里 **663 张（45%）**
  是第②种（宽度中位 **1px**、缝全部 > 40）。把它当药丸的代价有两处：新名字整条**从残渣那列
  起写**（名字+冒号+正文一起**左移 ~50px**）、以及把框左沿一块 16px 宽的地填平
  （那张图丢的就是「胶囊头」）。判据（`platforms.badge_left_of`，两条都要）：
  那段**像药丸**（`is_badge_like`：宽 ≥ `badge_min_width` 且填充率 ≥ `badge_fill_ratio`，
  与「跨过徽章」同一条尺子）**且**它**就在名字这一串里**（缝 ≤ 40）。
  **不误伤**：770 张真药丸填充率 min 0.628 / 中位 0.843 全过；663 张残渣全挡下。
- **药丸自带一圈 ~10px 的柔和投影**，它**暗于背景 14 级 < `BG_DIST_THRESH=45` ⇒ 不算墨迹**，
  蒙版/行范围/槽位都碰不到它。只擦药丸的话，投影会留在新名字左边成一条 **15 级的暗竖条**
  （药丸没了、影子还在）。所以填平区往两侧各多吃 `BADGE_SHADOW_PX=12` 列，
  并且**逐列检查那几行里有没有真墨迹**（药丸左边偶尔还有图标、右边就是名字），**遇到内容立刻停**。
- **那块地的底不是拿全框一个色平涂**：框内底色**沿 x 会跳**（拿报的那张图逐列量中位数：
  x≤1790 的左段 ≈ **40 级**、x≥1817 的右段 ≈ **50 级**，台阶就在 x≈1800），而**全框 mode 色
  按多数票取到 50** ⇒ 填在左段的带子上就是一块**亮 10 级**的板。改法：**从它旁边就地取背景**
  （逐行中位数，`LOCAL_FILL_SPAN_PX=16`，且夹在内缩框里）—— 这样连**穿过这块地的绿描边**也一并续上。
- **「胶囊头」得留着，且新名字离它必须是固定值**（Request F，用户「得保留背景的胶囊头还得计算
  胶囊头距离用户名的距离变成固定值」）。胶囊头 = 药丸左边那截半透明圆头，**不是实心体** ⇒
  ① 往左吃不能吃到它；② 新名字的起点不能等于药丸左沿（老规矩），否则**每个用户量出来的
  「头→名字」距离都不同**（语料实测 8~40px 不等）。改法：`inkmask._capsule_head` 从填平区
  左沿往左逐列找「**跟页面底色同色的连续列**」（`CAPSULE_HEAD_MIN_CONTRAST=4`），找到就是
  胶囊头右缘；`_badge_rect(..., head=…)` 把填平区左界**钳在 `head+1`**（一格不吃），
  填平也改成**只从右边取背景**（左边就是胶囊头，取样会把它涂花）；`EraseRegion.name_left`
  = `capsule_head + CAPSULE_HEAD_NAME_PAD`。全批复验（1466 张、与 20:51 那批逐张 md5）：
  改动的 **770 张全部** `name_left − capsule_head = 24`（**一个固定常数，无例外**），
  框外改动 >20 级 = **0 px**（max 17，jpg 噪声），源图/旧图/新图在胶囊头那几列的逐列中位数
  是 `43 43 43 42 40 35 32 32 30 30`（源）→ `43 43 43 43 42 42 42 42 40 40`（旧 = 抹平）
  → `43 43 43 42 40 35 32 32 31 31`（新 = 复原）。⚠️ **它是条件生效的**：药丸没被认出来
  （见下面的 bug-327）就没有胶囊头可量，`metrics.capsule_head` 为 `null`、退回药丸左沿起写。
- **重切会把槽位切短，名字少擦一个字**（bug-326，用户报 `包子爱睡觉-15/2.jpg`「有问题」：
  旧名「顺意」原样留在新名字右边）。`_resplit_on_band` 是 bug-183 为**两行框**写的兜底
  （第二行的墨把名字与冒号在列投影上并成一段），但它唯一的闸门「宽 ≤ 8 且 高 ∈ [0.4, 0.8]×行高」
  会被**本行名字自己的笔画**满足：视频号「顺」的**川字竖笔**正好 4×25px（0.757）⇒ 被当成冒号，
  槽位 1243-1426 被切到 1243-1370 ⇒ 「顺意」既不在蒙版里也不在尾巴平移范围里，整字留下。
  抖音拉丁昵称（`jlrfc…`）更狠 —— 每个字母都又窄又「不高不矮」，直接在字母中间下刀。
  守卫：新冒号右侧、原槽位右缘之内，**本行不许再有墨**（`ink & row_keep[:,None]`）—— 有墨就说明
  那不是冒号、是本行名字的下一截（真病征恰恰相反：冒号右边多出来的列是**别的行**的墨，本行是空的）
  ⇒ `return None`。实测：报的那张不再重切、抖音 bug-183 的招牌案例 `军陌-4/3` 照旧放行
  （它被切掉的 722-737 列只有第二行的墨）；9 行抖音假阳性 + 51 行视频号假阳性全部挡下。
  **静默错误**：硬校验全绿（`gap_now`/`outside_changed` 都按被切短的槽位量），只能看图发现。
  **怎么验的（值得抄）**：⚠️ **两批成品之间不能做逐路径 md5** —— 换素材的重试走**一条共享的
  随机流**，守卫让 2 张原本 `DIRTY`（残余墨迹 >5%）的图通过 ⇒ 流移位 ⇒ **几乎每个用户配到的
  素材都变了**（两批同 `(名字,素材)` 对只剩 442/1448）。改成**把配对钉死**：同一张源图、同一个
  新名字、同一个框，**只翻守卫这一个开关**（把修前的函数从源码里删掉守卫那一段 exec 回来）。
  结果：**9 个受影响的源全部复现**（`顺心-3/3` 槽位 1316-1342 → 1316-1370、`gap_now` 1 → 5；
  出图 修前「老石有点甜**心**：」→ 修后「老石有点甜：」），**30 个不受影响的源两版逐像素相同**。

⚠️ 这一步**故意动蒙版外**的像素，所以它自己带一条**同口径的硬校验**（改动只许落在声明的矩形里）：
`outside_changed` 于是仍是「**声明范围之外**零改动」，只是声明范围多了一块地
（说清楚参照物，见 [`../docs/技术说明.md`](../docs/技术说明.md)）。

⚠️ **已知边界：药丸跑到 ROI 框外就擦不到**（2026-10-11 量）。抖音语料的框**贴着名字起**，
有些图的等级药丸**整颗在框左沿之外**；管线的改动范围被约束在框内（D1 的诉求正是「别超框」），
所以这种图**产出仍带真用户的等级标**。实测（各 30 张产出）：**视频号 0 张**；
**抖音 5 张框内定不到药丸、其中 4 张（13%）药丸在框左沿外 1~89px 处**（例：
`向前走-3/3.jpg`，`◆3` 在框外 ⇒ 出图「◆3 夜航船：这个有没有装颗粒捕捉器?」）。
**要不要擦框外的药丸由用户定**（见 `.wolf/STATUS.md` 的 🚀 待办）：三条路 —— ① 认这个缺口；
② 允许这一次越框擦（与扩展线「徽章可越框 ≤26px」同类，但这里整颗在框外、量更大）；
③ 定位时**只看不擦**地往框左沿外扩一段找药丸，再按②擦。**未改**。

⚠️ **已知边界：有些药丸「太淡」，认不出来**（bug-327，2026-10-11 量，**未改·待决策**）。
药丸体亮度 ≈93、页面底色众数 53 ⇒ 差 **40 < `BG_DIST_THRESH=45`** ⇒ 药丸那片地**不算墨**，
那一段的墨占比只有 0.274 < `BADGE_FILL_RATIO=0.60` ⇒ `is_badge_like` 判否、`badge_span=None`。
后果三条：槽位从**药丸左沿**起算（真名字还在 80px 之外）、胶囊头那条逻辑**不生效**
（`capsule_head` 为 `null`）、药丸底色留在新名字后面成一块淡亮板。指纹好认：**胶囊头→名字
只 8~9px**（设计值 24）。影响面：256 个视频号源里 **5 个**（`8万事顺意-4/3`、`7生活百般滋味-4/1`、
`7余生&默走-6/2`、`亿。过往-6/1`、`大成2-8/6`）。候选改法：`is_badge_like` 补一条**亮度板**判据
（段内亮度显著高于页面底色众数、且形状是圆角矩形），或对药丸区域单独把 `BG_DIST_THRESH` 降到 ~35。
**要不要改由用户定**。

### 判据：过了就出片，不过就**换一张素材**（不是硬出片）

| 判据 | 含义 |
| --- | --- |
| `TRUNCATED` | 名字被砍了字（`fit=width` 下不该出现，兜底） |
| `OVERFLOW` | 缩到最小字号仍塞不下 |
| `BOX_BAD` / `GAP_BAD` / `TAIL_BAD` | 越框 / 名字↔冒号距离变了 / 尾块不是原像素 |
| `LEAK` / `DIRTY` | 蒙版外被改动 / 残余墨迹 > 5% |
| `SKIP_EMOJI` | 原图名字段里有 emoji（测量阶段就该拦掉，兜底） |
| `FONT_SMALL` | 成品字号 < 原字号 × `--min-font-ratio`（默认 0.6 —— 名字比槽位宽时 `fit=width` 会一路缩到 10px，那在截图上就是一条墨线） |

任一不过就**换一张素材重出**，最多 3 轮（`MAX_ROUNDS`）；仍不够的进 `shortfall`。
逐条原因计数在 `summary.json` 的 `rejected_after_render`（素材侧的拒绝在
`material.rejected_by_reason`）。

⚠️ **不拒片、只落数的一条**：「正文搬干净了没有」逐张记进 `manifest.json` 的
`metrics.tail_leftover_px`，并在 `summary.json` 的 `tail_move` 里汇总（张数 + 总像素），
非零时打 warning。它**不是**拒片判据 —— 拒片 = 换素材，加一条就会动供给
（见 `../expand/扩展张数.md` §25.6）。

| 确定性 | 同一名单 + 同一素材 + **同一份依赖代码**，8 次重跑 md5 全等 |

⚠️ **可复现性有个前提**：上面那句「同一份依赖代码」是真条件 —— 本仓库是多会话共享的工作树，
`core/inkmask.py` 在 2026-09-30 被另一个会话改过两次（14:20 / 14:56），改完之后同一份名单的产物
就与改之前不同。报「同输入同输出」时要说清**对哪一份依赖版本**。

### 几个口径上的坑

- **`--dry-run` 走的是另一条分支**（不落盘），所以它照得出「只在落盘分支才被填的容器」这类错
  —— 这个脚本的第一版就是拿 `rows`（落盘后才有）当产出计数源，于是**一次完全正常的预演
  报「全都没产够」**。
- **名单映射的「值」就是张数**，别把 `{"张三": 3}` 读成「用户名叫张三、张数取默认」——
  默认值恰好等于映射值时，错的实现和正确的实现输出**一模一样**。
- **进程池的结果要按入参下标回填**，不能用 `as_completed` 的完成顺序：那个顺序会一路传到
  选材（并列时按遍历顺序取种子抖动）、落盘顺序、`manifest.json` 的行序。
- **素材池 < 需求量时只会复用并如实上报**（`reuse.max_source_reuse`），不报错 ——
  要不要「池子不够就失败」由使用方定。
