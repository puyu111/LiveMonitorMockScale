mock_scale · 上游字段实测 · sample-73

text_box 和 colon_box 到底能替掉哪几步

7 个片段、73 张截图、309 条评论行。结论先说：整行文字的位置和范围上游都给全了——名字从哪到哪、正文从哪起、到哪结束，误差 5px 以内。只剩药丸的右沿和字号颜色要自己量。

04

表情：上游也给了框

comments.jsonl 里 emojis[] 每条都是 {box, n, score, name, id} —— 有坐标，不只是名字。309 行里 67 行含表情（22%），其中 43 行是纯表情（content 为空）、24 行是文字 + 表情。

情况行数怎么取正文右缘
表情整个在 text_box 内38 / 67直接 text_box.x1 够用
表情越过 text_box.x129 / 67max(text_box.x1, max(emoji.box.x1))，最多多出 258px
纯表情行（content 空）43整段都是表情：没有可位移的文字，名字放不下就截，不要动表情

也就是说，「正文右缘」的规则是 max(text_box.x1, 所有 emoji.box.x1)，两种上游信息合起来才完整——只看 text_box 会把表情切掉，只看像素会把旁边的视频画面也算进来。

05

三个例外，两条边界

  • 3 行的 text_box 切进了冒号（正文宽为负）：seg2/30 −25px、seg4/1 −2px、seg7/6 −1px。同一批也是「冒号跑出框外」的那 3 行。比例 3/238，用 colon_box.x1 兜住即可。
  • 27 行的 text_box 跨两行：高度中位 31px（= 行高），但有 27 行 >60px、最高 150px。这种框当「行带」用之前要夹回 roi 的上下沿，否则会连下一行一起采样。
  • 71 行没有 colon_box：这是唯一必须保留旧逻辑的地方。
06

结论：换掉哪几步，还剩什么

管线里的一步现在怎么做能不能用上游
行带（背景估计 + 改动的上下沿）像素找行 / 整个 box用 text_box.y
名字段（左右沿）saturation_run用 colon_box.x0
正文起点colon_anchor用 colon_box.x1
正文右沿（尾巴位移终点）column_segments 扫全宽用 max(text_box.x1, emoji.x1)（±5px）
药丸范围_badge_rect只剩这一步要量（48% 有框）
字号 / 名字颜色墨迹统计仍需像素
head  = (tb.x0, tb.y0, tb.x1, tb.y1)          # 整行的采样与改动范围
name  = (x_text, cb.x0)                       # 名字槽位：起点 → 冒号左沿
body  = (cb.x1, max(tb.x1, *emoji_x1))        # 正文：冒号右沿 → 文字框 / 表情框右沿
pill  = (badge_left, tb.x0) if badge_box else measure()
# 兜底：cb 缺失（23%）或 tb.x1 < cb.x1（3/238）→ 走旧逻辑

这份实测直接改写了 白底误判修复方案 里的 C 方案：原来只借上游的上下沿，现在列范围也整段借——「正文右缘要自己量」这条不成立了。

07

补记：colon_box 的两点不总落在冒号上

73 张里有 2 张，colon_box 落在正文第一个字上：四___◆3-5/5 框住「空」（152–170），梦___◆8-2/2 框住「外」（153–171）；真正的冒号在 135–138，宽 8px，比框左移了 17px。

直接拿 [x_text, cb.x0) 当名字槽，会把真冒号一起擦掉，成品变成「小风空间真的大」。所以落点改成：先在同一行里找「窄（≤6px）且墨迹分上下两截」的列段，再取右缘最靠近 cb.x1 的那个；一个都找不到，才退回「与框重叠、右缘最近」的老规则。

结论不变，用法要改。colon_box 仍然是「名字到哪结束」的最准依据，但它给的是附近的冒号，不是冒号本身的像素；拿它当锚点找冒号段，别直接读它的 x0 / x1。

73 张逐个量过：没有冒号被吞进名字槽，也没有 8px 以上的冒号段被误判。两支对照跑的完整结果见 行带改用上游框 的 06。
