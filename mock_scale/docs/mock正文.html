mock 正文

名字之后，下一步换掉评论正文。两条流水：远端 NLP 按「字数阶梯」生成正向评论，上游几何量出原正文的宽、行、字号、颜色，按像素宽度挑一条写回去。73 张里 65 张可换，下面每个数字都是量出来的。

02

量：上游能给什么，不能给什么

能用的

  • colon_box 定正文左界（冒号右沿 + 1 起量第一列墨迹）。badge_box / emojis[] 用来识别该跳过的行。
  • 正文右缘：正文自己量出来的最右墨迹列。不要用 text_box.x2 —— 它紧贴文字，比墨迹宽 1–7px（34 行恰好 4px），拿它当右缘会让新文字顶到绿框上。
  • 字号：等于这一行名字的字号（实测同一行 25/24、26/26、23/23）。所以正文不新立字号来源，直接用名字那一路的 em。

不能用的

  • x_text 不是正文起点：苏***那一行 x_text=106，而冒号是 102–111 —— 它指向名字/冒号，不是正文。
  • text_box 不是「这一行的正文」：4 张图里它跨到了下一行评论（框高 76–84px），第一行甚至可能是官方横幅。这类行只能跳过，不能猜。
  • 行数：71 行有正文 —— 67 行单行、4 行两行（2 条真评论折行，行距 31/36/38/38px；另 2 张是官方横幅自己折了行）。别按框高除行高去推，按墨迹行游程数。

正文墨迹宽度：最小 47px、p25 122、中位 147、p75 171、最大 292px；右缘离上游框右边 1–6px（30 行恰好 4px）。

03

生成：先把「多长」定下来，再让 NLP 写

正文不是随便「长短不一」就能贴上的：绿框紧贴原文，写短了框内留一块空白，写长了顶到框上。所以生成的第一步是把语料换算成字数阶梯 —— 每行的正文宽度 ÷ 字号，就是这一行需要几个字。

65 行可换正文的「需要几个字」（宽度 ÷ 字号，四舍五入；4 张跨行、2 张纯表情不参与下单）。5–7 字占了 50/65 行，超过一半 —— 这个语料的评论本来就很短，句池必须短句密集。这组数是 mock/measure_bodies.py 量出来的，同目录 mock/data/bodies_need.json 可 diff。

NLP 侧按这个阶梯下订单：每个桶要 K 条，逐条约束「恰好 n 个字、正向、口语、不含 emoji / 链接 / @ / 价格与数字 / 品牌型号」，避免新造事实。字形宽度不等于字数（标点只有半个字宽），所以最后仍然按像素宽度挑，字数只是提高命中率。

# mock/bodies_need.json（mock/measure_bodies.py 产出；同输入重跑字节相同，可 diff）
{"ladder": {"2": 4, "4": 1, "5": 15, "6": 18, "7": 17, "8": 2, "9": 5,
            "11": 1, "12": 1, "13": 1},
 "per_bucket": 8, "prompt_version": 1, "model": "deepseek-v4-flash-0731"}
  • 凭证：跟现有 NLP 约定一致 —— NLP_API_KEY 环境变量、DashScope 兼容端点、模型名写错会 404（客户端会把 /models 的现名捞出来印在日志里）。本机现在没有这个变量，所以下面的演示用的是本地兜底句池；接上 key 后同一管线直接换源。
  • 缓存：bodies.jsonl 只追加，键是 (model, prompt_version, 桶, 条号)。重跑不重复调 API，同一份 jsonl 出的片子逐像素可复现。
  • 兜底：仓库里保留一个 50 条左右的正向句池，无 key / 断网时用；报告里标明这一批是「本地池」还是「远端」。
04

匹配与写回：四条判据 + 一处顺序

每条候选按原始几何换行，四条全过才可用：

  1. 行数相等：单行对单行，两行对两行。
  2. 每行不越界：第一行可用宽 = 右缘 − 正文左沿；续行可用宽 = 右缘 − 段落左沿。
  3. 第一行要顶满：宽度 ≥ 可用宽 − 0.6em，否则折行点跟原图对不上。
  4. 右缘对齐：单行时新宽度与原宽度差 ≤ 0.5em，且不得越过绿框右边 2px。

两行的那 2 条额外一条：续行也要对得上原尾巴（|尾巴宽 − 原第二行宽| ≤ 0.5em）。 只判「放得下」会写出「9 个字 + 1 个字」的排版 —— 实测 远***-2/2 原图 9+4 字， 第一版断成 9+1，右缘差 74px 被闸挡下，改成 9+4 才过。

写回的顺序是「先正文、后名字」。名字那一路会把「冒号 + 正文」整块当像素往右搬，正文先换好，它照搬就行，名字代码一行都不用改。反过来先换名字，正文的坐标就成了搬过之后的，得再算一遍偏移。代价只有一个：正文右缘本来就顶着框的行，名字变长时尾巴搬不动会被现有 GAP_BAD 拒掉 —— 这是既有行为，正文模块不改变它。

步骤做法复用的东西
擦每行一个矩形 (左−1, 上−3) – (右缘+2, 下+4)，逐行左右取中位数铺平inpaint_local.fill_local
写按墨迹上沿对齐，颜色取本行正文的核心色（最亮 20% 的中位数）draw_text.render_name 的对齐方式
顺序先擦完所有行，再逐行写名字那一路踩过的坑：先写字会被铺平啃掉左半

验收（2026-10-28 首批跑完）

  • 可换 65 / 65 条全部替换（67 行，含 2 条两行），八道闸 0 失败；不换的 8 张逐条写明原因（4 张官方横幅黑名单 / 2 张纯表情 / 2 张框跨下一条评论）。

  • 语料只读（inputs_digest=c638deb474c2f267 不变）；同输入跑两遍，report.json 与 65 张成品图字节一致。

三个已知短板（首批实测）

  • 同一句被多张复用：65 条正文只用了 31 句（15 句各 3 次 = 上限、4 句各 2 次、12 句各 1 次）。5–7 字占了 50 行，手写库这个长度只有 10–11 条（加句末标点变体后 30–32 条）—— 上线前把底子加到 100 条以上，或把上限压到 2。
  • 新字更「实」：重新栅格化的边缘比视频压缩过的原字锐一档。字号没问题（行高 64/67 行完全相同，3 行差 1–2px），要抹平得在出片后加 0.4px 的轻微模糊。
  • 上游正文框跨行的 4 张：2 张是官方横幅（黑名单，换掉等于改写公告）、2 张是真评论但框多圈了一行（几何指错，属下一条线）。
