## 一句话

工程里仍有**两条出片线**，但它们现在**共用同一份管线代码**：

```
mock_scale/
├── core/       两条线共用的管线 + 工具 + 运行配置（只有一份）
├── mock/       mock 用户线：假名字出假图（入口 + 名单 + 本线 README）
├── expand/     扩展张数线：给真实用户补图（入口 + 运行配置 + 本线全文）
├── docs/       两条线共用的文档
├── data/  outputs/  输入 / 输出（工程根上）
└── requirements.txt
```

`mock/` 与 `expand/` 各只剩**自己的入口和本线资料**；`core/` 是唯一的代码真身。
2026-10-11 分线时曾把 `core/` 的内容在 `mock/` 与 `expand/` **各拷一份**、
用 `check_shared.py` + `shared-modules.json` 守字节相同；
**2026-10-27 合并成一个工程后，两份合成一份，漂移守卫随之退役**（见文末「迁移对照」）。

## 两条线怎么找到 core/

两个只属于本线的入口，在 **import 之前**把 `core/` 放进 `sys.path`：

```python
# mock/make_spec.py 与 expand/expand_produce.py 均有这两行
sys.path.insert(0, str(Path(__file__).resolve().parent.parent / "core"))

import batch_produce   # noqa: E402
import config          # noqa: E402
import runconfig       # noqa: E402
```

* **脚本方式**（`python3 mock/make_spec.py`）：`sys.path[0]` 本来是 `mock/`，
  这两行把 `core/` 插到最前，`import config` 命中 `core/config.py`。
* **模块方式**（`python3 -m mock.make_spec`，在工程根）：同理，`core/` 插到最前。
* **子进程**：`batch_produce` / `batch_run` 用 `ProcessPoolExecutor`，
  Linux 的 `fork` 继承父进程的 `sys.path` ⇒ worker 里 import 同样命中 `core/`。
* **反向不成立**：`core/` 里的模块**不 import** `mock/` `expand/` 的任何东西（单向依赖）。

`core/config.py` 的 `PROJECT_ROOT = Path(__file__).resolve().parent.parent`
在合并后**语义不变**：仍然是 `mock_scale/`（`data/` `outputs/` 所在处，也是配置里
相对路径的基准）。`BLACKLIST_PATH` 则是 `core/source_blacklist.json`。

## 运行配置（JSON）

每个入口读一份**同名的** `<脚本名>.config.json`（用 `--config` 换一份）：

| 目录 | 配置文件 | 管什么 |
| --- | --- | --- |
| `core/` | `batch_produce.config.json` | 名单 / 素材根 / 输出 / 平台 / 字号 / 并发 |
| `core/` | `batch_run.config.json` | 语料根 / 探针 / 落图档 / 并发 |
| `mock/` | `make_spec.config.json` | 素材根 / 名字个数与长度 / 输出 |
| `expand/` | `expand_produce.config.json` | **抖音**：语料根 / 模式 / 各口径开关 |
| `expand/` | `expand_produce.视频号.config.json` | **视频号（网页版）**：同上，`platform` 写 `generic` |
| `expand/` | `expand_produce.视频号app.config.json` | **视频号（App 端）**：`platform` 写 `wechat_app` |
| `expand/` | `expand_produce.快手.config.json` | **快手（App 端）**：`platform` 写 `kuaishou_app`；交付框多行融合，自动重建 geom |

**一个平台一份配置**，于是「出抖音」与「出视频号」不再靠记忆里的那串 flag 区分。

### 优先级与实现（`core/runconfig.py`）

```
命令行显式给  >  JSON 里写的  >  脚本里的 DEFAULTS
```

实现上，可被 JSON 控制的命令行参数在 argparse 里**一律 `default=None`**（`None` = 这次没给），
parse 完之后由 `runconfig.fill()` 依次回填。⚠️ **别给这些参数写 `default=` 的实值** ——
写了就分不出「用户给了这个值」和「这是默认值」，JSON 会被**静默忽略**（比报错难查得多）。
这条规则写在 `runconfig.py` 的模块 docstring 里，加参数前先读它。

跑完第一行日志会汇报这次到底用了什么（便于复现）：

```
运行配置 /home/puyu/work/mock_scale/core/batch_produce.config.json · JSON 生效 12 项 ·
命令行给 2 项（其中 limit, dry_run 压掉了 JSON）
```

### 几条口径

* **路径以工程根为基准**。`runconfig.path()` 把配置里的相对路径按 `config.PROJECT_ROOT`
  解析 ⇒ **在哪个目录下敲命令结果一样**。`"out": "outputs/x"` 从工程根敲和从 `core/` 里敲
  都落到 `mock_scale/outputs/x`。绝对路径原样。
* **写错键就报错**。JSON 里出现不认识的键 ⇒ 报错并把合法键全列出来。与名单 JSON 的
  「**宽容输入严格报错**」是同一条口径：配置写错一个字母就静默失效是最难查的那种 bug。
* **`_` 开头当注释**。`_note` / `_comment` / `_source` 不进合法键检查、也不进结果 ——
  所以每份配置都能把「这个字段为什么是这个值」写在它旁边。
* **每个键旁边都有一条 `_<键名>` 备注**，写四件事：**干什么** · **可以填什么** ·
  **不填时用哪个默认** · **踩过的坑**。于是**配置本身就是参数手册**：

  | 配置 | 键数 | 看到哪一条会救命 |
  | --- | --- | --- |
  | `mock/make_spec.config.json` | 12 | `_per_user`（每个名字几张） vs `_seed`（写死 ⇒ 名单逐字节可复现） |
  | `core/batch_produce.config.json` | 17 | `_limit` 是「前 N 个**用户**」· `_font_size` 的 `"auto"`/整数/`"off"` · `_erase_badge`「等级标连名字一起擦」 |
  | `core/batch_run.config.json` | 17 | `_limit` 是「前 N **张**」（与上一条口径不同，注释专门点出来）· `_erase_badge` 必须与成品线同口径 |
  | `expand/expand_produce.config.json` | 23 | `_out: null` = 就地写回（须 `_yes: true`）· `_seed: 20261010` |
  | `expand/expand_produce.视频号.config.json` | 23 | 与抖音那份**逐字相同**，只差 `_platform` 与 `_source` |

  改参数时**连备注一起改**：注释与值对不上，比没有注释更坏。
* **`null` 读作「没给」**。`"out": null` ⇒ 用 `DEFAULTS` 里那个（例如 `batch_produce`
  是「`outputs/produce_<时间戳>`」、`expand_produce` 是「就地写回」）。

## 怎么跑（都在 `mock_scale/` 里敲）

```bash
# mock 用户线
python3 mock/make_spec.py                 # 生成名单 → mock/names/
python3 core/batch_produce.py             # 按名单出片 → outputs/produce_<时间戳>/
python3 core/batch_run.py                 # 拿真语料验收（检测 → 定位 → 擦除 → 排版）

# 扩展张数线
python3 expand/expand_produce.py                                      # P1 只读账（抖音）
python3 expand/expand_produce.py --mode run --out /tmp/exp            # P3 预演
python3 expand/expand_produce.py --config expand/expand_produce.视频号.config.json

# 工具
python3 core/platform_probe.py <语料根> --limit 5                     # 这份语料能不能跑
```

## 加东西时的小抄

* **改共用管线** ⇒ 直接改 `core/` 里那一个文件；没有第二份要同步。
* **加共用模块** ⇒ 放进 `core/`；两条线都能 `import`，`mock/` `expand/` **不要再放副本**。
* **加只属于一条线的入口** ⇒ 放进那条线的文件夹（`mock/` 或 `expand/`），
  需要共用管线时照抄上面那两行 `sys.path` 引导。
* **加本机实例/凭据文件** ⇒ **不进本工程**：放全机一份的地方（`~/脚本/smb_download.json`，
  `chmod 600`），再给一份 `*.example.json` 模板。
* **加可调参数** ⇒ 进 `DEFAULTS`（它同时是合法键清单与类型表），argparse 里 `default=None`，
  类型多态的（如 `font_size` 的 `"auto"`）走 `load(..., loose=(...))`。
* **改常量阈值** ⇒ 常量留在 Python 里（`core/config.py` 每个常量旁边就是它的实测量与口径），
  **不要**挪进 JSON：那会把「为什么是这个数」和「这次跑成什么」混成一堆。
* **写文档** ⇒ 本线的东西写进本文件夹的 `README.md`（长纪要如 `扩展张数.md` 也放本线），
  只有**两条线都成立**的才放 `docs/`。
