用户名大小与位置

「大小位置不固定」拆开只有两件事：起写列跟着源截图走（这条是对的，但有一行差 9px），字号全批钉死 23px（对 720 宽的图正好，对 590 宽的缩放图大了 4px）。下面 45 行的数字全部来自 manifest.json，不需要重跑。

02

位置：唯一一处错位是 D 行的 9px

A 和 D 是同一版式的两行：图上量到的等级标都从第 40 列开始（蓝紫色药丸的首列相同），两行的胶囊与名字右缘也在同一列。但 A 写在 40，D 写在 49。

原因是 name_left 有两条取值路径，而 45 行里只有 D 一行走的是第二条：

44 行 badge_span[0]→ 40 / 41 / 33
1 行 capsule_head + 24→ 25 + 24 = 49

问题在 capsule_head = 25：等级标在第 40 列，40 − 25 = 15，离 24px 的固定间距差 9px —— 这一行的框高 129px、下半截还有一条 emoji 行，胶囊头量偏了。两条量本来可以互相校验，现在没有校验。

O1 · 两条量自洽才采信 建议做 影响 1/45 行

等级标左沿本来就该在胶囊头 + 24 处；对不上就说明头量错了，退回 badge_span[0]（44 行用的就是这个，等于零回归）。

    @property
    def name_left(self) -> int:
        if self.badge_span is None:
            return self.slot[0]
        if self.capsule_head is not None:
            fixed = self.capsule_head + config.CAPSULE_HEAD_NAME_PAD
            # 两个量必须自洽：等级标左沿本来就该在胶囊头 + 24 处。
            # 对不上 ⇒ 头量偏了（梦___◆8-2/1：25 vs 应为 16，差 9px），信等级标。
            gap = self.badge_span[0] - self.capsule_head
            if abs(gap - config.CAPSULE_HEAD_NAME_PAD) <= 3 and fixed <= self.slot[0]:
                return fixed
        return self.badge_span[0]

验收：A、D 两行的 name_left 相等（40）；其余 44 行逐像素不变。

03

字号：590 的缩放截图大了 4px

语料里两种采集宽度。590 是把同一版式缩小 0.82 倍后的截图：这一行正文墨高 19px，我们按 23px 写，写出来墨高 23px —— 假名字比同一行正文高 4px（+21%）。720 那批正文墨高 23px，正好对上。

O2 · 字号跟采集宽度等比 需要你拍板 影响 4/45 行

基准仍是 23px，只对缩放截图按宽度等比：round(23 × W / 711)，W < 690 时才生效 → 590 得 19px，其余 41 行一个像素不变。

代价（已实测这 4 行）：19px 下「大猫」只有 38px，而槽位是 47px，补位规则会加 1 个随机字（大猫 → 大猫X，实测 text_width 56）。4 行里 3 行会这样，四/5 不会。这是补满槽位的既定行为，但确实多了一个字。

REF_W, BASE = 711, 23          # 原始采集宽度；这一档的对齐字号

def pinned_font_size(width: int) -> int:
    if width >= 690:
        return BASE
    return max(config.FONT_SIZE_MIN, round(BASE * width / REF_W))

另一种修法（只改字号、不补字）会让冒号左移 9px —— 换成一个更显眼的错位，不建议。

04

05

不做

  • 全批统一 name_left = 40。590 那 4 行会把名字挪到胶囊左侧 7px（33 → 40），41 那 8 行会差 1px。位置跟源图是对的，错的是「哪个源图的量信错了」。
  • 按行自适应字号（18–24）。一批里会出现 5 种字号，正是 2026-10-11 之后被否掉的做法（「每次运行都一定数量的图片定字号」）。O2 是 1 个基准 + 1 个比例，跨批稳定。
  • 动名字颜色、阴影、字体。不在这次范围。
