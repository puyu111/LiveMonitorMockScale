为什么必须有几何

一张交付图是整屏截图，屏幕上同时有十几条评论。要换掉其中一条，程序必须先知道两件事：圈的是哪一条，正文从哪儿开始。这两件事 OCR 层已经知道，并写在各段导出的 comments.jsonl 里。

geom.json 把这份知识按交付树的相对路径索引起来，交给量测和替换两个阶段。没有侧车文件时，core/upstream_geom.py 会按交付树自动重建；三条来源都拿不到才拒绝。换错比不换贵。

自动重建也拿不到时：measure_bodies.py / batch_body.py 打印原因并以 2 退出，不会从像素猜框。

它在管线里的位置

交付树里有图，几何在各段导出目录里。两者按相对路径配对成一份 geom.json（core/upstream_geom.py 自动做），之后量测与替换共用同一份。

  1. 01交付树manifest.json
    rel / seg / t / roi
  2. 02各段导出comments.jsonl
    text_box / colon_box / badge_box / emojis
  3. 03配对seg + t + roi
    → 交付树的 rel
  4. 04geom.jsonitems[rel]
    = 四个几何字段
  5. 05下游measure_bodies
    → batch_body + 八道闸

成品写完还要用同一份几何重测一遍（REMEASURE 闸）。前后口径不一致，验收数字就没有意义。

框是锚点，不是正文的边

上游框只回答「这一行在哪、正文从哪起」。正文左沿、右缘、行带、字号、颜色，仍在框内从墨迹重量。下面这张图是 某人-84/1.jpg：

text_box.x2=413，正文墨迹的右缘是 412。差 1px 看着不大，但它落在绿框的留白里：拿框当右缘，新写的字就会顶到框线。

整框量，不只看冒号右边

折行的续行回到段落左沿，可能远在冒号右边那段的左边。只看冒号右边，会把两行读成一行。

这也是跳过规则的来源：框跨到下一行评论 9 张、框上方压着另一条行带 2 张，都按「说不清」跳过。全批两行正文 60 张，单行 2,297 张。

geom.json 的形状

v1 形状，顶层 items 的键是交付树里的相对路径。本批第一条：

{
  "schema_version": 1,
  "kind": "geom",
  "items": {
    "某人-84/1.jpg": {
      "text_box":  [43, 1277, 413, 1305],
      "colon_box": [92, 1277, 117, 1305],
      "badge_box": null,
      "emojis": []
    }
  }
}
字段作用本批
text_boxOCR 文字框，定位这一行的行带全部有
colon_box冒号框，定位正文起点全部有
badge_box粉丝团药丸框多为 null
emojis表情框列表部分行有

坐标是图坐标，闭区间。text_box / colon_box 只做锚点；正文的五个数由 core/body_text.py 在框内从墨迹重新量。

自动重建：从交付树取几何

没有显式 --geom、也没有 <source>/geom.json 时，core/upstream_geom.py 会自己重建。livepipe 的 export / collect 目前不写 geom.json，collect 还会从 manifest 里筛掉四个几何字段；但它们都在各段导出目录里：manifest.json 给 rel / seg / t / roi，comments.jsonl 给 text_box / colon_box / badge_box / emojis。代码对每张图：

  1. 遍历 manifest.json 的 users[].images[]，取 rel / seg / t / roi。
  2. 读该段的 comments.jsonl，按 round(t, 3) 建索引。
  3. 用 roi 逐字段相等收窄到唯一一条。
  4. 写 items[rel]，只带四个几何字段。
idx = defaultdict(list)
for line in comments_jsonl:
    c = json.loads(line)
    idx[round(c["t"], 3)].append(c)

cands = [c for c in idx[round(im["t"], 3)] if c["roi"] == im["roi"]]
if not cands:
    missing += 1
    continue
chosen = cands[0]          # 多条同 roi 计入 ambiguous，仍取第一条
items[im["rel"]] = {k: chosen.get(k) for k in
                    ("text_box", "colon_box", "badge_box", "emojis")}

时间只做粗筛。t=24.557 这一帧同时有「王远：要5度电」（roi y=1227–1255）和「某人：朋友开的奇瑞几年了还挺稳」（roi y=1277–1305）。只按时间会配错，用 roi 才唯一。本批 2,410 张全部唯一命中，缺失 0，歧义 0。

这段逻辑内置在两个入口里，不需要先跑额外脚本。每次 collect 重建交付树都会重新编号、重写 rel，自动重建每次按当前 manifest 重算；手写的 geom.json 才会在树重建后整份失效。

边界

  • 自动重建跟着 rel 走。collect 每次重建、重新编号，代码每次按当前 manifest 重算；手写的 geom.json 会整份失效。
  • 有几何不等于能换。53 张按判据跳过，脚本不猜。跳过比换错便宜。
  • 逐张量测含昵称。body_measure.json 只在本机流转；bodies_need.json 是聚合结果，可以进交付包。
