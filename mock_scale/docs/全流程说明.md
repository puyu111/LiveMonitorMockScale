# mock_scale 全流程说明

**把直播截图里标注框内的用户名换掉，其余一个像素不变。**

本文按**执行顺序**把这条管线从头到尾走一遍：语料怎么进来、每一段代码在做什么、
判据在哪一步量、失败长什么样、文件落在哪。重点铺在**两套核心逻辑**上：

- **定位逻辑**（§2 检测 · §3 定位）—— 怎么在一张截图里认出「用户名 / 冒号 / 正文」这条装配，
  并把它变成一副像素级准确的擦除蒙版；
- **绘画逻辑**（§4 擦除 · §5 排版与写字）—— 怎么把旧名字抹掉、把「冒号 + 正文」
  原样搬到新位置、再把新名字画上去。

其余外围（为什么这样做、跨平台、规格与逐图验证）不在本文展开：
「为什么」去 [`技术说明.md`](技术说明.md)，「跨平台」去 [`多平台方案.md`](多平台方案.md)，
「规格与验证记录」去 [`../README.md`](../README.md)。

> 📁 **2026-10-27 合并后**：管线、工具与运行配置只有 **`core/` 一份**；`mock/`（假名字出假图）
> 与 `expand/`（给真实用户补图）两条线只保留各自的入口与本线资料，用 `sys.path` 指向 `core/`。
> 本文引到的 `box_detect.py` / `inkmask.py` / `draw_text.py` 等**共用模块**都在 `core/`。
> （旧 `test2` 路径与 `check_shared.py` 漂移守卫的去向见 [`工程结构.md`](工程结构.md)。）

> ⚠️ **这条管线不调用任何模型。** 它整个是为**替掉一次云 API 擦除调用**而立项的。
> 这里的「擦除」是传统确定性算法（`cv2.inpaint`），
> 「写字」是本地字体渲染（Pillow + Noto Sans CJK）—— 没有网络、没有接口、0 元。

## 技术栈

一句话：**Python 3 + 三个 pip 包 + 一个系统字体**，没有别的。

| 层 | 用什么 | 在这一条管线里干什么 |
|---|---|---|
| 语言 / 运行时 | **Python 3.14.4**（`.venv`） | 纯 CLI 脚本 —— 不是服务，**没有 Web 层、没有数据库、没有前端** |
| 图像 I/O | **Pillow 12.3.0**（`PIL`） | 读写 jpg/png、渲染新名字（truetype + 抗锯齿）、拼对比图 |
| 图像算法 | **opencv-python-headless 5.0.0.93**（`cv2`） | 形态学（膨胀 / 闭运算）、`inpaint`（Telea / NS）、HSV 阈值（框检测）、`distanceTransform`（笔画粗细） |
| 数值 | **numpy 2.5.3** | 全程按 `(H,W,3)` 数组算：蒙版、列投影 / 行投影、逐像素比对 |
| 字体（**系统依赖，不在 pip 里**） | `/usr/share/fonts/opentype/noto/NotoSansCJK-Medium.ttc` | 写新名字用。`config.FONT_PATHS` 四个候选按优先级取第一个存在的；⚠️ 一个都没有会直接抛 `FontNotFoundError`（`sudo apt install fonts-noto-cjk`） |
| 并行 | `concurrent.futures.ProcessPoolExecutor`（stdlib） | 批量按图分片，默认 `min(8, CPU 核数)` |
| CLI 与报告 | `argparse` · `csv` · `json` · `logging`（stdlib） | 参数解析；报告落 `rows.csv` / `summary.json` |
| 可复现随机 | `hashlib.md5` 派生种子（stdlib） | 补字用的种子。**不用内建 `hash`** —— 它受 `PYTHONHASHSEED` 影响，跨进程不稳，会毁掉「同一张图永远同一结果」 |

**刻意没有的东西**（每一条都是设计决定，不是没来得及）：

- **没有模型、没有云接口** —— 不装 `dashscope`，无 `requests`、无任何网络调用；
- **没有 OCR** —— 全流程**不读文字**（`--old` 只记录、不生效）：定位靠**版面几何**
  （颜色饱和度、段宽、填充率、笔画粗细），不是靠认字。这也是它能只依赖三个包的根本原因；
- **没有深度学习框架** —— 无 torch / tensorflow / paddle；擦除是 `cv2.inpaint` 这类传统算法；
- **没有测试框架** —— 没有 `tests/`、没有 pytest、没有 `pyproject.toml`。验证靠 `core/batch_run.py` 的
  **内建判据**（每图 × 每探针都量、都进报告）+ **锚点自检**（`爱国者-9` 必须 8/8 全绿）
  + README 里那份独立校验脚本。
  ⚠️ 这是本项目最反常规的一点：**判据是产品的一部分，不是外围的测试** ——
  删掉判据就没法回答「这批片子对不对」。

⚠️ `requirements.txt` 里写的是**版本下限**（`numpy>=1.24` / `opencv-python-headless>=4.8` / `Pillow>=10.0`），
上表列的是本机 `.venv` 的**实际版本**。

## 0. 全景：一张图从进到出

```
 语料目录                                    每条评论一行： [用户名][：][正文]
 <根>/<昵称-张数>/<n>.jpg                    外面套一圈彩色描边（标注框）
        │
        │  批量入口 core/batch_run.py：扫目录、建任务表
        ▼
 ┌─ 阶段 0  跳过①  SKIP_PURE_EN ─────────────────── 昵称只有 ASCII？→ 不出片（读图前）
 │
 ├─ 阶段 1  检测     box_detect.detect_boxes ─────── 找彩色空心矩形描边
 │                                                  NO_BOX / MULTI_BOX（取面积最大）
 ├─ 阶段 2  定位     inkmask.find_erase_region ───── 框内量出「名字 / 冒号 / 尾巴」+ 蒙版
 │             └─ 跳过② SKIP_EMOJI ──────────────── 名字段里有 emoji？→ 不出片（定位后）
 ├─ 阶段 3  擦除     inpaint_local.erase ─────────── 洗源 → inpaint → 只贴蒙版内
 ├─ 阶段 4  排布     draw_text.plan_name ─────────── 去 emoji、定字号、截断、补满槽位（只算不画）
 ├─ 阶段 5  搬尾巴   draw_text.shift_tail ────────── 把**原图**的「冒号+正文」整块平移
 ├─ 阶段 6  写字     draw_text.render_name ───────── 最后把新名字左对齐写在原槽位上
 └─ 阶段 7  度量     三条内建判据在**结果图上**重量 ── 间距 / 尾块像素 / 不越框
        │
        ▼
 产出：单张 → outputs/<名>_replaced.png · _compare.png · _mask.png
       批量 → outputs/batch_<时间戳>/ rows.csv · summary.json · skipped.txt · dump/
```

**三条入口，同一套管线：**

| 入口 | 什么时候用 | 框从哪来 |
|---|---|---|
| `core/replace_username.py`（单张/小批） | 冒烟、调参、验证规格 | `--bbox` > `config.BOX_TABLE` 查表 > 报错。**刻意不接检测器** |
| `core/batch_run.py`（真实语料） | 全量跑、出报告、看效果图——回答「**管线对不对**」 | `core/box_detect.py` 自动检测 |
| `core/batch_produce.py`（名单生产） | 按 JSON 名单出片——回答「**给我出这批片子**」 | 同 `batch_run`（检测一次，选材时量好随任务带走） |

`batch_produce` 调的是同一个 `replace_username.process_image`，所以它出的片与 `batch_run`
验过的片是同一套合格标准（`GAP_BAD`/`TAIL_BAD`/`BOX_BAD`/`LEAK`/`DIRTY` 逐条同一套定义）。
它的差异只在**选材与包装**：名单 → 选材（先量一遍、按「名字放不放得下」打分、长名字先挑）
→ 出片（九条判据不过就换素材）→ 落成 `<名字>-<实际张数>/<n>.jpg` + `manifest.json` / `summary.json`。
⚠️ 三处口径与 `batch_run` **刻意不同**（`fit=width` 不砍字 / 不补满槽位 / 默认 jpg），
理由见 [`../README.md`](../README.md)「批量生产」一节。

单张模式不接检测器是**故意的**：8 张的结论要量的是 inpainting，不能让检测误差混进去
（`replace_username.resolve_box` 的 docstring 写明）。批量模式则**必须**接，因为没有框表可查 ——
代价是检测的错会进入统计，所以报告按「检测 / 定位 / 擦除 / 排版」分段计数。

## 1. 阶段 0 · 语料扫描与跳过①

**入口：** `batch_run.collect_images`（批量）／`replace_username.collect_inputs`（单张）

批量模式只认一种目录形态：`<根>/<昵称-张数>/<序号>.<后缀>`。目录名里的**昵称**会被
`split_user_dir` **从右边**切第一个 `-` 取出来（昵称本身可能含 `-`，如
`一麻袋开心(沧海一舟)-6`，也可能含 `@`）。这个昵称后面有三个用途：
`equal` 探针的新名字、纯英文跳过的判据、报告里的用户分组。

**跳过① `SKIP_PURE_EN` —— 判在「读图之前」。** 昵称串 `str.isascii()` 为真就整张跳过：

- 判据取**目录名里的昵称**，一个像素都不读 —— 检测、定位、擦除、排版全省下；
- 理由：昵称整段是 ASCII 时，「保持总长不变」这条规格**完全没有意义**，出的都是不该要的片；
- 注意数字、`@`、`_` 也是 ASCII，所以 `123456`、`@abc`、`Czy` 都按这条跳过 —— 与规格
  「名字串只有 ASCII」**字面一致**。

跳过的图**不擦不画、不落任何图片文件**（`--dump` 任何档都不给），也不进任何失败统计；
唯一留下的是 `rows.csv` 里一行（`probe="-"`）+ `skipped.txt` 里的**绝对路径**。

⚠️ **这条规格的「跳过率」是语料相关的，换平台必须先量**（三份语料全量实测）：
抖音 **9.2%**（60/650）· 视频号 **18.1%**（76/420）· 微博 **3.7%**（15/406）。
⇒ **规格和阈值一样，都得按平台复核** —— 而复核必须用**全量**，`--limit` 会骗人：
最初拿 `--limit 20` 报过「微博 60%」（那 20 张里正好排进两个纯英文目录），全量只有 3.7%。
⇒ 三平台现在的默认：抖音/视频号跳过纯英文，**微博不跳**
（`platforms.PROFILES["weibo"].skip_pure_en=False`）。详见 [`多平台方案.md`](多平台方案.md)。

> ⚠️ **方向是安全的**：目录名会把昵称里的 emoji 丢掉或转写成 ASCII
> （`A淘气⇒` 的真身是 `🦄淘气💨`），所以「目录名是 ASCII」推不出「图里也是 ASCII」。
> 这一条只负责**跳过**，不命中就照常往下走 —— 图里真有 emoji 由阶段 2 的
> `SKIP_EMOJI` 兜住，两条判据互为兜底。

## 2. 阶段 1 · 检测（`core/box_detect.py`）

**入口：** `batch_run.detect_box` → `box_detect.detect_boxes` → `pick_box`

**目标**：从整张截图里找出**彩色空心矩形描边**的坐标 —— 也就是「这一条评论」的范围。

**算法四步：**

1. **HSV 提色。** `cv2.cvtColor(BGR2HSV)`，对每种描边颜色（`config.COLOR_PROFILES`）
   做 `inRange`，得到该颜色的二值蒙版。
2. **闭运算连描边。** `MORPH_CLOSE`（`MORPH_CLOSE_ITERATIONS` 次）把抗锯齿/压缩打断的
   描边连起来 —— 描边必须是**连续直线**，断口靠这一步补。
3. **找轮廓。** `findContours(RETR_EXTERNAL)`；先用外接矩形粗筛（小于 `MIN_BOX_WIDTH/HEIGHT` 的丢掉）。
4. **判「是不是空心矩形描边」。** 对轮廓块调用 `_rect_outline_box`：
   在行 / 列**覆盖度剖面**上取**最外侧的两条实线**（覆盖度 ≥ `LINE_COVERAGE_MIN=0.60` 的连续段），
   四条边都得有、且上下 / 左右之间要有真空档，再要求「四条带都是细带」
   （厚度 ≤ `FRAME_MAX_RATIO=0.30` × 边长）且「围出的内部基本是空的」
   （内部墨占比 ≤ `INTERIOR_MAX=0.35`）。四条线**自己围出**框。

⚠️ **不能拿外接矩形当框。** 闭运算会把几十像素外的同色碎屑并进来，外接矩形比真描边大出一圈
（实测下缘多 8px）。正解是**找线**：描边的本质是四条贯穿的直线，框由线自己围出来，
外接矩形多出多少都不影响结果。

⚠️ **大框套小框要专门去重。** 同一根描边闭运算后可能产生嵌套的外 / 内两条轮廓，而两者
IoU 可能低到 0.10 —— 光靠 IoU 去不掉。所以候选框两两判：`IoU > 0.5` **或**
`containment ≥ CONTAINMENT_RATIO=0.90` 就丢弃后者（按面积从大到小处理，先留下的一定是外面那个）。
最后按「上边缘、左边缘」排成阅读顺序。

| 结果 | 标记 | 处理 |
|---|---|---|
| 一个框都没有 | `NO_BOX` | 这张图**到此为止**，记一行（`probe="-"`），三个探针都不跑 |
| 找到多个框 | `MULTI_BOX` | `pick_box` **按面积取最大**继续跑（不是 `boxes[0]`，误检的 UI 小色块常排在前面）|
| 读图失败 / 检测抛异常 | `READ_FAIL` / `DETECT_ERROR:*` | 同样记一行 |

⚠️ **`MULTI_BOX` 不是失败。** 实测 650 张里有 **50 张**命中多框，其中 **34 张定位仍然成功
（68%）** —— 按面积取最大是对的；把「多框」直接当检测失败会**高估三倍**。它只是报告里的一个计数。

⚠️ **最阴的一类检测错是「框跨两行评论」**：检测器只要求「框内前景占比 ≤ 0.35」，两行评论之间的
空隙让它过关，于是框高 96 里装了两行文字。这种框**四道判据全绿**（因为判据判的是几何自不自洽，
没有一道问「框里该有几行」）。对策在阶段 2 的**行带切分**（§3 ⑤）。

⚠️ **`core/box_detect.py` 是移植件，不是本实验的产出** —— 算法与参数照搬既有管线（在 650 张上做过标定），
只去掉了 `config._env()` 的环境变量覆盖。它只服务于批量；单张模式的框是查表固定的。

## 3. 阶段 2 · 定位（`inkmask.find_erase_region`）

**这是整条链上最复杂、也是唯一大面积失败的一段**，本节的篇幅也最长。

输入的是一张原图 + 一个标注框（**含彩色描边**），输出一个 `EraseRegion`：擦除蒙版，
外加下游要用的全部几何 —— 名字**槽位** `slot`、冒号列区间 `colon_span` / 行区间 `colon_rows`、
尾巴包围盒 `tail_span` / `tail_rows`、名字字带 `glyph_top/bottom`、拼接间距 `join_gap`、
背景色 `bg_color`、文字本色 `text_color`。**下游（擦除 / 排版 / 度量）一行代码都不重算这些量**，
所以定位这一段的准确度直接决定整条管线的上限。

### ① 内缩 + 按颜色削边 —— 先把「描边」这块地排除掉

框坐标含描边，先内缩 `BOX_INSET=6` px（`inset_box`，并夹进图像范围）。但**固定内缩挡不住
逐图变化的量** —— 描边的抗锯齿往框内糊多少每张图不同（有一张糊到「框右缘 −7」列，
落在 inset 之内，会被当成正文墨迹跟着尾巴搬走、绿框内缘缺一块）。修法是内缩之后再跑一趟
`shave_frame`：逐边检查最外一行 / 列是否**「绿占优」且占比 ≥90%**（`FRAME_GREEN_MARGIN` /
`FRAME_LINE_RATIO`），是就削掉，直到不满足为止。**不能靠加大 inset 解决** —— 那是全局量，
会切掉别张图的字顶字底（有的图字形下缘本来就贴着框）。

### ② 背景众数色 → 墨迹二值图

框内像素取**众数色**（`estimate_background`，按 `(R<<16)|(G<<8)|B` 打包后取 `np.unique` 的最大计数；
mode 比均值稳健 —— 均值会被文字和徽章拽偏）。与背景的**最大通道差** > `BG_DIST_THRESH=45`
才算「墨迹」（`compute_ink_mask`）。实测背景 40~60 亮度、文字 200+，45 落在巨大空隙里。

于是框内变成一张**二值「墨迹图」** —— 这是后续一切几何的基础。

### ③ 列投影切段

墨迹按**列**投影（`ink.any(axis=0)`），切成若干**列段**（`column_segments`）。
每一段再算两个统计量（`_segment_stats`）：**填充率** = 段内墨迹 / (段宽 × 框高)、**平均亮度**。
另外每段取**主体色**（`_core_color`：取段内最亮 25% 像素的均值，先筛掉抗锯齿过渡带）
并算它的**彩度** = `max(core) − min(core)`。

> ⚠️ **彩度是 `max − min`（色度），不是 HSV 的 `S`。** 两把尺子刻度差很远
> （同一枚 🌈：这里 190、HSV 那里 204；名字文字这里 ≤82、那里 ≤88）。定阈值绝不能混用。

### ④ 定位：两条策略，产出同样四个量

`find_erase_region` 按 `profile.name_strategy` 分派到两条**互不干扰**的策略，
它们只产出同样的四个量 `(first, name_idx, colon_idx, badge_found)`，
**下游完全共用、一行不改**：

- **`saturation_run`**（抖音路径，含 `profile=None` 的旧调用）—— 按**核心色饱和度**认名字（规则 3/4/5）；
- **`colon_anchor`**（视频号 / 微博 / 未知平台）—— 按**冒号**认分界，颜色不作必要条件。

#### 策略 A：`saturation_run` —— 按颜色认名字

**规则 3 · 剥离徽章（最左段若是「实心药丸」或「粗笔画图形」就排除）。** 两条判据：

| 判据 | 常量 | 徽章 | 文字 |
|---|---|---|---|
| **填充率** = 段内墨迹 / (段宽 × 框高) | `BADGE_FILL_RATIO=0.60` | 实心药丸 **0.74** | 汉字 0.37~0.49、冒号 0.20 |
| **笔画粗细** = `cv2.distanceTransform` 峰值 | `BADGE_STROKE_MAX=6.0` | 空心图标 **16.0** | 名字 3.0~3.2、冒号 2.0 |

两条都要求**同时**满足宽度 ≥ `BADGE_MIN_WIDTH=40`（emoji 也是图形，但只有 26~28px 宽，
**是名字的一部分**，不能剔）。**为什么要第二条**：抖音有一版等级徽章是**空心图标 + 数字**，
填充率只有 **0.48**，正落在汉字的 0.37~0.49 里 ⇒ 单靠填充率分不开，徽章会被当成名字的
第一个段（`宝宝不乖-3/1.jpg` 槽位 194px vs 真名字 112px、字高取到 32px vs 28px、取色取到
徽章的蓝紫 (112,128,224)）⇒ 出图「名字又大又白」。笔画那条**只对「上下连成一条带」的段生效**
（`row_bands` 只有一条）—— 框跨两行时徽章会和两行文字在**列**上连成一整段、笔画峰值一样高，
不加这道闸会把整段（含名字）当徽章剔掉（实测回归 3 张）。

**规则 3 的兜底（两行框专用）。** 两个失效原因：① 填充率的分母是**框高**，两行框框高翻倍 ⇒
徽章 0.74 掉到 **0.58**，跌破 0.60；② 粗笔画那条要求「段内只连成一条行带」，而两行框里同列
上下各一枚徽章＝两条带。兜底改用两个**与框高无关**的量：宽度 ∈ `[40, BADGE_MAX_WIDTH=100]`
且笔画粗细 ≥ 6。⚠️ **宽度上限是关键**：它挡住「徽章与文字在列上连成一整段」那种病理段
（实测 112~236px，段里含名字，剔掉就等于把名字丢了）。

**规则 4 · 从徽章之后开始，连续若干段「够饱和」的就是用户名。**
从 `first` 起，`sats[i] >= USERNAME_SAT_MIN=60` 的段连续收下。

> ⚠️ **按颜色切，不是按位置切。** 正文里字与字的空隙会把它切成多段（实测某张图正文是
> `[198-253]/[255-280]/[310-421]` 三段），按「最右段是正文」的把正文前半截当名字擦掉。
> 而颜色的分离度是干净的：用户名 70~80、冒号 31~42、正文（白）4~6，中间有空档。

**规则 4 的补丁 · emoji 桥接。** emoji 是多色 / 低饱和的，它的段彩度够不到阈值，会把
「名字 → 冒号」这条链**断开**。实测 `🍼携酒话清风` 切出来是 `A`(70) → `🍼`(36) → `携酒话清风`(76)，
循环在 `🍼` 停下 —— 名字被从中间切断，`🍼` 又被下一步当成「冒号」，槽位缩到 20px、
真冒号留在原地，**七项判据全过 = 静默出错**。对策是**宽度闸 + 前瞻**：

- `_is_emoji_like`：宽度 ∈ `(COLON_MAX_WIDTH=8, USERNAME_BRIDGE_MAX_W=40]` 且彩度 < 阈值
  （「宽于冒号 ⇒ 不是冒号；窄于单字上限 ⇒ 是单枚 emoji 而非段落；不够饱和 ⇒ 不是名字文字」）；
- `_bridge_reaches_text`：桥之前先确认「**桥过去能接上饱和的文字段**」。
  直觉 —— **emoji 从不单独出现在昵称之后，它总嵌在文字中间**；所以「桥过去只看到正文段」
  就证明桥错了（`Czy-12/7.jpg` 的碎屑桥过去接的是正文 sat=4 ⇒ 不桥接）。

⚠️ **别用「缝里有没有内容」判桥接** —— `_bridge_gap` 实测失效（`compute_ink_mask` 本就是
「任何非背景像素」，emoji 的浅色边缘已被算进它自己的列段，缝里确实是空的）。

**规则 5 · 冒号 = 紧跟用户名之后的那一段。** 再往右的一切（正文等）都是**尾巴**。

#### 策略 B：`colon_anchor` —— 按冒号认分界

**为什么是冒号**：三份语料的实测名字段彩度是 **74 / 2 / 0**（抖音 / 视频号 / 微博）——
「按饱和度认名字」在后两个平台上 **0 命中**；而冒号在三份语料里都是同一个签名
（宽 4~6px、填充率 15~37%、**高度约占行高的六成**）。判据在
`platforms.find_colon_candidates`（五道闸：宽 `[4,8]`、填充率 ≤0.45、高 0.40~0.80 × 行带、
上缘 ≥0.20、右侧有 ≥60px 的正文段），多个候选取**右边正文最长**的那个。

**名字 = 冒号左边、与之相邻的那一串段**（`platforms.name_run_left_of`，撞上实心宽块＝徽章就停；
微博的「铁粉牌」夹在名字与冒号之间，要**跨过它继续往左**取名字）。
本策略只在**非「背景不够纯」**的失败上报错 —— 背景不纯时整框会连成一段，
那应该在定位之前由背景检查拦掉。详见 [`多平台方案.md`](多平台方案.md)。

### ⑤ 上下这一维：字带 + 行带（2026-09-30 改动）

列投影只管**左右**；「字有多高」「框里是不是装了两行」是**上下**这一维的事，
按**行带**量（`row_bands`：把有墨迹的行按「相邻两行的缝 ≤ `GLYPH_ROW_GAP_PX=3`」聚成带，
返回 `[(top, bottom, 墨量)]`）。

- **字带（`glyph_band`）** —— 名字自己的墨迹行范围，决定字号与对齐。过去取墨迹蒙版的**极值行**，
  会被描边内侧的**抗锯齿残渣**钉住（实测内缩后右框内缘残留 1 列杂点、底框内缘残留 50 列，
  `glyph_top/bottom` 被顶到整个内缩框高 **84px**，而昵称本体只有 ~33px ⇒ 字号算成 88px、
  框高才 96 ⇒ 新名字上下撑出框）。**现在按「与冒号行范围重叠最多」的那条带选** ——
  ⚠️ 不能只取「墨量最大」的那条：两行框里第二行常常墨更多（实测质量 1577 vs **2295**），
  会把字高量到**另一行**上去。冒号紧跟名字、行范围确定，用它当锚最稳。
  **兜底**：若选中的带**高得不像一行字**（> `NAME_EMOJI_MAX_SEG_H=45`，本语料单行 27~32），
  说明带里混进了头像 / 礼物动画 / 两行粘连，改用**本色墨迹**（彩度 ≥ 阈值）的那条带。
- **行带（`band`）** —— 全框有**两条以上**「≥ `ROW_BAND_MIN_ROWS=8` 行」的行带（`box_bands`）⇒
  `multi_line=True`。只保留**与字带重叠最多**的那一条，带外的一切（擦除蒙版、冒号行、尾巴行）
  全部按行硬切，第二行原样留着。
- **`row_keep`** —— 最终允许动笔的行窗口 = `band` ∩ `[glyph_band[0]−margin, glyph_band[1]+margin]`
  （`margin = MASK_DILATE_PX + 2 = 5`）。⚠️ 再用**字带**夹一次是必须的：行带可能是「两条文字
  粘成一条」（实测 `军陌-4/3` 行带 79px、字带只有 28px），不夹的话擦除蒙版纵向漫到第二行、
  把名字列下方压着的第二行墨迹啃掉 251px。对单行框和已正确切分的两行框，这一步**恒等**。

### ⑥ 名字与冒号被第二行的墨并成一段时，重切

整框列投影用 `ink.any(axis=0)` —— **任意一行**在这列有墨就算命中。两行框里，第二行的文字会把
名字与冒号**在列上粘成一段**（实测 `军陌-4/3`：段 656-737 = 名字 656-711 + **冒号 717-721** +
第二行的墨 712-737）。后果：① 冒号落在槽位里 ⇒ **被擦掉**（用户报「冒号没有了」）；
② 槽位宽度虚高 ⇒ 补满槽位会把新名字撑到冒号原来的位子上。

`_resplit_on_band` 只在**名字这一行**上重切列段：往右走，撞到第一个「**又窄又矮**」的段
（宽 ≤ 8、高 0.40~0.80 × 字带高）就是冒号。切出来之后冒号归尾巴（跟着平移、一个像素不动），
槽位回到真名字的宽度。

⚠️ **别用「只看下半行有没有墨」判冒号** —— 那是错的：本图冒号的两个点在行 897-900 与 909-913，
**上点在中线之上**（`data/` 那 8 张的冒号恰好在下方，当年才记成「只有下半截」）。
窄 + 高度区间才是跨语料的判据。

### ⑦ 尾巴组、间距、取色窗口

- **尾巴组**（`group_cols`）= 从**名字与冒号之间的一切** ＋ 冒号 ＋ 右侧一切。
  ⚠️ 夹在名字与冒号之间的东西（微博的「铁粉牌」）必须**跟着尾巴一起走**：① 它占的正是
  名字变宽时新名字要占的那块地；② 判据「名字右缘之后的第一条墨迹列」会把它当成冒号 ⇒ 间距当场报
  `GAP_BAD`。抖音 / 视频号的牌子在名字**左边**，这条对它们不生效。
- **拼接间距**（`join_gap`）—— **按墨迹量，不按列段边界**。列段左缘由**任何一行**的墨迹决定，
  两行框里直接拿「列段左缘 − 槽位右缘」推会小几个像素。这里与结果图上的 `gap_now`
  **同一把尺子**：同一个行窗口里、名字右缘之后的**第一条墨迹列**。
- **取色窗口**（`text_color`）= **名字自己的列 ∩ 名字所在的行**，两边都必须夹。
  ⚠️ 这个窗口被污染过**三次**，每次脏东西都不同，且都被画上了错误的颜色：

  | 混进来的是谁 | 症状 | 实测 |
  |---|---|---|
  | 夹在名字与冒号之间的**药丸**（微博 `[名字][铁粉牌][：][正文]`） | 灰名字被染成淡金 | `yoyo_light-11`：`(188,188,188)` → `(211,189,153)` |
  | **第二行**的文字（框跨两行，名字那几列在第二行上也有字、且更亮） | 青蓝名字被染成灰绿 / 发黄 | `一麻袋开心(沧海一舟)-6/1`：`(166,218,238)` → `(192,214,186)`；`/5` → `(220,210,133)` |
  | 紧跟名字的**「冒号」段其实与正文连成一段**（112px 宽、含正文白字） | 青蓝名字被染成**近白** | `军陌-4/3`：`(164,220,236)` → `(247,248,253)` |

  修完之后这三张的偏差都是 **0**（画出即本色）。⚠️ 单行框下这个窗口与旧口径**等价**，
  所以这个修复只在「两行框」和「有夹层」的图上生效。

### ⑧ 生成蒙版 —— 只擦用户名，冒号一个像素都不碰

蒙版 = **名字槽位内的墨迹**（`--full-rect` 时是整段列区间，含字间空隙），膨胀
`MASK_DILATE_PX=3`（汉字边缘有 1~2px 抗锯齿过渡带，不扩会留淡淡字影），然后**三道硬切**：

1. **冒号列起清零** —— 膨胀会往右漫，而名字右缘到冒号左缘只有 `join_gap` 个像素（实测 5），
   膨胀 3px 之后只剩 2px 余量，再多一点就把冒号啃掉一角；
2. **行带外清零**（`~row_keep`）—— 两行框的第二行；
3. **内缩框外清零** —— 膨胀漫出去会**把绿色描边本身擦掉**。这是本模块唯一一处会「静默出错」
   的地方：结果图看着正常，只是框没了，批量跑时极难被肉眼发现。

⚠️ 冒号**不擦**是有意的：既然它不重画，就别擦它 —— 擦了再用 Pillow 画回去，字形宽度会差
1~2px（原冒号墨迹 745-748，重画后 745-750），多出的 2px 漏到冒号右边。保留原文则
「冒号及其后逐像素不变」是**构造保证**。

### ⑧b 等级标连着名字一起擦（`erase_badge`，**mock 线默认开**，2026-10-11）

昵称左边那颗等级药丸（抖音 `◆12` / 视频号 `✦14`）**要不要一起擦**，两条线**口径相反**，
所以它是一个**显式开关**（`process_image(erase_badge=…)`，共享代码里默认**关**）：

| 线 | 口径 | 为什么 |
| --- | --- | --- |
| mock 用户线 | **擦**（名字从**胶囊头 + 24px** 起写） | 假用户的图上**不留真用户的痕迹** —— 等级数字本身就是可认人的信息 |
| 扩展张数线 | **不擦**，整颗药丸从**目标用户自己**的图里搬 | 那条线换的是真名，标必须与名字同属一个人（用户 2026-10-10「等级标得一致」） |

擦的范围比「蒙版内的墨迹」大一圈，`inkmask._badge_rect` 专门算这块**填平区**，两处与直觉相反：

- **「名字左边那一段」不一定是药丸**（bug-325，用户「胶囊头没有了」）。视频号这条定位是
  **从冒号往左走**、缝超过 `NAME_RUN_GAP_MAX=40` 就停，「左边还有段」于是有三种来路，
  只有第一种是药丸：① 走过一段实心宽块（= 药丸）；② **缝太大走不过去**，那段其实是
  **框左沿糊进来的 1px 描边残渣**；③ 更左边还有别的段。20:51 那批 1466 张里 **663 张（45%）**
  是第②种（宽度中位 **1px**）。当药丸的代价：新名字整条**从残渣那列起写**（名字+冒号+正文
  一起**左移 ~50px**）、且把框左沿一块 16px 宽的地填平（丢的就是「胶囊头」）。
  判据 `platforms.badge_left_of` 要**两条同时成立**：那段**像药丸**（`is_badge_like`，与
  「跨过徽章」同一把尺子）**且**它**就在名字这一串里**（缝 ≤ 40）。770 张真药丸全过、
  663 张残渣全挡下。
- **药丸的柔和投影（~10px）不算墨迹** —— 它暗于背景 14 级 < `BG_DIST_THRESH=45`，
  蒙版、行范围、槽位**都碰不到它**；只擦药丸的话它留在新名字左边成一条 15 级暗竖条。
  所以填平区往两侧各多吃 `BADGE_SHADOW_PX=12` 列，**且逐列检查那几行里有没有真墨迹**
  （左边偶尔还有图标、右边就是名字），遇到内容立刻停 —— 宁可少填，绝不盖别人的东西。
- **查墨迹的行范围只能取 ROI 内缩框的行**：内缩框外沿就是绿描边的两条横杠，那几行里
  **每一列**都「有墨迹」，不排掉的话投影一格都吃不动。（另一面：`shave_frame` 是**从边缘连续
  削**的，行窗口一旦从描边外开始，它一格都不削。）
- 药丸探出内缩框的那 1~2 行也要盖住 —— 所以这块地按**整图**量，不夹在蒙版的框内。
- **胶囊头（药丸左边那截半透明圆头）要留着，新名字离它固定 24px**（Request F，用户
  「得保留背景的胶囊头还得计算胶囊头距离用户名的距离变成固定值」）。药丸不是实心矩形：
  左边半透明圆头、右边实心体。吃掉圆头 ⇒ 背景被抹（bug-325 的第二重后果）；从药丸左沿起写 ⇒
  **每个用户量出来的「头→名字」距离都不同**（语料 8~40px）。`inkmask._capsule_head` 从填平区
  左沿往左逐列找「**与页面底色同色的连续列**」（`CAPSULE_HEAD_MIN_CONTRAST=4`）= 圆头右缘；
  `_badge_rect(..., head=…)` 把填平区左界**钳在 `head+1`**、填平**只从右边取背景**；
  `EraseRegion.name_left = capsule_head + CAPSULE_HEAD_NAME_PAD`。1466 张复验：改动的 770 张
  **全部**距离 = 24（固定常数）、框外改动 >20 级 0 px。⚠️ 药丸没认出来（下条）则**退回药丸左沿**。
- **重切会把槽位切短，名字少擦一个字**（bug-326，用户报 `包子爱睡觉-15/2.jpg`「有问题」）。
  `_resplit_on_band`（bug-183 为**两行框**写的兜底）的闸门会被**本行名字自己的笔画**满足 ——
  视频号「顺」的**川字竖笔** 4×25px 落进「宽 ≤8、高 ∈ [0.4,0.8]×行高」⇒ 被当冒号，槽位
  1243-1426 切到 1243-1370 ⇒「顺意」既不在蒙版也不在尾巴平移范围 ⇒ 整字留下。守卫：新冒号右侧、
  原槽位右缘之内**本行不许再有墨**（真病征相反：那几列是**别的行**的墨，本行是空的）⇒ `return None`。
  ⚠️ 修这种 bug 时**两批成品之间不能做逐路径 md5**：换素材的重试走一条**共享随机流**，守卫少拒
  2 张就足以让几乎每个用户重新配素材（两批同 `(名字,素材)` 对只剩 442/1448）。要**把配对钉死**再比
  —— 同一张源图 + 同一个新名字 + 同一个框，只翻守卫这一个开关：9 个受影响的源全部复现，
  30 个不受影响的源两版**逐像素完全相同**。
- ⚠️ **已知边界（未改·待决策）：药丸太淡就认不出来**（bug-327）。药丸体 93 − 底色众数 53 = **40
  < `BG_DIST_THRESH=45`** ⇒ 不算墨 ⇒ 墨占比 0.274 < `BADGE_FILL_RATIO=0.60` ⇒ `badge_span=None`
  ⇒ 槽位从药丸左沿起算、胶囊头逻辑不生效（`capsule_head=None`）、药丸底色留成一块淡亮板。
  指纹：**胶囊头→名字只 8~9px**（设计 24）。256 个视频号源里 5 个。

⚠️ 这一步**故意改蒙版外**的像素 ⇒ 它自己带一条**同口径硬校验**（改动只许落在声明的矩形里），
`outside_changed` 仍是「**声明范围之外**零改动」。

### ⑨ 顺带报一句「名字段里有没有 emoji」

`EraseRegion.name_emoji` **只报告证据、不做决定** —— 擦不擦、跳不跳是调用方的事
（批量流程据此跳过整张图）。判据：名字段里凡**核心色彩度**落在名字文字色带**之外**的段，
就是 emoji；先过三道噪声闸（墨迹 ≥ 120px、宽 ≥ 10px、段高 ≤ 45px —— 最后一道挡「跨行的段」，
否则「框跨两行」会伪装成「昵称含 emoji」）。抖音用标定好的色带 `(60, 92)`；
`colon_anchor` 平台按**名字段自己的彩度中位数 ± 15** 现算（否则白 / 灰名字彩度 0~5 全落在带外，
名字被整片报成 emoji ⇒ 每一张都被跳过）。

### 定位失败（`RegionNotFoundError`，批量记 `LOC_NONE`）

宁可硬失败也不猜 —— 猜错的代价是**擦掉不该擦的东西**（正文、徽章），而那种错误在批量跑时
很难被肉眼发现。失败分三类：① 有饱和段但**拼不出「名字 + 冒号」**（昵称里带 emoji，
被填充率判据当徽章剔掉）· ② 框内**压根没有**高饱和段（昵称淡灰蓝，或检出的框根本不是评论行）
· ③ 有名字段但其后没有冒号段。实测占比与例见 §9。

## 4. 阶段 3 · 擦除（`inpaint_local.erase`，**无模型**）

**目标**：把蒙版里的旧名字抹掉，且**蒙版外一个像素不动**。

三种策略：`telea`（默认，OpenCV 快速行进法）· `ns`（Navier-Stokes）· `flat`（直接填背景众数色）。
`flat` 在「背景近乎纯色」时**最不可能出意外** —— 它连源像素都不看，也就没机会被污染。

两个步骤是必须的，都是被 bug 教出来的：

**① 洗源（`clean_sources`）。** Telea 的取样半径会伸进 5px 厚的彩色描边里 —— 有一张图
字形下缘几乎贴边，于是 **Telea 把绿色抹进了填充区**。修法：在**工作副本**里把「蒙版半径内的
非背景像素」先刷成背景色（用圆盘结构元膨胀蒙版得到取样带），让 Telea 只取到干净背景。
⚠️ 这个 bug **指标抓不到**（残余墨量、蒙版外改动都是好的），是肉眼看对比图看出来的。

**② 只贴蒙版内。**

```python
out = img_rgb.copy()
out[inside] = filled[inside]     # 只有蒙版内用插值结果
```

这一行把「蒙版外逐像素不变」从**事后断言**升级成**构造保证** —— 不是「我们检查过没变」，
而是「代码结构上不可能变」。`assert_outside_untouched` 仍会跑一遍，但那是**冗余保险**
（守「未来有人改坏了合成逻辑」）。

**度量量在「擦完、写字之前」。** `ink_before` / `ink_after` 都在这一步量 —— 量在最终图上会把
**新写的名字**也算成残余墨迹，得出「越擦越多」的假象（曾经真的报出 1326 → 1497）。

## 5. 阶段 4~6 · 绘画：排版、搬尾巴、写名字（`draw_text`）

这是「绘画逻辑」的主体。三条规格句子叠出整个模型：

> 1. 冒号前是要改的，冒号及其后不改；2. 短了填充、长了截取；
> 3. **冒号距离名字的距离不变**；4. **正文也是相对距离不变**，整体超过框就截断；
> 5. （补）拼接时不管正文还是用户名都不要表情；6. （补）总体长度不够就把用户名补长，保持总长不变。

第 3、4 句合起来把模型补完整了：

```
[名字][间距][：][间距][正文]  是**一整块刚体**，一起平移 位移 = 新名字墨迹宽 − 槽位宽
```

于是实现成**三段有序流水线，顺序不能反**：

```
plan_name    只算不画：去 emoji、定字号（对真实字体二分搜索墨迹高度）、按预算截字、
             名字比槽位窄时随机补满槽位、算出位移
shift_tail   把**原图**的「冒号 + 正文」像素整块搬到新位置，原位填背景色
render_name  最后写名字（Pillow）
```

> ⚠️ **顺序是硬约束，不是风格。** 搬尾巴要把它原来占的竖带填成背景色，而那条带子
> 在新名字变宽时**正好压在新名字身上**。先写字后搬尾巴 = 拿背景色把名字啃掉一块。

### 阶段 4 · `plan_name` —— 只算不画

1. **去 emoji**（`strip_emoji`）：新写的文本里不许有表情（正则按 Unicode 主块扫，不引包）。
   两个理由同向：规格要求「新文本不要表情」，而 emoji 在 Pillow + Noto Sans CJK 下**本来就画不出来**
   （没有彩色字形，只会落成豆腐块）。剔掉的字符进 `Outcome.stripped_chars` ——
   **不静默改用户给的名字**。原图里的 emoji 不受影响（那是语料）。
2. **定字号**（`fit_font_size`）：对**真实字体**做**二分搜索**（`FONT_SIZE_MIN..MAX`），
   用样例字「爱国者」去逼近目标墨迹高度（取自原名字实测字高）。
   ⚠️ Pillow 的 `size` 是 em 尺寸，汉字实际墨迹高只占其中一部分，「想要 27px 高的字」远不是传
   `size=27`；而换字体会改这个映射 ⇒ **不查表、不乘系数**。`FONT_SIZE_RATIO=1.36` 只是搜索起点。
3. **裁进预算**（`fit_name`）：预算 = `clip` 时是 `槽位宽 + 尾巴余量`（`max_name_width`），
   `width`/`height` 时是槽位本身。放不下就按 `--fit` 处理：
   - `clip`（默认）字号不动、**从右往左砍字**（至少留一个字，其余交给 `overflow_px` 上报）；
   - `width` 保名字完整、**缩字号**（实测字高只剩 57%）；
   - `height` 什么都不做、任由溢出（**会违反规格**，用途是「看清不裁会怎样」，不拿来出片）。
4. **补满槽位**（`fill_to_slot`）：名字比槽位**窄**时，从「常用中文字池 / ASCII 字母数字池」
   随机补字补到最接近槽位宽 —— 于是 `shift_px ≈ 0`、**总长不变**、尾巴几乎不动。

   ⚠️ **补字要「不近视」**：字宽是离散的（中文≈整字宽、ASCII≈半宽），逐步贪心很容易栽 ——
   在没有余量的图上，先补一个汉字（差 5px）比补一个 ASCII（差 16px）看着更近，于是抓了汉字、
   之后再也补不进更窄的组合。`fill_to_slot` 每步除了随机抽字，还**穷举一个小字母表
   `FILL_SLOT_ALPHABET` 的 1~2 字组合**兜底可达性，**并列最优里随机取一个**
   （否则小字母表每次都赢、`--seed` 形同虚设）。`max_width` 是硬上限，
   于是「正文已顶到框」的图只会补到 ≤ 槽位、绝不会把尾巴顶出框。

5. 算出 `shift_px = 最终名字宽 − 槽位宽`。**此时一个字都还没画。**

**随机性是可复现的**：种子默认由「图名 + 新名字」经 **md5** 派生（不用内建 `hash` ——
它受 `PYTHONHASHSEED` 影响，跨进程不稳定），同一张图永远给同一结果；`--seed N` 可整体换一套抽法。

### 阶段 5 · `shift_tail` —— 搬，不是画

把**原图**的「冒号 + 正文」像素**整块复制**到新位置（`out[新位] = source_rgb[原位]`），
原位填背景色。

⚠️ **「填背景色」不是拿全框一个 mode 色平涂**（2026-10-11 修，bug-321）：框内底色**沿 x 会跳**
（拿报的那张图逐列量中位数：x≤1790 的左段 ≈ 40 级、x≥1817 的右段 ≈ 50 级，台阶就在 x≈1800），
而全框 mode 色按多数票取到 50 ⇒ 填在左段就是一块**亮 10 级**的浅灰板，而**所有闸都还是绿的**
（`outside_changed=0`、`ink_after=0`，因为那块地确实在「该填」的范围里）。正解是 `inpaint_local.fill_local`：从待填区域**外侧**、
同样这几行、紧邻 `LOCAL_FILL_SPAN_PX=16` 列里取**逐行中位数**铺过去。
逐行是必须的（底色沿 y 基本不变、沿 x 会跳），中位数也是必须的（那 16 列里常混着邻居的
抗锯齿边/投影）。好处是「整行同色」的东西（**穿过这条带子的绿描边**）会跟着一起续上。
⚠️ 也别拿 `clean_sources` 那种 inpaint 代替：它会把贴得近的绿描边洗成框级 mode 色，
反过来污染填充区。量过全批：**88%** 的图尾巴动过（必然平涂），其中 **100%** 的带子与真实背景
差 ≥10 级（中位 15 级，跨到绿线上的到 ~200 级）—— 这类「指标全绿但肉眼看得见」的错，
只有**拿成品肉眼看**才会暴露。

- **为什么是搬**：用 Pillow 重画冒号，画出来的墨迹**宽 6px，原文只有 4px** ——
  多出的 2px 漏到冒号右边，肉眼一看就是「冒号变粗了」。字形再调也做不到和原截图**渲染引擎**
  的字形逐像素对齐。搬原图像素则天然一致 —— 因为它们本来就是同一批像素。
- ⚠️ **顺序不能反**（bug-153）：搬尾巴要把它原来占的竖带填成背景色，而那条带子在新名字变宽时
  **正好压在新名字身上**。先写字后搬尾巴 = 拿背景色把名字啃掉一块。当时想靠「把矩形左边界
  切到名字右缘之后」保护名字，结果**把冒号从补丁里切掉了**，整条尾巴错位 51px ——
  **正解是换顺序，不是收边界**。
- ⚠️ **矩形四边都要钳进内缩框**（bug-154）：外扩的 `TAIL_MOVE_PAD=2` 圈会伸出内缩框、
  盖到绿色描边的抗锯齿边上，这一步又涂又贴 ⇒ 把描边的边线搬走一截（实测 4 张图各有
  124~549 px 绿描边被啃）。位移本身也被夹住：`shift` 不许越过框右界，宁可位置差一点、
  也不能把框涂了。
- 尾巴像素取**原图**，不是擦过的那张。

### 阶段 6 · `render_name` —— 最后写字

整条装配里**只有名字是真正「画」出来的**，冒号和正文都是**搬**的。这是全篇唯一一处重画，
理由是一条不对称：

| | 怎么来 | 为什么 |
|---|---|---|
| **名字** | **Pillow 重新渲染** | 它本来就要被换掉，没人拿它和原文逐像素比；而且新名字的**长度**是自由变量，没法搬 |
| 冒号 + 正文 | **搬原图像素** | 它们必须逐像素不变 —— Pillow 画的「：」墨迹宽 6px、原文只有 4px，多出的漏到右边（bug-150） |

**位置：按「墨迹包围盒」对齐，不按排版框。** 就是这一行：

```python
canvas = Image.fromarray(img_rgb)                      # 已经搬好尾巴的图
ImageDraw.Draw(canvas).text(
    (slot_left - report.off_x, glyph_top - report.off_y),
    report.drawn_name, font=report.font, fill=text_color)
```

`off_x` / `off_y` 来自 `measure_ink`：它把字**真的画到一张临时画布上**，再数哪些像素被点亮
（`font.getbbox()` 给的是**排版框**，含大量行距留白，不能拿来对齐）。减去这两个偏移之后，
**墨迹**左缘正好落在 `slot_left`（原名字墨迹左缘）、**墨迹**上缘正好落在 `glyph_top`
（原名字墨迹上缘）—— 于是新名字**左对齐 + 顶对齐到原文的墨迹框**。

`text_width` 也是这么量出来的，`shift_px = text_width − slot_width` 直接由它定 ——
**先量后搬**，所以顺序是 `plan_name → shift_tail → render_name`。

**字体**：`resolve_font_path()` 取第一个存在的候选 —— 本机是 `NotoSansCJK-Medium.ttc`
（`FONT_WEIGHT="Medium"`，实测这个粗细最接近直播 UI 的字形）；`FONT_FACE_INDEX=2` = **SC**，
⚠️ 退回 0 会渲染成**日文字形**（「直」「骨」这类字一眼能看出差别）而且是**静默**错，
所以这里硬断言、不做兜底。

**颜色**：`fill=text_color`，即原用户名的**主体色**（取「名字自己的列 ∩ 名字所在的行」里
最亮 25% 像素的均值，避开抗锯齿过渡带与夹层污染，见 §3 ⑦）—— 新名字沿用原色，不另配。

⚠️ 画完之后**不再修正**名字是否越框 —— `box_ok` 是**量**出来的，不是画的时候顺手保证的。
这就是为什么「装配右缘距框 Npx」要进每张图的日志。

## 6. 阶段 7 · 度量与判据

每一条规格承诺都配一条**在结果图上重量**的判据，**不接受「按构造它应该是对的」**。
其中三条**内建进主管线**，每次跑都量：

| # | 判据 | 怎么量 | 代码 |
|---|---|---|---|
| ① | 名字 ↔ 冒号的距离 | 从名字右缘往右找第一个墨迹列，必须等于原图量出来的 `join_gap` | `_first_ink_col` → `gap_now` |
| ② | 尾块是**原图像素** | 原图那块矩形 vs 结果图平移后的同一块矩形，**逐像素比** | `_block_diff` → `tail_diff_px` |
| ③ | 整条装配**没越框** | `result[:, box_right:]` 是否有改动 | `overrun` → `box_ok` |

⚠️ **③ 量的是「框右界之外」，上下方向不在内建判据里。** 判据叫「不越框」，实际口径是那条
**竖线**：左 / 上本来就不会被越过（装配左对齐在名字槽位上），上下由**定位的行带**按构造守
（§3 ⑤）＋独立校验脚本的判据守（那个只在 `data/` 那 8 张上跑、**没进批量**）。
**这条口径真的漏过一次**：某张 `short` 档在绿框**上沿外 2px** 改了 54 个像素，批量照样报
`box_ok`（根因已在 §3 ⑤ 修掉，但**判据本身没变**）。

另有四条**只在独立校验脚本**里（适合改动后回归）：④ 腾出去的空隙是纯背景 · ⑤ 绿描边一个
像素不变 · ⑥⑦ 框右界之外、内缩框上下之外零改动。脚本全文在 [`../README.md`](../README.md) 最后。

**「擦干净」（`clean`）= 残余墨迹 ≤ 5% 且蒙版外零改动。**

## 7. 批量流程：三档探针与报告

`batch_run.run_one` 处理一张图：**检测只做一次**（链上最贵的一步），三个探针**共用同一个框**。

### 三档长度探针

| 探针 | 新名字 | 测什么 | 实测宽度比 |
|---|---|---|---|
| `short` | `A` | 名字比槽位**窄** ⇒ 随机补满、尾巴不动 | 1.013 |
| `equal` | 目录名里的昵称 | 长度相当 ⇒ 最接近原图的基线 | 1.01 |
| `long` | `SuperUser` | 名字变长 ⇒ 吃掉余量，不够就**截断** | 1.391 |

⚠️ `short` / `equal` 的宽度比都是 ~1.01 而不是「明显小于 1」，是**补满槽位按构造决定的** ——
关掉它（`--no-fill`）才回落到旧口径的 0.26 / 0.96。

⚠️ `equal` 用的昵称取自目录名，而目录名把 emoji 转写成了 ASCII ⇒ 它**不是**「逐像素还原
原图」的基线，能验的只是「长度相当时的排版」这一支。

### 跳过② `SKIP_EMOJI` —— 判在「定位之后」

规格原话（2026-09-30）：「**含有表情也跳过，跳过的不记入数量，跳过的要记绝对路径**」。
emoji 是**图上的像素事实**，必须等定位才判得出，所以搭**第一档探针**的车：第一档命中就
整张跳过，不必跑完三档。这一档的擦除 / 渲染白做了一次，但**没有落任何图、也没进任何数量**
——「不擦不画」这条规格守的是**产出**，不是内存里的中间量。

### 并行与汇总

`ProcessPoolExecutor`（默认 `min(8, CPU 核数)`）分片跑，主进程只汇总。**子任务异常必须留下
痕迹** —— 兜异常处会产出一条可统计的 `CRASH:` 记录，而不是只打日志：曾经出现过「子任务全崩，
报告却照常打印『失败分类：无 / 总耗时 0s』」，**静默零结果和真成功在报告上长得一模一样**。

`rows.sort` 后落报告，再打印汇总、跑锚点自检。

### 输出

```
outputs/batch_<时间戳>/
├── rows.csv        每张图 × 每个探针一行（utf-8-sig，可直接进表格工具）
├── summary.json    by_probe 分组 / failure_counts / skipped / run 元信息 / anchor
├── skipped.txt     跳过的图：绝对路径 + 理由（唯一的留存）
└── dump/           按 --dump 档位落图，默认 none（不落）
```

**跳过的不计入任何数量**：`run.images` == `images_processed` 都是**处理过的张数**，
扫到的总数单列在 `images_scanned`；跳过的图只出现在 `skipped` 块里，不参与任何比率。

| `--dump` | 落什么 |
|---|---|
| `none`（默认） | 只落报告 |
| `failures` | 有失败判据的那几张：`<序号>_<探针>_replaced.png` + `_compare.png` |
| `all` | 每张一张**裁剪摞图** `<用户>/<序号>_probes.png`（原图 + 三档，框外裁掉） |
| `full` | 每档**两张**：`_full_<档>.png`（整张尺寸、只有绿框内被换）+ `_<档>.png`（裁剪条），另加 `_orig.png`（原图基准条） |

⚠️ 看长度影响用 `all`（四行对齐才好比），看整屏观感用 `full`（换完名字跟右边按钮挤不挤 ——
那些恰恰在框外）。**探针没出图时不落整图、但要落裁剪条**（原图那条加红框写失败标记），
否则「这一档没跑」和「跑了但失败」在目录里长得一模一样。

⚠️ `full` 落整张尺寸 PNG，实测 ~2.9 MB/张 × 3 档 ≈ 8.7 MB/张原图 ⇒ 650 张全量 ≈ 5.7 GB，
要配 `--limit` 跑。

### 锚点自检

内置一条自检：`爱国者-9`（原来那 8 张图出自这里）在 `equal` 探针上必须**全绿**。
这 8 张在单张模式下已有定论，若批量给出**不一样**的结论，就是**批量外壳**写错了，
不是管线坏了。**这是这个脚本唯一的自我验证手段。**

## 8. 失败码速查

| 段 | 码 | 含义 | 该改哪个文件 |
|---|---|---|---|
| 检测 | `NO_BOX` | 一个框都没找到 | `core/box_detect.py` |
| | `MULTI_BOX` | 找到多个（取面积最大的继续）| 计数项，非失败 |
| | `READ_FAIL` / `DETECT_ERROR` | 读图失败 / 检测抛异常 | 输入或 `core/box_detect.py` |
| 定位 | `LOC_NONE` | 框里找不到「用户名 + 冒号」结构 | `core/inkmask.py` |
| 擦除 | `DIRTY` | 残余墨迹 > 5% | `core/inpaint_local.py` |
| | `LEAK` | 蒙版外有像素被改动 | `core/inpaint_local.py` |
| 排版 | `GAP_BAD` | 名字↔冒号距离 ≠ 原图的 `join_gap` | `core/draw_text.py` |
| | `TAIL_BAD` | 尾块不是原像素（重画了 / 被压住）| `core/draw_text.py` |
| | `BOX_BAD` | 装配越过了标注框 | `core/draw_text.py` |
| 外壳 | `CRASH:*` | 子任务异常 | `core/batch_run.py` |
| 跳过 | `SKIP_PURE_EN` / `SKIP_EMOJI` | **不是失败**，这张图不该出片 | — |

⚠️ **`DIRTY` 与 `LEAK` 是「不该出现」的两类**：本地确定性插值物理上不可能造字，
「只贴蒙版内」让蒙版外零改动成为构造保证 —— 出现就是代码 bug（对照：API 路线
14 张真调里 4 张凭空造字、擦干净只有 3 张）。**实测 1476 次探针里这两类一次都没出现；
全部损失都发生在它们前面的「定位」。**

## 12. 边界：这套东西什么时候不成立

1. **依赖「用户名是框内唯一的高饱和色文字」。** 昵称本身不饱和（白 / 灰）或正文比昵称更亮，
   `USERNAME_SAT_MIN=60` 就不成立 ⇒ 定位失败，或**静默量错对象**（把正文白当用户名 ⇒
   擦掉评论、留下用户名）。⚠️ **这不是调阈值能解决的** —— 白名字和白正文彩度都 ≈2，
   降阈值会把正文一起卷进名字段。要换的是**锚点**：从「按颜色认名字」换成「按冒号定位」
   （冒号在三份语料里都稳：宽 4~6px、填充率 15~37%）。
   **这一改已经落地**（`colon_anchor` 策略），视频号 / 微博语料的定位从 0 命中抬到
   75.1% / 88.6%，抖音逐图零回归 —— 完整记录见 [`多平台方案.md`](多平台方案.md)。
   本语料（抖音 112 个昵称）全是青 / 白 / 灰蓝，实测名字段彩度最大 82。
2. **依赖「背景近乎纯色」。** 本语料 std ≈ 5。背景一有渐变、纹理，或评论压在图片 / 视频上，
   `flat` 会露补丁、Telea 会糊 —— 那种场合才轮到 inpainting 模型上场。
   视频号实测里就有整框连成一段、众数色占比只有 8~10% 的图（连「背景是什么颜色」都估不出来）。
3. **「放不下就截断」是规格，不是缺陷。** 名字写长 + 版面不变本身无解，三档取舍
   （`clip` 砍字 / `width` 缩字号 / `height` 什么都不做）里必须选一个代价，默认选「保字号、砍字」。
4. **本模块只在这个语料上硬化过，别直接搬去别的语料** —— 它处理不了 emoji、多色昵称、
   视频号那类版式。真正可复用的是三条工程约束：**洗源** · **只贴蒙版内** · **平移而非重画 + 先搬后写**。
5. **「零违规」不等于「出的片对」。** 判据判的是「几何自不自洽」，不是「框对不对」——
   检测框跨两行评论那种错，四道判据全绿（§2 末）。
