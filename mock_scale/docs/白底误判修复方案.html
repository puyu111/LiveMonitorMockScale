白底误判：一行被铺成白条

素材右下角压着一张白色浮层卡，它落进了评论行的标注框。背景色被估成纯白之后，整条判定链反了过来 —— 深色的评论行成了「墨迹」，457px 宽的它成了「药丸」。45 张产出里有 5 张这样废掉，而且现有六道闸一张都没拦住。

5 / 39废掉的成品（12.8%），全部来自 5 张素材
1个根因：bg 众数落到了白卡上
0道现有闸能发现它 —— outside_changed = 0
01

现象：同一块地方，进去和出来

02

机制：五步，每一步都有实测数

STEP 1框跨到了白卡上框内白卡 31.6%
STEP 2背景取全框众数bg = (255,255,255)
STEP 3墨迹定义反了深色行成了「墨」
宽442 填充0.97 亮度67
STEP 4442px 的行被认成药丸badge_rect 457×47
真药丸 ≈72px
STEP 5按白背景铺平erase + fill_local
成品行 76% 近白

关键在第 2 步：inkmask.estimate_background() 取的是整个内缩框的 RGB 众数（core/inkmask.py:1374）。直播 UI 的底色是大片纯色，众数本来稳健 —— 前提是框里只有这一行。白卡一进来，众数就成了白。

04

三个方案：两道闸 + 一处根治

A、B 是闸（宁可不出片，也不出坏片）；C 是根治（作业面改用上游给的行带头，这 5 张还能救回来）。A、B 互不替代，C 也不替代它们。

A · 背景反相闸

建议先上≈1 h

背景估成近白、而「名字段」明显比背景暗 —— 这两个条件同时成立，说明框里混进了大块亮色，直接判 LOC_NONE 不出片。

# inkmask.find_erase_region 返回前
if bg.min() > 235 and name_lum < bg_lum - 80:
    raise RegionNotFoundError("BG_INVERTED")

误伤面：真·白底浅色主题的直播（白底黑字）。这类语料在本项目里还没出现过；真出现时，日志会报 BG_INVERTED，一眼能看出来是闸判的、不是算法失灵。

B · 药丸宽度闸

建议先上≈1 h

等级药丸的宽度有物理上限（本项目实测族 57~84px）。宽到框宽一半以上就不是药丸，撤销 erase_badge、退回「只擦名字」。

# _badge_rect 采纳前
if badge_w > 0.5 * box_w or badge_w > 2 * BADGE_W_TOL + 100:
    badge = None        # 当没量到，别拿它当擦除起点

它挡的是「药丸误认」这一族，不止白卡 —— 浮层边角、表情大块、纯色徽标都会撞上。白卡这张里它单独也能把 457px 拦下来。

C · 行带头：从上游取，不从像素猜

根治 · 单独立项≈0.5 d + 回归

上游已经给了这一行的几何：comments.jsonl 每条评论都带 roi / text_box / colon_box / badge_box（309 行里 text_box 100% 有、badge_box 48% 有），语料 manifest.json 每张图又带 roi + seg + t，而 A 档已经证明「导出图 roi == comments roi 73/73」。一行查表就能拿到真实的行带，不必再写行带检测。

取样范围bg 众数近白占比
roi（现在的做法）(255,255,255)34.5%
text_box ∪ badge_box（上游）(0,40,42)1.9%
# ① 取样：上游的行带头（缺 badge_box 就用 text_box，再缺才退回像素行带）
head  = union(text_box, badge_box) or text_box
bg    = mode(img[head.y0:head.y1, head.x0:head.x1])   # 这行 (0,40,42)

# ② 改动：蒙版 / 填平 / 写字 的上下沿夹到同一个 head
mask  &= rows(head.y0, head.y1)      # 现在是 y1387–1434，比上游多 11px / 2px
rect   = clip(rect, rows(head.y0, head.y1))

# ③ 列范围整段用上游：名字段 text_box→冒号，正文段 冒号→文字框右沿
name  = [text_box.x0, colon_box.x0)     # 99..165，宽 66
body  = [colon_box.x1, max(text_box.x1, emoji.box.x1))
                                        # 175..289；有表情取表情框右沿

列范围为什么能用上游：这条 text_box 是 [99,1398,289,1432] —— 上下沿就是这一行，右沿 289 正好在最后一个字（284）右边 5px；colon_box [165,1412,175,1424] 把名字（x_text=106…165，宽 59）和正文（175 起）分开。「认名字段」和「找正文右缘」两步都可以整步替掉。73 张配对实测：框右沿比最后一个墨列多 4px（中位）、0/73 框比字长；238 行里只有 3 行的框切进冒号。正文右缘若遇表情，用上游 emojis[].box 补齐。剩下的量测面是药丸（badge_box 只 48%）和字号/颜色。逐项实测 →

代价：bg 是整条管线的地基（墨迹、列段、药丸、字号、名字色全都读它）。正常图上 text_box 内取样与整框取样应当同色 ⇒ 结果逐字节不变，但这必须靠全量 md5 归因证明；另外 mock 线可以吃到上游几何，扩展线在 plan 阶段只读 manifest.roi，要接同一份表得先把 comments 挂进 plan（A 档那条路已经铺好了）。

05

怎么落地：顺序、预期、验收

阶段做什么预期
今天A + B 两道闸，各带一条日志原因码（BG_INVERTED / BADGE_TOO_WIDE）坏片 5 → 0；产出 39 → 34；缺口 +5 如实进 expand_reconcile.csv
下一步C：取样与改动都改用上游 text_box 的上下沿（缺字段才退回像素行带），先只对「结构闸已过」的图生效，再全量这 5 张救回 34 → 39，且白卡这类图以后都能出片；正常图须逐字节不变
再接把「成品框内近白占比」接成常驻指标，进 report.counters同类坏片下次在账上就能看见，不必靠人翻图

验收线（改完必须全过）

  • 同一份语料复跑：成品框内近白占比 > 50% 的张数 = 0
  • 既有六道闸仍是 100%（tail_exact / gap_ok / box_ok / badge_pixel_exact / diff_in_box）
  • 34 张（或 C 之后的 39 张）逐张人工过一遍审查图
  • verify 原件 md5 0 变；扩展线 53 张逐张 md5 不变（闸只该拦、不该改）

一句话建议

A + B 今天上 —— 它们只决定「出不出这张片」，不动任何像素，风险是零；C 是真正把这类图救回来的那一刀，但它动的是全管线共用的背景量，必须单独一轮、带全量回归和 md5 归因。
