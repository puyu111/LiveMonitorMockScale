04

哪些能直接换掉

现在这一步可换成上游能省掉什么 / 风险建议
像素行带（上下沿）roi.y / text_box.y / badge_box.y白卡案的根治；上下沿不再逐图猜。高度这三维度都稳（本例 1398→1432）可用
药丸左沿badge_left（100%）擦药丸的起点不用找；右沿仍要像素（badge_box 只 48%）可用
冒号位置 / 名字起点colon_box / x_text给「按颜色认名字」加一道交叉校验；视频号那档尤其省事可用
mock 线自扫框manifest.roi（seg + t 可回查 comments）框不再比上游大 9px；但 mock 线要能吃「素材目录 + 语料 manifest」两种源可用
等级数字badge_text（72%）C 档已接；缺口那 28% 仍要降级处理已用
名字段的左右沿 / 名字与正文的分界text_box + colon_box能替「按饱和度认名字段」整步：名字 = [text_box/x_text, colon.x0)，正文从 colon.x1 起。实测名字宽 colon.x0 − x_text 中位 59px可用
正文右缘（尾巴位移的终点）text_box.x1能替：73 张配对实测，框右沿 − 最后一个墨列 中位 +4px（p90 +5，最大 +7），0/73 框比字长；正文宽 tb.x1 − colon.x1 中位 138.5px。有表情的行要并上 emojis[].box（67 行里 29 行表情越框，最多 +258px）可用
药丸宽 / 药丸右沿badge_box只能参考：本例 49×20 对，另一行 16×16、还有一行 43×24；48% 覆盖部分
名字色 / 字号 / 槽位宽上游没有这三项是像素度量，只能自己量（B 档缓存正是为它们做的）维持现状

正确用法：这两个框配起来就是「名字行」

# 一条评论行（本例 seg6）
y 范围 = text_box.y0 .. text_box.y1        # 1398 .. 1432，就是这一行的上下沿
名字段 = [text_box.x0, colon_box.x0)       # 99 .. 165，宽 66（x_text=106 起也算同一段）
正文段 = [colon_box.x1, max(text_box.x1, *emoji.box.x1))
                                          # 175..289（纯文字）；有表情取表情框右沿
药丸段 = [badge_left, text_box.x0)         # 32 .. 99（有 badge_box 就用它，48%）

这样「名字在哪、正文从哪起、到哪结束、药丸占哪」都不用再靠颜色猜；只剩药丸右沿（badge_box 只 48%）和字号/颜色留在像素侧。覆盖缺口：colon_box 缺 23%（71/309 行）—— 缺的那部分才回退到现在的饱和度/冒号锚逻辑。逐项实测见 上游字段实测。

05

三个必须记着的坑

  • roi 不唯一：seg6 里有 2 条评论共用 [32,1398,700,1432]（另一条正文不同）。查表必须带上 username / content 或 t，不能只按 roi。
  • text_box 的右沿就是正文终点，但别把它当固定宽度：73 张实测框右沿比最后一个字多 4px（中位），从不越过字；可正文宽从 42px 到 216px 都有，所以只能逐行取 tb.x1，不能按常量推。另有 27 行的框跨两行（高度最高 150px），当行带用要先夹回 roi。
  • badge_box 覆盖一半：badge_text 有 72%，但 badge_box 只有 48% —— 有等级数字却没有药丸框的行很常见，擦药丸仍得回退到像素。

一句话

上游能替的是位置（上下沿、左沿、冒号、等级数字），不能替的是度量（颜色、字号、墨宽）。所以「换上游」只该换前一半 —— 白卡那个 bug 正好落在位置这一半上，换上下沿就能根治，不必动颜色与字号。

数据口径：sample-73（27 户 / 73 图 / 7 段），comments.jsonl 309 行、rows.jsonl 3,511 行；覆盖率按字段非空计。样例记录 seg6 · 冷___◆14-2/1.jpg。上游 = livepipe/tools/export_user_images 的导出产物。
