# livepipe 全流程说明

从一段直播录屏到「合格用户名单 + 交付图」，一共 **6 步**。本文按**实际跑过的顺序**写，每步给可直接照抄的命令、
产物、耗时/成本，以及踩过的坑。逐参数含义见 [CONFIG.md](CONFIG.md)，最小示例见 [examples/](examples/)。

```
① emoji_tables   建表情表（联网一次，建过就不必再建）
② panels         定位评论区 → **人工给每个面板填平台** → 面板文件
③ parse          OCR 抽行 → 表情识别 → 解析 → 跨帧去重 → 出评论 + 标注图   ← 最耗时的一步
④ filter         评论 → 合格用户（大模型判「正面」+ 用户名排除词）           ← 唯一花钱的一步
⑤ draw           把某时刻附近的框画到一帧上（可选，排查用）
⑥ export         合格用户 → 交付图（按平台分目录 · 每用户一文件夹 · 每条评论一张图）

—— 上面六步之外的**两个跨段步**（只有多段素材才用得上，`input.videos`；单段跑也无害）：
   qualify        各段的正面条数按**账号身份**合计 ≥N 才算合格 → 回写每段 users_qualified.jsonl
   collect        各段的导出目录按**账号身份**并成一棵交付树（图号跨段连续编号）
                  （身份默认是昵称；抖音 App 这种昵称打码的版式由平台档案的 account_key
                    改成 (昵称, 等级标 ◆N)，见 CONFIG.md 与 livepipe/account_id.py）
   一场直播切成几段录屏时，这两件事**必须跨段做**：各段自判会把「seg1 两条 + seg2 两条」
   的账号判掉两遍（静默掉出名单），同名账号也会出两个目录。见 CONFIG.md 的同名小节。
```

## 0. 前置

```bash
P=/home/puyu/anaconda3/envs/vlx/bin/python     # OCR / 模型走这个 env（rapidocr + torch + transformers）
V="/home/puyu/work/data/抖音奇瑞汽车/抖音视频号.mp4"
cd /home/puyu/github/LiveMonitorMockScale            # 所有相对路径都相对这里（= 配置里的 base_dir 默认值）
```

- **纯文本/配置校验**用 `python3` 就行（零第三方依赖）；**只要碰视频或模型**就得用 `$P`。
- **模型路线必须带离线变量**，否则 transformers 会卡在等 hub 超时（实测卡十几分钟）：
  `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1`。
- 输入是一段**录屏**（屏幕录制，不是下载的视频流）。画面里可以是并排的多个直播间窗口。

## 1. 建表情表（联网一次，之后可离线）

```bash
python3 livepipe/douyin_emoji_table.py --api   --out out/douyin_emoji    # 抖音官方 214 条
python3 livepipe/wechat_emoji_table.py --fetch --out out/wechat_emoji    # 微信 2021 新版 109 条
python3 livepipe/weibo_emoji_table.py          --out out/weibo_emoji --config  # 微博 config 自动建表 338 条
```

| 产物 | 内容 |
|---|---|
| `out/douyin_emoji/douyin-emoji.json` + `img/` | 214 条 token/name/hash + 214 张 lossless webp（**4.2MB**） |
| `out/wechat_emoji/wechat-emoji.json` + `img/` | 109 条 + 109 张 128px PNG（**2.0MB**）+ 核对图 `sheet_*.png` |
| `out/weibo_emoji/weibo-emoji.json` + `img/` | 338 条（`--config` 自动模式；`--include-parse-only` 可到 556）+ 338 张 PNG/GIF + 核对图 `sheet_*.png` |

- 几套表情**互不通用**：抖音是官方 webp（阈值 0.85），视频号是微信新版 PNG、微博是新浪图床的小位图
  （阈值都跟着表走）。
- 微博那张表的 **thresholds 是「部分标定」**（表里 `thresholds_calibrated="partial"`）：
  `min_score=0.82` / `min_margin=0.12` / `min_saturation=30` 已按「报警器」流程量过，但只有
  `[打call]` 一种字形交叉验证 —— 跑新素材前仍要复核；不对的表现是**静默丢光**或**满屏 `?[林致]` 假框**。
- 重跑安全：已下载的图会跳过。离线重建用 `--src <已有图目录>`（微博表的面板 DOM 与
  key→URL 解析表都在仓库里，所以它离线也能重建）。
- 表情是**锦上添花**：表不在只会降级（打警告），不会让主流程跑不动。

## 2. 定位评论区 → 人工标注平台（两阶段）

**为什么要人工**：定位只能说「这里有一片评论」，说不出「这是哪个平台」；而平台决定**行距 + 表情表 +
裁切策略**（填错整片认不出）。视频号的面板右边还跟着内容伸缩，不能靠固定值。

```bash
# ① 定位（用模型，一次；结果落盘）
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 $P -m livepipe panels cfg.json
#   → 产出 cfg.panels.file（默认 out/<dir>/panels.json），每个面板 "platform": null

# ② 人工打开那个文件，给每个面板填平台：
#      { "left":  { "rect": [...], "platform": "douyin" },
#        "right": { "rect": [...], "platform": "wechat" } }
#    可用平台 = 配置 platforms 段里的键（微博的档案写在 livepipe/征服8.json ⇒ 见第 1 节的 ⚠️）

# ③ 之后重跑：面板文件已存在 ⇒ 定位自动跳过，**不会覆盖你的标注**
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 $P -m livepipe run cfg.json
```

- 耗时：模型加载 ≈11s + 定位 ≈10s，**只跑一次**。
- 没填 `platform` 就往下跑会直接报错并告诉你填什么（不会静默用错平台）。
- 想重新定位：删掉面板文件，或配置里 `panels.overwrite: true`。
- 视频号评论很稀疏（实测 20 帧里 3 帧一条评论都没有）⇒ 取样窗别太短，否则**整个面板会被跳过**；
  范围会变就调大 `panels.auto.span`（多帧取并集）。

## 3. 解析：OCR → 表情 → 评论（最耗时）

> **这一节的时间大头是表情识别，不是 OCR**（实测 2560×1520 / 左右两面板 / 单进程）：
> 表情模板匹配 ≈4.9s/帧（68%）· RapidOCR ≈2.1s/帧（29%）· 抽帧 seek ≈0.2s/帧。
> OCR 引擎已调参（`use_cls=False` + 8 算子线程；实测无损），见 `parsing/ocr/engine.py` 的 `_rapidocr`。

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 $P -u -m livepipe run cfg.json
```

`cfg.json` 的关键几项（全片长跑）：

```jsonc
{
  "input":  { "video": "…/抖音视频号.mp4", "interval": 2.0,
              "sample": { "mode": "adaptive" } },               // 按内容抽帧：静止不白拍、快滚不漏条
  "panels": { "mode": "reuse", "file": "out/x/panels.json" },  // 复用第 2 步人工标注过的
  "output": { "dir": "out/x", "frames": false, "rows": true }  // 长跑务必关标注图
}
```

> **长跑强烈建议开 `input.sample.mode: adaptive`**（默认 `interval`）。固定 `interval` 是
> 「抽的帧数 = 时长 ÷ interval」，静止段在对着同一画面白拍、快滚时又可能漏条；`adaptive`
> 改按**面板内容的位移/停稳/入口**触发，只 OCR 触发了的面板 —— 静止段几乎不拍、滚动段一条不漏。
> 逐参数（`safety_rows`/`settle_frames`/`max_gap_s`…）见 [CONFIG.md](CONFIG.md)。

| 产物 | 内容 |
|---|---|
| `comments.jsonl` | 唯一评论（`username`/`content`/`emoji_text`/`roi`/`text_box`/`t`/`panel`/`badge_text`…） |
| `rows.jsonl` | 行序（`output.rows: true`）—— **回喂 `input.rows` 可复算，省一次 OCR** |
| `summary.json` | 统计 + 出图清单 + 定位/表情取证 |
| `frames/<t>_roi.jpg` | 逐帧标注图（`output.frames: true` 才出；`parse.colon_marks` 默认把昵称/正文之间的分隔冒号也圈出来） |
| `panels.resolved.json` | 面板经平台档案展开后的实际裁切窗口 |

> **`badge_text`（等级标 `◆N` 的读数）是跨帧凑出来的，不是「这一帧读到什么就是什么」。**
> 跨帧去重只留**一帧**来代表一条评论，而留哪一帧是按**正文清晰度**挑的（最早 / 抖动最小），
> 跟徽章有没有检出来无关 —— 所以 `dedup_comments` 会拿**同一条评论的其它帧**上的读数去补
> （同昵称 + 多数决，平票不补），`normalize_badge_alias` 还会把**并进昵称的那截药丸数字**
> 顺手记进 `badge_text`（`13白***` 的 `13`）。2026-10-14 实测 T7 七段：读数覆盖率
> **22.0% → 39.6%**（3399/8588 条唯一评论有读数）。读到的值**只补不改**（OCR 的直接读数证据更强）。

**先干跑看清要做什么**（不执行）：

```bash
python3 -m livepipe run cfg.json --dry-run      # 含还原出的命令行，可逐字对照
python3 -m livepipe check cfg.json              # 只校验配置
```

**跑完补标注图**（或改了解析逻辑后复算交付物，不重跑 OCR）：

```bash
$P -m livepipe run cfg.json --only parse        # 配 input.rows + output.frames: true
```

## 4. 评论 → 合格用户（唯一花钱的一步）

```bash
# 先估算调用量，别直接花钱
python3 livepipe/user_filter.py --comments out/x/comments.jsonl --dry-run

# 真跑（key 走环境变量，别写进配置文件）
NLP_API_KEY=sk-… python3 -m livepipe run cfg.json --only filter
```

规则：**用户名 ≥ `min_positive`(默认 3) 条正面评论**才算合格；「正面」由大模型**逐条**判定，
**表情一起发给它**（纯表情评论的 `content` 是空串）；用户名命中 `exclude_keywords` 的一律排除。

| 产物 | 内容 |
|---|---|
| `users.jsonl` | 合格用户 + **逐条判定**（label/内容/表情/时间/面板/ROI）—— 可一条条核 |
| `users.json` | 汇总：候选数/合格数/调用数 + **被排除的用户名** |
| `judgments.jsonl` | 判定缓存（重跑 0 调用） |

## 6. 导出交付图（按平台分目录 · 每用户一个文件夹 · 每条评论一张图）

管线里这是 `export` 步骤（`export.enabled=true` 时跟着 `run` 走）；直接调脚本等价：

```bash
$P livepipe/export_user_images.py --users out/x/users.jsonl
# → out/x/抖音/all_users_正面_3张以上/<用户名>-<条数>/1.jpg 2.jpg … + manifest.json + 正面账号.txt
#   out/x/视频号/all_users_正面_3张以上/…
```

- **按平台分目录**（`<平台中文名>/all_users_<标签>_<N>张以上/`）：平台由每条评论的 `panel`
  查 `panels.resolved.json` 得到。与参考交付语料
  `2-2026-06-17艾瑞泽8征服版上市/{视频号,抖音,微博}/all_users_正面_3张以上/` 同形。
- 每张图 = **整帧原图 + 该条评论一个绿框**：只圈这一条，**图上没有任何识别出来的文字/编号**
  （对齐参考语料实测：整帧不裁 · 绿框 RGB(0,255,0) · 线宽 3）。
- **框留白**：外扩量 = `max(--pad, --pad-ratio × 行高)`，默认 `0px / 0.25`（行高 29px ⇒ 外扩
  7px），外扩后夹在画面内（贴面板边的评论坐标越界时 PIL 会把那条边静默裁掉）。要参考语料那种
  **紧贴不留白**用 `--pad-ratio 0`；想更宽松就调大 `--pad` 或 `--pad-ratio`。
- 底图从**视频**按 `summary.json` 记的 `sample_mode`/`start` 取：`adaptive` ⇒ **顺序解码数
  计数器**（与抽行同一把尺子），`interval`/`backoff` ⇒ seek。**绝不把 adaptive 的行配上按 t
  seek 的取帧** —— 变帧率录屏上 seek 会漂（实测最多晚 218 帧），漂了框就画在另一时刻的画面上
  （bug-264）。要那套「带编号的标注图」用 `--base annotated`（调试用，不是交付形态）。
- 阈值默认**按平台各算**（`--min-scope platform`）：一个账号抖音 2 条、视频号 2 条，两个平台
  都不该被算成「正面账号 ≥3」，不够数的平台那一侧不出图（日志会点名这种账号）。
- `--labels`（默认 `正面`）/ `--min-positive`（3）/ `--flat`（不分平台）/ `--no-box` /
  `--color`/`--width`/`--pad`/`--pad-ratio` / `--limit` / `--dry-run` / `--force` 见 `--help`；
  `--selftest` 跑纯函数自检（纯 python3 即可，不依赖 Pillow/OpenCV）。

## 7. 撞库（名单 × 直播全量账号）

交付树出来后，拿活动方的名单撞一遍。**默认撞直播全量**：发过**任意一条**评论
（正面/负面/中性）就算，不管有没有达到交付阈值（≥3 张）—— 只撞交付树加 `--delivered-only`。

```bash
python -m livepipe match 撞库名单/10.31人名单.xlsx out/10.31              # 阈值默认 0.8
python -m livepipe match 撞库名单/10.31人名单.xlsx out/10.31 -t 0.9      # 更严
python -m livepipe match 撞库名单/10.31人名单.xlsx out/10.31 --delivered-only  # 只撞交付树
python -m livepipe match 名单.txt out/10.31 --platform 抖音              # 纯文本名单
# → out/10.31/撞库结果/
#     matches.json · 命中明细.csv · 未命中明细.csv · 撞库结果.xlsx · README.md
#     标记图/<平台>/<名单名>/<账号目录>/1.jpg …   ← 交付图原样复制（默认导出）
#     只在直播里、没进交付树的命中：按同样口径从视频原帧现补（顺序解码，慢但同口径）
#     撞库清单/<日期>_<场次>_<平台>.html          ← 给人看的交付清单（默认写，多平台另有 汇总.html）
#     只要表格不要图：加 --no-images；不要 HTML：--no-html
```

- **HTML 交付清单**：一平台一页，顶部 5 个 KPI + 人数/图片两条占比条，中间可搜索、
  可点表头排序的撞库用户名单，下面附未命中名单与口径说明。场次/日期自动从 `cwd` 里
  `output.dir` 指向本平台的配置取 `name`，`--title` / `--date` 可强制。
  清单不嵌图（只给「首图」链接指向 `../标记图/…`），几百 MB 塞不进一页。

- **名单**（`.xlsx` / `.csv`）里平台表头下面（或右边）是人名，例如
  `序号 | 抖音 | 序号 | 视频号 | 序号 | 快手`；布局 `--layout auto` 自己认。
  `.txt` 一行一个名字，用 `--platform` 指定平台。**按平台各撞各的**。
- **直播路径**是 `run` 产出的目录（`out/10.31`）。撞库账号 = 各段
  `<平台>/seg*/comments.jsonl` 按 (昵称, 等级标) 去重后的**全部账号**
  （发过任意一条评论就算，正负面不看；认人口径/排除词与 `filter` 同源）∪ 交付树
  `<平台>/all_users_正面_<N>张以上/`：同一人以交付树身份为准（保留账号目录），
  只在直播里的记 `in_delivery=False`；评论数/正面数按平台共用的
  `<平台>/judgments.jsonl` 判定缓存回填；没有 `seg*/comments.jsonl` 的旧产物
  退回 `seg*/users.jsonl`（只有正面评论的账号）。
  有多棵交付树（不同阈值）用 `--tree` 指定。
- **匹配度**先归一化名字（NFKC、忽略大小写、去空白/零宽；标点/数字/emoji 保留），
  默认 `--metric partial` 容忍昵称截断（`期待`↔`期待sj`、`喜乐哥`↔`喜乐哥554`）。
  直播全量账号上千，防误撞：短名做前后缀时多余那段是汉字就只按整体 ratio 算
  （`用户`↔`用户6758305` ✅、`天后`↔`明天后天` ❌）；夹在中间的片段只对 ≥3 字的短名做窗口比。
  阈值只决定算不算命中，**没命中的名单名也留在 `未命中明细.csv`**（带最近账号与分数）。
- 一个名单名可命中多个账号（同名不同等级标、OCR 近似档），报告全部列出；
  `--max-matches`（默认 5）封顶。
- 读 `.xlsx` 需要 openpyxl；csv/txt 与匹配本身零第三方依赖。

## 量级与成本（全片实测：6294s 视频 / interval=2.0 → 3147 帧）

| 步骤 | 实测 | 备注 |
|---|---|---|
| 建表情表 | 联网一次 ≈1 分钟 | 建过就跳过已下载的图 |
| 定位 | ≈21s（模型加载 11s + 定位 10s） | 只跑一次，人工标注后复用 |
| **解析 OCR** | 3147 帧 × ≈6.2s ≈ **5.4 小时** | 单进程；关标注图 |
| 出标注图 | 3147 张 ≈ **14 分钟 / 1.7GB** | 单独补跑 |
| **过滤（LLM）** | 6866 条评论 → **74 次调用 / 137 秒** | 预筛 + 去重后；合格 256 人 |

- 解析时间 ≈ 帧数 × 6.2s。默认 `interval` 下 **帧数 = 视频时长 ÷ interval**；改
  `input.sample.mode: adaptive` 后**帧数由内容决定**（静止段几乎不拍），实测滚动 3s + 静止 27s
  的一段是 **4 帧 vs 固定间隔的 15 帧（少 73%）**。想更快又不想漏条，**用 adaptive，而不是调大
  `interval`**（调大 interval 省的是帧、代价是漏掉短命的评论）。
- 过滤的调用数 ≈ 去重后条数 ÷ `batch_size`；**先 `--dry-run` 看数**，用 `nlp.limit` 硬卡上限。

## 断点 / 复算（长跑必备）

| 想干什么 | 怎么做 |
|---|---|

## 排错

| 症状 | 原因 / 处置 |
|---|---|
| 加载模型卡住十几分钟 | 少了 `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1` |
| `还没填 platform` | 第 2 步的面板文件没标注，打开填 `douyin`/`wechat`/`weibo`（微博档案是配置里的 `platforms.weibo`，本 checkout 见 `livepipe/征服8.json`；别的配置得把那一段抄过去，或退回 `--emoji-table comments=weibo`） |
| 重新定位把人工标注冲掉了 | 不会 —— `panels.overwrite` 默认 false；除非你显式打开 |
| 某个面板整片没数据 | 定位取样窗太短，那几帧里它一条含冒号的行都没有 ⇒ 调大 `panels.auto.span` |
| 某一屏全是 `?`（表情认不出） | 平台填错了（两代表情表互不通用） |
| 长评论尾巴读错字 | 面板右边跟着内容伸缩 ⇒ 该平台的 `x2_from` 要设 `window` |
| 标注图里表情在框外 | `parse.right_pad` 要是 0（贴面板边） |
| 磁盘被吃满 | 长跑关 `output.frames`（3147 张 ≈1.7GB） |
| 过滤花了钱却没人合格 | 阈值太高 / 评论太少：先 `--dry-run` 看候选人数 |
| `adaptive` 重复评论偏多 | 触发太密：调大 `settle_frames` 或 `safety_rows`（≤5），或把 `max_gap_s` 设 0 |
| `adaptive` 疑似漏条 | 触发太稀：调小 `settle_frames` / `safety_rows`；确认平台 `row_pitch` 填对（行距错 ⇒ 位移按行算就错） |
