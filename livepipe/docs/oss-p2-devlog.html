链路：本地写、任务边界同步

结果不直写 OSS：小文件直写只有 10–13 个/秒，长文件 append 也不可控； 任务产物先写本地，收尾时整体同步一次。

阶段谁做动作
1. 跑livepipe runner产物写 <batch>/out/<场次>/<平台>/（本地）
2. 收 / 回传batch_local / batch_remote复制 / rsync 到 <local_out_root>/<场次>/<平台>/，按字节核对
3. 结果同步oss_sync.py 大小相同跳过；不同则直接写 OSS 正式名；可开 SHA256
4. 登记批处理 state oss_state=synced + 文件数 / 字节 / 上传与跳过数

工具行为

项行为
增量判据目标存在且大小相同 → 跳过；--sha256 再比内容哈希
跳过项符号链接（goofys 不支持）、. 开头的文件/目录、 *.part / *.lock / *.failed；可 --exclude / --include-hidden
写入直接写正式名，close 后核对字节；失败重试 3 次并清理旧 .part（结果文件小，失败可重跑）
并发默认 4；goofys 小文件元数据瓶颈，再高不提速
模式--dry-run / --verify-only （严格核对多出文件，--allow-extra 放宽）/ --report
机读结尾一行 OSS_SYNC_RESULT {json}；批处理据此登记

行为说明
自动同步transfer_task 核对通过后立即调用； 失败不会把任务打回 transfer_failed，本地产物仍有效
--oss-only只处理 state 里已 transferred 的任务；--force 重新核对（同尺寸仍跳过）
state 字段oss_state / oss_dst / oss_files / oss_bytes / oss_uploaded / oss_skipped / oss_at
落点推导任务级 oss_result 优先；不写则按 local_out 相对 local_out_root 镜像

没有做什么

  • 没有让 batch_remote 真连服务器：回传后的同步走的是同一段本地逻辑与 同一套字段；离线自检覆盖，真实 SSH 队列未在本次跑。
  • 没有改 P1.5 的读路径：结果同步只写 直播产生结果，录屏输入路径不变。
  • 没有删本地结果：P4 影子期结束前保留本地副本。
  • 没有打包交付树：小文件逐个同步；如果后续任务对象数到 1 万以上，再评估 「交付树按账号打包」。
  • 没有提交 git：仓库内脚本/文档留在工作区；批处理脚本在 ~/脚本/ssh/，不在仓库内。
