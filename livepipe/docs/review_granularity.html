复核按条，还是按整帧？

两种口径都不免费。逐条保住全部 14,202 个框，代价是 914 个「有读数没坐标」的等级标在训练时算背景； 整帧全或无消灭这些假负，代价是连坐丢掉 4,206 个正确框。下面把两边的账都算出来，再说清楚在什么条件下谁更划算。

01 · 先分清

训练图早就是「整帧全标」，逐条只是人审的单位

数据集里一张图 = 一整帧原图（720×1600，不裁），同一帧上的每条评论各出 1–5 行标签，全都写在同一张图上。 中间那一步人才是按条看的——因为「删」这个动作必须能表达「只这条不要」。

02 · 等级标

等级标不是「不处理」，是「不编」

量到框就写；只读到数字、没量到位置的，宁可不写一行标签，也不按邻居位置猜一个框—— 猜出来的框会把误差写进训练集，而且恰恰写进最难的那批样本。

03 · 账本

同一批标签，两种口径各剩多少

训练侧怎么处理「无框区域」

Ultralytics 的 YOLOv8/11 没有 ignore 标记：没有被 GT 匹配上的锚点一律按背景算负样本。 所以漏标在训练里不是被跳过的，是被当成负例用的。五种处理方式，代价各不相同：

做法怎么落地代价原生支持
① 当背景（现在）什么都不用做914 个等级标成为负例；这一类的难例召回偏低YOLO 默认行为
② 像素遮挡按推算位置把等级标涂掉破坏 0.024% 的真实像素；位置本身还不准离线脚本
③ 补标用 badge_left / 邻居位置推一个框914 个框带定位误差，等于换个方式把误差写进标签改上游解析
④ ignore 掩码损失里跳过该矩形内的锚点要改 assigner / loss；YOLO 不原生支持mmdet / Detectron2 原生
⑤ 整帧丢整帧全或无4,206 个正确框一起没（见 §03）现成

← 横向滑动看全部

一个缓解事实：914 个假负全部落在已标注的 comment_row 框里。 YOLO 的对齐指派会把这些锚点按对齐度分给 comment_row 正样本，真正落到「背景」的只是其中一部分—— 所以整体 mAP 常常看不出问题，代价主要记在 level_badge 的难例召回上。
所以现在选 ① 是划算的：0.024% 像素的假负，换 14,202 个框和 0 个连坐。 但要把 level_badge 的 recall 单列监控；如果它是硬指标，先修上游的框检测（914 条是量框失败， 改标签治不了），再考虑 ③/④，而不是 ⑤。
05 · 触发条件

整帧口径的损失，是触发规则的函数

「一个标的不对」到底算哪些？触发越严，整帧丢得越多；只认一半，损失就从 29.6% 降到 15.7%。 §03 那个 70.4% 不是整帧口径的固有属性，是最严触发下的下限。

← 横向滑动看全部

75%/50%/25% 三行是「只有一部分缺框被认作错」的期望值（按每帧缺框数独立计算）；q 两行由真实的每帧评论数分布推算。

换成可执行的判据：决定权在两个可测量的量——触发率 p（多少评论被判「标不对」） 和拥挤帧占比。这张数据表上，p ≥ 20% 且拥挤帧占 28.4% 时，整帧口径要丢掉三成以上的标签， 而逐条口径的假负只有 0.024% 像素、32.2% 的一个类实例。反过来，如果哪批素材的缺陷率降到 5% 以下、 且几乎都是单条帧，整帧口径的损失会缩到 ~9%，那时它才值得作为一个选项拿出来比较。

07 · 训练

两种口径各自错在哪

逐条的错是「漏标成负例」，整帧的错是「连坐删监督」。前者的代价在 §04 量过（914 个实例、0.024% 像素）， 后者的代价在 §03 量过（−29.6% 框）。这里说的是，为什么后者通常更贵。

  1. 检测的损失是逐框算的。

    缺一个框，只让那一个目标在分类头里落成负样本；帧里其余框的回归和分类监督完全正常。整帧丢弃等于把正确的监督一起删掉，用一个局部错误换掉一整帧信号。

  2. 样本量先掉三成，框掉三成。

    train 图 1,904 → 1,275（−33.0%），框 9,766 → 6,444（−34.0%）。检测模型在小样本上对「少 600 张图」的敏感度，通常比「每 5 个框里有 1 个漏标」更高。

  3. 丢掉的恰好是拥挤帧。

    被删的帧 39.7% 是多人同屏，留下的只有 24.0%。真实直播一屏 2–6 条是常态，模型最该学的是「一屏多条、框要分开」；整帧口径把这个分布削薄了。

  4. 等级标的选择偏差。

    触发删除的是「读数在、框没量出来」——遮挡、低对比的难例。整帧口径下它们被删，留下的等级标全是好读的：带等级标框的评论占比从 45.6% 升到 56.7%。模型在难例上的召回只会更差。

  5. 验证集被悄悄变简单。

    test（微博）一条不丢，val 却丢了 174 帧（−33.5%）、884 个框（−33.7%）。val 与 test 的难度不再一致，用 val 选模型会系统性高估，上线才发现拥挤场景掉点。

触发条件换成人判错误时

整帧口径的保留率随触发规则变化：q = 5% 时保留 91.0%，q = 10% 时保留 82.8%（完整表见 §05）。 也就是说，上面四条判断成立的前提是「标签缺陷多、且集中在拥挤帧」；缺陷率降下去，整帧口径的代价也跟着降。

A/B 已经跑完（§10），上面的推断基本被验证。账本（§03–05）是实测的；训练上的判断里， 「整体 mAP 更低」「拥挤帧掉得更多」都成立，「难例召回更差」方向也成立（但难例子集只有 64 个 badge 框）； 唯一反转的是 level_badge 的聚合 recall —— 整帧在保留的易读帧上更高，因为缺框难例被整批删掉了。 这恰好也是「验证集被悄悄变简单」那条的直接证据。
08 · 建议

保持逐条；整帧作废留一条命令

删除单位 = 标签单位，这是唯一不会连坐的口径。人若真判定某一帧全废，也不必一张张删——用命令一次丢掉该帧全部评论。

  1. 默认逐条复核。

    删哪条丢哪条；等级标已不进数据集，不再需要为它单独挪文件。

  2. 整帧全废时用 --reject-frame。

    给帧名（<视频键>_f<帧号>），这一帧的全部评论一起记进 rejected.jsonl，幂等，和手删每张横条完全等价。

  3. 等级标缺框不再写进数据集。

    2026-10-29 起 level_badge 这一类整体移除：914 个缺框实例、0.024% 像素的假负不值得用一类标签去换。要恢复，先修上游的框检测，再把 (level_badge, badge_box) 加回 common.CLASSES。

  4. 只有当缺陷率低到 5% 以下时，再回头看整帧口径。

    那时它的损失从 29.6% 收到 ~9%，和逐条的差距变小；这也是 §05 那张表真正的用法——先量触发率，再选口径。

§10 的 A/B 没有推翻这个建议。整帧口径在五组评测上的整体 mAP50–95 全部更低； 它对 comment_row 的伤害在拥挤帧上最明显（recall 90.8% → 59.6%）。保持逐条，--reject-frame 只作为人工整帧作废的出口。

import pathlib
from livepipe.tools.dataset.sources import scan_runs, units_of, frame_groups
from livepipe.tools.dataset.common import DEFAULT_SPLIT_RULES, normalize_split_rules, frame_name
sides = scan_runs(["out/风云T7_20260826_11", "out/风云T7_20260826_11_02", "out/征服8"],
                  exclude=["风云T7_20260826_11_02/seg7"])

recs = [r for u in units for r in u.recs]
lab = sum(1 for r in recs if r.row.get("badge_box"))
unl = sum(1 for r in recs if r.row.get("badge_text") and not r.row.get("badge_box"))
print(f"逐条假负：{unl} 个等级标 / 可见 {lab + unl} = {unl / (lab + unl):.1%}")
bad = {frame_name(u.vk, u.frame) for u in units
       if any(r.row.get("badge_text") and not r.row.get("badge_box") for r in u.recs)}
tot = keep = 0
for p in pathlib.Path("out/dataset_v1/labels").glob("*/*.txt"):
    n = len(p.read_text().splitlines()); tot += n
    keep += 0 if p.stem in bad else n
print(f"整帧全或无：丢 {len(bad)} 帧，保留 {keep}/{tot} 框 = {keep / tot:.1%}")

判定：保持逐条。五组评测里，整帧口径的整体 mAP50–95 全部更低；拥挤帧的 comment_row recall 从 90.8% 掉到 59.6%，与 §07「整帧优先删拥挤帧」的推断一致。整帧唯一的稳定优势是 precision（+5.4pp）和易读帧的等级标 recall（+4.9pp）—— 代价是 train 少 33% 帧。
预注册预测分两半。「拥挤帧掉得更多」成立；「level_badge 难例召回更差」 方向成立但证据弱：被丢弃的 174 帧上 21.9% → 18.8%，只有 64 个 badge 框；完整 val 的聚合 badge recall 反而 +4.3pp，因为 B 在保留的易读帧上更高。这正是 §07「验证集被悄悄变简单」的直接证据。
结论强度。train/val 100% 抖音、test 100% 微博，两臂 test mAP50 只有 0.011–0.029， 主判据在 test 上没有区分力；colon 类两臂全 0（中位框 10×12 px，640 输入下约 4×5 px），五类均值被拉低； 单 seed、每臂一次，<1pp 的差异不能当结论。要真正比泛化，需往 train 掺微博或另划抖音留出集。
