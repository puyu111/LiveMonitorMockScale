开发中发现并修掉的问题

全部由真实运行暴露，不是纸面推演。

现象根因修法验证
--selftest 崩溃 ingest 默认允许无时长收尾，与 README/用例相反；断言失败后 .part 已被改名，后续报“文件不存在” 默认要求有效时长，新增 --allow-no-duration 自检 310 项全过
三个自检套件全红 missing 口径、sync 默认哈希与用例各说各话 统一 missing/local_missing 口径；sync 默认只比大小并改文档 三套件全绿
默认根审计报 82 缺失 默认根 奇瑞汽车/直播看管 下只有空的结果目录 按候选顺序自动选真实录屏根并打印实际根 不传 --oss-root 得到 53/27/2
10-19 六个裁尾 trim_s=null 文件名没有 _<start>-<end> 时直接放弃 用已探到的时长回退成 [0, duration] seg5 → [0, 5455.716]
入口 usage 名不对 python -m livepipe oss 没把 prog 传进 parser main(prog=...) + 入口显式传入 usage: python -m livepipe oss
P1 目标路径丢事件目录 生成脚本一度把索引根放宽到整棵 直播data/录屏（412 个对象） 两批各自用事件根（50 / 30 个可用对象），dst 用父根 + 事件目录拼 29 行 dst 含事件目录，跨事件零碰撞
默认根 audit 要 4–5 分钟 建索引时对每个 OSS 对象都跑一次 ffprobe 改成惰性探测：只有同尺寸多候选时才探，结果缓存 22 配置从约 4 分钟降到约 5 秒（本次 5.1s），输出不变
0 字节百度云临时文件被算进索引 scan_oss_entries 只按扩展名过滤，统计 51，映射引擎实际 50 复用 is_temp_name + 跳过 0 字节；两批改为 50 / 30，共 80 coverage.total_indexed_videos=80，映射数字不变
补传后 55/0 反而 EXIT 1 脚本只认 P0 基线（53 整段 / 2 缺失 / 29 行），P1 完成后被判“多出 2 段” 同时接受 P0 与 P1 基线，acceptance.phase/state 按实际数字自动切换 P1 稀疏镜像实跑：55/0/27、27 行、40,069,546,585 B，EXIT 0
裁尾配置遇空 OSS 根也报 PASS 裁尾段只校验本地 _live，audit 的 PASS 文案不说明范围 PASS 文案改为“清单完成：…… N 段裁尾副本不在本次检查内”；P1 落盘用 --verify-uploads 空根 + 2 裁尾：PASS 带范围说明；--verify-uploads 缺 27 → EXIT 1
verify-media 探不到时长仍返回 0 没有时长直接打印 PASS，损坏成品 / 非视频也通过 默认 UNKNOWN + EXIT 1，新增 --allow-unknown-duration 自检新增 2 项：无时长 1、加标志 0
CSV 交接信息不全 只有 src/dst/bytes/duration/trim/kind，~ 未展开，看不出哪条为什么传 加 config/seg/note/src_abs 列，note 说明两类目标；BOM 用途写进 README 29 行、10 列；dst 仍可被脚本直接解析
显式 --oss-root 写错只报全量缺失 resolve_oss_root 对显式路径不查存在性 strict 模式要求目录存在并提示检查挂载；check-env 仍走非 strict 假路径 → “显式 OSS 根不存在”，EXIT 1
兜底解析丢自定义段名 配置加载失败时 input.segment_names 被忽略，清单退回 segN 兜底读取同一字段（长度不符才退回 segN） JSONC 兜底用例：段名“开场”保留
把两个事件根传成同一个父根 两批对象落进同一候选池，跨事件同字节视频可能互相误配；索引对象也从 80 涨到 412 默认就用两个事件根；脚本入口校验两个根相同或互相包含时直接退出 2 同根运行 EXIT 2；默认运行 5.4s，产物与冻结版 diff 为空

关于早前出现过的 236s：那是 21:40 前的旧脚本 （单一公共根 + 全量 ffprobe）在多 agent 并发时的首轮数字，已被当前默认路径 （两个事件根 + 惰性探测，5.1s）取代，不再引用。
