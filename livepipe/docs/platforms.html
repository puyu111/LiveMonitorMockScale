一套流水线，五份版式档案

读图三条规则

  • 徽章在左还是在右，决定折行能不能靠形状认：左边有徽章列，续行必然更靠左。
  • 右沿跟内容还是跟窗口，决定会不会裁内容：面板宽度会变，就只能取窗口。
  • 正文起 x 取哪条边，决定药丸是被丢掉还是被并进昵称：取药丸右沿，续行才会归到正文。

几何闸

两个阈值决定干净与否

这两个数都是版式事实，只能写在档案里。自标定会留一行日志当证据，但不覆盖手写值。

浮层只在一部分时间出现。分段 1 的商品卡 t≈314–370 才出现，而自标定只 OCR 开头 4 帧； 浮层最左那块还会飘 1px（标到 479、实测 478，1px 之差决定 4 条评论干不干净）。所以这个数写死，不交给自标定。
overlay_cards 的两种写法：true 只用内置短语表； 写成字符串 = 内置表 + 本素材才有的词（品牌名只能写在这里，放进内置表就是拿品牌名赌内容）。 开它还会带上跨帧判据「列表滚了它没动」；跟着列表一起滚的横幅认不出，只能写短语。
认人

打码昵称只能靠等级标分开

account_key 只在交付这一层生效：username 只看昵称， nickname_level 按（昵称、等级标）认人。抖音 App 昵称打码成 1___、 好___，五个人可能同名。

读作 1___ + ◆12 → 1___◆12-3
读作 1___，没读到等级 → 1___-9
读作 8___ + ◆2 → 8___◆2-5
目录名里 * 换成 _，末尾 -N 是去重序号。等级标没读到的那些单独成组， 不会再被并进同名账号。身份只有一处实现：livepipe/account_id.py；其余平台用 username，不受影响。

接入

加一个平台要量什么

顺序不能省：先量网格，再判版式事实，最后才配浮层和表情。

  1. 量行网格

    在录屏里量行距、首行相位、正文起始 x。先用兜底值跑一段，再看 parse.calibrate 的日志复核。

  2. 判三个版式事实

    徽章在左还是在右、折行贴左沿还是缩进、正文 x 该取药丸左沿还是右沿。它们决定 rank_pill、 wrap_at_text_left、x_text，猜错整片认不出。

  3. 判浮层

    跟着列表滚的写短语（overlay_cards），不跟着滚的靠冻结判据；压在评论列右边的量空带，写 x_ignore_from。

  4. 选表情表、量阈值

    表情是哪个源就用哪张表；换源要重量高度比与 looks_like，不能照抄。

  5. 写档案、接引用

    platforms 加一条，面板文件填这个档案名，PLATFORM_CN 加一行。

  6. 先切片，再全量

    挑 90 秒有浮层、有折行的片段跑一遍对图；确认没有卡行、没有截断，再跑全片。
