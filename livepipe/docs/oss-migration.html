目标：OSS 单一副本，本地只留一个任务

录屏只存 OSS 一份，dypy 的直播下载输出直接指向 goofys 挂载点：先写 <名>.part，关闭后校验大小与时长，再 rename 成正式文件。计算节点通过 goofys 只读访问；结果先写本地 NVMe，任务完成后按文件大小和校验和同步到 OSS。这样下载不再落本地再传一遍，结果又避开了 goofys 小文件慢、长文件缓冲不可控的问题。

为什么录屏直写、结果不直写

录屏是单个 3GB 顺序写，goofys 实测 9.4–12.5MB/s，直写不会多一份副本；128MB 文件 rename 只要 0.15 秒，所以 .part 收尾很便宜。结果是一个任务约 6,000 个小文件，直接写只有 10–13 个/秒，要多花 8–10 分钟；更麻烦的是 rows.jsonl 逐帧 append，长文件持续 flush 的请求放大没有实测边界。所以结果先落本地、完成即同步。

2026-11-19 实测修正：用户要求结果也不落本地。已把探秘局两份配置的 output.dir / collect.out 指到 OSS；20s 切片直写 rows/frames/comments 全部正常，写+flush 不触发整文件重传。真正的坑是 goofs 不支持 open("a")： rows.jsonl 续跑已改为重写已有行；小文件逐张写仍比本地慢（约 10–13 个/秒）。

录屏由 dypy 直接写挂载点。唯一要求是输出路径落在 OSS 上，扩展名先写 .part；收尾脚本再改名并登记清单。

# dypy 的下载参数以它自己的 --help 为准；这里只约束 --out 的落点
OSS=/home/puyu/oss-bucket/web/1/奇瑞汽车/直播看管
dypy 直播 <参数> --out "$OSS/直播录屏/$EVENT/$DAY/$PLATFORM/$ACCOUNT/$NAME.mp4.part"

# 收尾：close 后校验 size / duration，rename 成正式名，写 manifest
python3 -m livepipe oss ingest --src "$OSS/直播录屏/$EVENT/$DAY/$PLATFORM/$ACCOUNT/$NAME.mp4.part" \
  --event "$EVENT" --day "$DAY" --platform "$PLATFORM" --account "$ACCOUNT"

配置改动很小：base_dir 继续指向本地（表情表、临时文件不动），只把 input.videos 和 output.dir 写成 OSS 绝对路径。用 10-01 视频号做探针，把 seg3 指到对应整段后，4 段 OSS 路径通过 livepipe check；裁尾副本已补传，切读时按原配置就能切换。

环境基线：任意机器都能复现

程序不假设固定在本机。下载机、计算节点、评审机只需要 Python 3.8+、FUSE3、bypy 1.8.9 和 goofys 0.24.0，以及两个凭据目录。bypy 管百度网盘，goofys 管 OSS，两者不要混用。

角色需要装什么拿什么数据
下载机dypy、bypy、goofys直播直写 OSS；百度 /直播录屏 拉取
计算节点goofys、conda 环境（rapidocr / torch）只读 OSS 录屏，结果写本地 NVMe
评审 / 撞库goofys只读 OSS 结果与返图

bypy：百度网盘侧

  • 本机 bypy 1.8.9；配额 14.103TB，已用 1.479TB。远端 /直播录屏 已有 10.20上午、10.20下午、10.21–10.25、11.10、11.12风云T7直播。
  • 安装：python3 -m pip install --user bypy==1.8.9；首次 bypy info 按提示授权。
  • 批量机器：直接复制已授权的 ~/.bypy/bypy.json（0600），不要进 git。
  • 拉取（2026-11-19 起）：scripts/oss_download.py baidu --remote /直播录屏/<目录> --dest-rel <OSS 相对目录> 直写 OSS；按 PCS Range 顺序流式写 .part，--resume 断点续传。
  • 边界：bypy 不是 OSS 客户端；它的 20MB 分块下载在 goofys 上大文件会失败。百度来源改由 scripts/oss_download.py baidu 用 bypy 授权/列目录、PCS 单请求 Range 顺序流式直写 OSS（不落本地暂存），失败保留 .part 可续传。

goofys：OSS 侧

  • 本机是 23MB 静态二进制，0.24.0；依赖 /dev/fuse 和 fuse3（本机 3.18.2）。
  • 凭据放 ~/.aws/credentials 默认 profile，chmod 600；不要把密钥写进配置 JSON。
  • 挂载：goofys -f -o allow_other --endpoint http://oss-cn-beijing.aliyuncs.com --subdomain static-cantotimes-com ~/oss-bucket。用 allow_other 时要在 /etc/fuse.conf 打开 user_allow_other。
  • 远端无 GUI：scp 凭据目录 + systemd 托管；不要再用明文 SSH 密码。
#!/usr/bin/env bash
set -euo pipefail

# 1) 系统依赖（Debian/Ubuntu；其它发行版换成 dnf/yum）
sudo apt-get install -y fuse3 python3-pip

# 2) goofys：静态二进制，无运行时依赖
curl -L -o /tmp/goofys \
  https://github.com/kahing/goofys/releases/download/v0.24.0/goofys
sudo install -m 755 /tmp/goofys /usr/local/bin/goofys

# 3) bypy
python3 -m pip install --user bypy==1.8.9

# 4) 凭据：从受控位置复制，chmod 600，绝不进仓库
install -D -m 600 /secure/bypy.json      ~/.bypy/bypy.json
install -D -m 600 /secure/aws_credentials ~/.aws/credentials

# 5) 挂载 + 自检（systemd 里同样用 -f）
mkdir -p ~/oss-bucket
goofys -f -o allow_other --endpoint http://oss-cn-beijing.aliyuncs.com \
  --subdomain static-cantotimes-com ~/oss-bucket &

bypy info
findmnt -T ~/oss-bucket

同步规则

  • 只按内容判断：目标存在且大小相同则跳过；关键批次再比 sha256。不要用 mtime，goofys 会丢。
  • 排除项：软链、*.lock、*.part、正在写的临时文件。软链树留在本地，或重建成真实目录再上传。
  • 失败策略：单文件重试 3 次；仍失败就留下本地文件和 *.failed 标记，不阻塞其他文件。上传完成后才允许删除本地。
  • 并发：大文件 2–4 路；小文件先打包成 tar/zip 再传，避免 10 个/秒的元数据开销。

入库脚本只做收尾：python3 -m livepipe oss ingest --src <OSS .part 路径> --event … --day … --platform … --account …，负责 close、校验、rename、manifest。dypy 的直播下载参数不写死在这层里，换下载器只改 wrapper 的第一段。
