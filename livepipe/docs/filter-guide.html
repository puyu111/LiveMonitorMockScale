livepipe · 直播评论清洗

句子过滤的四个入口

直播里混着界面公告、顶部通知、系统动作和评论正文里的广告。它们由不同的层负责拦；加错地方不会生效。这张页把四个入口、判定条件和真实数据放在一起。

①② 两个在配置里 ③ 一个在内置表 ④ 正文过滤还没有口子

先记一句：没有冒号的行，是界面句；有冒号的行，是评论。所有过滤都绕这条分界。

配置都在 风云A9L.json 的 platforms.<档案> 下；内置表在 livepipe/parsing/text/notices.py。

顺序是代码里的真实顺序：先剥粘在行首的通知，再判整行要不要丢，最后才切用户名和正文。

② 在切分之前跑；①③ 只认没有冒号的行；④ 还缺口子。

四个入口，逐个说

①

界面句、公告、浮层卡

风云A9L.json → platforms.douyin_app → "overlay_cards"

取值是正则片段（| 分隔），也可以写 true 只用内置表。只对没有冒号的行生效：命中整行丢弃，并顺带丢掉紧跟其后的那一行（浮层卡折行后的续块）。

// 追加句子直接往后接，正则元字符记得转义
"overlay_cards": "非主驾开播|吸烟酗酒|低俗色情|人身财产损失"
                 "|严禁未成年人|诱导打赏|新车型上市|点击预约"

真实例子

视频号「奇瑞QQ」seg1 的 rows 里，68 行没有冒号且命中上述短语，例如 非主驾开播请注意驾驶安全公众号奇瑞QQ>、2027款风云A9L全球真C级旗舰。风云T7 的开关差分：同一段 150s 切片只差这一个键，评论 13 条 → 5 条，去掉的 8 条全是浮层卡，真评论一条没少。

别混右侧商品卡走的是几何闸 x_ignore_from，不是句子匹配。抖音素材的商品卡文字左沿实测 477，所以配 460；它比 overlay 更早一步生效。
注意只能写素材专属的词；通用 UI 词进内置表要按项目惯例在既有语料上逐条 diff。改完用 rows 复算，不需要重跑 OCR。
②

粘在昵称左边的顶部通知

风云A9L.json → platforms.douyin_app → "notice_prefix_strip"

OCR 有时把顶部通知和第一行评论并成一句。这个键是正则：短语出现在行首 12 字符内、并且剥完剩下的部分还有冒号时才动手——保证剥的是通知、留下的是评论。

"notice_prefix_strip": "开播请注意驾驶安[全金]"
// 安全 → 安金 是实测的 OCR 变体；新通知改这段正则即可

真实例子

视频号「奇瑞QQ」seg1 有 327 行带这种粘连，例如 非主驾开播请注意驾驶安全感激：家用车，靠谱最重要、粉丝鱼非主驾开播请注意驾驶安全鱼丸：第一次看这款车多了解一下。开启后这些行的用户名恢复正常；复算后的交付树里，非主驾开播… 这类假账号为 0。

边界没有冒号的通知行不归它管——那是 ①③ 的活。剥完只剩通知本身时它也不动，交给整行丢弃。
③

系统动作行

livepipe/parsing/text/notices.py → _NOTICE_RE

抖音自己发的通知：赞了直播、为主播点赞、入了直播间、关注了主播、送出了…、在线观众 等。和 ① 一样只认没有冒号的行。

_NOTICE_RE = re.compile(
    r"赞了直播|为主播点赞|入了直播间|关注了主播|送出了?"
    r"|在线观众|贡献用户|高等级用户"
)

真实例子

视频号「奇瑞QQ」seg1 有 17 行命中内置短语；抖音 seg1 有 10 行。内置表已知漏 分享了直播：风云T7 的 150s 切片 5 条里漏 1 条（贝***分享了直播），111 条样本里漏 5 条。

做法素材里遇到漏网的系统句，先写进 overlay_cards（素材级、零风险）。动 _NOTICE_RE 要走语料 diff，别为一个素材改全局。
④

评论正文里的句子（还没有口子）

现状：没有配置键；filter.exclude_keywords 只筛用户名

如果广告、抽奖、私信话术出现在有冒号的评论正文里，现在的 overlay_cards 和 _NOTICE_RE 都不会碰它——它们只处理没有冒号的行。想要按正文丢掉，需要加一个显式的 opt-in 键，作用在切分之后。

// 提议的新键（尚未实现）：只对写了它的平台生效
"parse": {
  "drop_content": "加微|私信|抽奖|点击下方链接"
}
设计实现时会按项目惯例做成默认关：匹配即丢整条评论、日志里记丢了多少条；因为它会直接减少交付评论数，需要先在切片上对比。把要过滤的句子清单给我，可以按这个口径加上。

改完怎么验证

1. 只用现有行复算（不重跑 OCR）

python -m livepipe run 风云A9L.json \
  --only panels,parse

过滤发生在 parse 阶段；<段目录>/rows.jsonl 已在时是零 OCR 复算。抖音两段约 5–6 分钟（主要是重画标注图）。

2. 看句子和数量

grep -c "新车型上市" \
  out/…/抖音/seg1/comments.jsonl   # 期望 0

再对比过滤前后的评论数（日志里的「=> 解析: N 条评论」）。过滤只减评论，不改用户名。

顺序过滤会改变评论集合；如果这批产物已经出过交付，要按顺序重跑 --only filter,qualify,export,collect（判定缓存可复用大部分），否则名单和交付图对不上。
数据来自 2026-11-01 的风云A9L / 风云T7 实测：视频号「奇瑞QQ」「风云新能原」、抖音 seg1/seg2。 入口定义见 livepipe/parsing/text/notices.py、livepipe/parsing/layout/paragraphs.py；配置示例见 风云A9L.json。
