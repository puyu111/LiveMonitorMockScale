# cerebrum — 偏好 / 经验 / 别再犯

## Preferences（用户偏好）

- 说中文；代码注释、日志、自检输出都用中文。
- 「标记图」= **不加字**：交付图本身就是「整帧原图 + 该条评论一个绿框」，不要往上写名字/分数/编号。
  （2026-11-06 明确选择「原样导出不加字」。）
- 撞库范围要**全**：不能只看交付树（≥3 张），发过**任意一条**评论（正面/负面/中性）的人
  也要能撞出来（2026-11-09 用户明确：「池子不按正面评论，按全部评论」）。
- 文档要随功能同步改：`livepipe/README.md`、`livepipe/全流程说明.md`、`tools/<名>/doc.py`。

## Learnings（项目经验）

- 交付树只是「合格账号」视图；**直播全量账号在 `seg*/comments.jsonl`**（parse 产物，全部评论，
  撞库池子就用它）；`seg*/users.jsonl` 是 filter 产物、只有 ≥min_positive 条正面的账号，
  只在没有 comments.jsonl 时兜底。跨段合并键是 `(username, level)`，别只按昵称。
- 素材盘路径会变：`summary.json` 里的绝对视频路径失效时用 `match --video-map 旧前缀=新前缀`。
- 同一批视频的取帧口径由 `summary.json` 的 `sample_mode` 决定；`adaptive` 必须顺序解码（bug-264）。
  补图复用 `export_user_images`，不要另写取帧。
- 自检是零第三方依赖的纯函数测试；涉及文件系统的用 `tempfile.TemporaryDirectory()`。
- 跑真实补图很慢（本批单段 18~67s，整批 426s）；只是核对表格时先 `--no-images`。
- 同一个人的昵称会在**不同段**里读成不同样子（`+1八重樱` / `八重樱`）：解析层的别名归一
  只在段内取证，跨段必须在 `qualify` 合计前再归一（`tools/merge_segments/align.py`）。
  相似度 ≥0.7 只是**入围**，复核分前缀形状：带数字药丸（`+1`/`★1`/`￥1`）直接认；纯数字
  （`7用户…`）要共用正文或等级标；**无数字标点（`-`/`~`/`？`）不算药丸**（快手药丸是行内
  的，`-风-` 这类是真实昵称），须叠加「只差一个字符 + 共用正文≥2」。
- 同一平台**不同分辨率**不能照抄档案数字：视频号 3x 录屏（1206×2622）行距 76.7、
  x_text 72，正好是 720×1600 那套（50.6 / 30）的 ~1.5 倍。换 rect 会让 x_text 失效，
  必须按素材重测（2026-11-07 风云A9L 渠道批）。
- 续行间距**必须实测再定 `wrap_gap_ratio`**：本批抖音 0.76、视频号 0.78，默认 0.73 会把
  折行全挡在门外（残句散成匿名行）。0.85 夹在续行（0.76~0.78）与独立行（0.92~1.09）之间。
- 视频号 1080×2400（安卓）评论列表顶部有 ~70px **渐隐带**：只渲染半截的行 OCR 会读成
  `天江丁工描`/`贝旦亩` 之类碎片并变成匿名评论。面板 rect 的 y1 要抬到渐隐带之下
  （2026-11-07 猎鹰智驾：分界 1178 → y1 1250），完整行往下滚时会被拍到。
- 各家 App 的评论输入框被主播打开时会把「闪光语录/表情面板」盖在评论区上（抖音实测
  seg3 t≈1030s）；这是无冒号文字块，配置里按素材短语写进 overlay_cards，别指望自标定。
- **认人口径要看昵称是否打码**（2026-11-08 用户定）：一场直播里匿名（`爱**`）和非匿名
  （`微风许甜`）会混着出现。打码昵称必须按 **(昵称, 等级标)** 认、等级标一致才算同一个人；
  不打码昵称只看昵称（OCR 等级读错/漏读不能拆账号）。平台档案写
  `account_key="nickname_level_if_masked"`，别再用一刀切的 username / nickname_level。
  整场都打码（抖音 App，实测 99% 行）就直接 `nickname_level`。
- **打码名的「名字一样」= 可见部分逐字 100% 相同 + 等级标一致**（2026-11-08 用户逐字纠正
  过两次：先说「第一个字」，后改为「可见部分」）。`visible_name()` = 星号之前那一截
  （`小***`→`小`，`10双***`→`10双`）：`小***`/`健***` 是两个人；`小***`/`小**` 只是星号
  个数被 OCR 读错，名字相同。名字对上后**两边等级标都要读到且相同**才并。打码名底下是
  几十个真人，模板化直播任意两号共用文案是常态 ⇒ **形近(≥0.7)/大小写/共用正文一律不算
  证据**（段内 `normalize_username_alias` 与跨段 `consolidate_users` 同一口径）。
  例外：数字药丸前缀 `15木***` → `木***`，剥掉后名字逐字相同、`15` 就是这行的等级
  （`promote_prefix_level`，只在按等级认人时开）。
- **按等级标认人的配置必须开 `parse.badge_reread`**（2026-11-08 实测）：药丸在屏幕上清晰
  可见、整屏 det+rec 仍会漏读（本批三段唯一评论漏读率 12~15%），漏一条就多一个
  `(昵称, "")` 假账号（`咕___-7` vs `咕___◆4-44`）。二次读数按正文框裁药丸带、只跑识别、
  跨帧投票，只补不改；从 rows.jsonl 复算即可，不必重跑 OCR 抽行。剩余无等级目录要先看
  导出图：真的没有药丸（非粉丝团用户）才是 `(昵称, "")` 的正确形态。
- **`parse.badge_reread` 不再手动开**（2026-11-08 用户要求）：默认 `null`，与 `account_key`
  绑定 —— 该段任一面板 `account_key ∈ {nickname_level, nickname_level_if_masked}` 就开，
  `username` 就关（`config/panels.py:level_identity_declared`，逐段判）。新人接手别又在
  配置里写死 `true`：那会在 `username` 配置上白跑几十秒/段回原帧读药丸；`false` 只留给
  「确实不需要补读」的例外。任何读 `cfg["parse"]["badge_reread"]` 的新代码都必须处理
  `None`，不能 `if value:` 了事（remedy_badges 就踩过）。
- **录屏可能是「侧躺」的**（2026-11-09 快手晚场实测）：mp4 带 `rotation=90` 显示矩阵，
  OpenCV `VideoCapture` 默认**会应用**它（拿到 3150×1968 的横向画面、文字侧躺，OCR 全废）；
  而且同一条流开头 ~258s 是横握录的、之后才转正 —— 显示矩阵管不了中途转向。
  处理：`ffmpeg -ss <转正时刻> -display_rotation 0 -i 原文件 -c copy 副本`
  （无损、几秒），配置里引用副本。先 `ffprobe -show_entries stream_side_data=rotation`
  看矩阵，再对半分钟一帧 OCR 数「带冒号的行」找转正时刻。
- **一个 config 里有多种分辨率时，`x2_from="window"` 只对全局 `panels.auto.frame_width`
  那一档成立**（`config/panels.py:_window_right` 只读这一个值）：把 720 写进全局，
  1968 宽的大档会被裁在 720。大档改用 `x2_from="content"`（rect x2 作上界）即可。
- **主播打开输入框时，键盘/闪光语录会落进固定 rect**（2026-11-09 快手实测：键盘行
  `ERTYU` / `SD@F#G%H` / `ZXVB` 被当匿名评论）。overlay_cards 里加
  `^[A-Za-z0-9@#%&+=×?·._\-/]{1,16}$` 丢掉纯拉丁/数字无冒号行，再补面板标签短语
  （`页面加载中` / `看播满` / `送票助我上榜` / 闪光语录话术）。真评论都带冒号，不受影响。
- **录屏会在直播结束后继续录**（2026-11-09 视频号末段实测）：文件名写 `18：49-19：00`，
  实际 65.8min，直播在 737s 就结束了，之后全是「直播已结束」推荐页（推荐卡/广告卡
  带冒号或不带冒号，OCR 会读成匿名评论）。先按 `直播已结束` 出现的时间点找直播终点，
  再用 `ffmpeg -i 原文件 -t <秒> -c copy` 只保留直播段；别用 overlay 去追不断变化的推荐卡。
- **同一平台可能一天出现多种分辨率**（480×1068 / 720×1560 / 592×1280 / 1968×3150 都见过）：
  每档都要独立量 `row_pitch / x_text / badge_span / rect`，不能按宽高比缩放套用。
  一个小 diff 的经验：480 档抖音行距 35.6、x_text 66、badge_span 36；
  快手 480 档行距 36.8、x_text 95、badge_span 72、x_ignore_from 350。

## Do-Not-Repeat（别再犯）

- 面板覆盖里 `y_phase / x_text / x_ignore_from / badge_span` 的 `int(round(float(...)))`
  必须先判 `None` —— CONFIG.md 明确允许 `x_ignore_from: null`（= 关闭浮层闸），
  `float(None)` 会让整个 parse 崩掉（2026-11-09 快手大档踩过）。

- 别让「短名被长名包含」无条件得 1.0：账号基数上千后 2 字名会乱撞。
  前后缀多余那段是汉字 → 只按整体 ratio；中间片段只对 ≥3 字短名做窗口比。
- 改 `score_norm` / `_partial_norm` 这类核心相似度时，**顺手删掉 return 之后的死代码**——
  自检不会报不可达块，它会一直误导后来的人。
- 不要手工改生成的 CSV/xlsx；要改就改代码重跑。
- 重跑撞库只覆盖同名文件，旧名单名留下的 `标记图/` 子目录不会自动删 —— 需要干净结果就换 `--out`。
- 补图/复制这类「会多段写同一目录」的逻辑，判断能不能直接写**必须靠本轮状态**（如 `owners` 集合），
  不能用「目标文件是否已存在」——重跑时旧文件还在，会判成「不是第一次」而加段名前缀，
  结果同一张图存两遍（赵丽丽 2→4 张）。重跑幂等要显式测：跑两遍看计数不变。
